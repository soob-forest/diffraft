# 선택 수정·초안 복구 보완

2026-11-02 · 상태: 세 결함 보완·관련 자동 회귀 완료, 일반 native 빌드 복원

이 문서는 첫 보완 단계의 체크포인트다. 아래 수치와 설치 미수행 표시는 당시 기준이며 최신 동작·검증·설치본은 [UX 개선 현재 상태](ux-status.md)를 따른다.

## Problem 1-Pager

- 배경: 선택 수정은 대상별 초안을 보존하며 최신 확정본·제안 revision을 검증한다.
- 문제: 다른 그룹 승인 후 재선택해도 이전 head를 재사용한다. 실패 요청의 초안 열기가 현재 활성 초안을 연다. 큰 JSON 초안 하나가 전역 저장·이동·종료를 막는다.
- 목표: 명시적 재선택으로 최신 대상을 복구하고, 실패 요청의 정확한 초안을 열며, 크기 초과를 사전 안내하고 해당 초안만 복구한다.
- 비목표: 버전 검증 완화, 요청 자동 실행, 이전 지시의 다른 대상 이식, 저장 실패 무시, 사용자 초안 자동 삭제.
- 제약: 기존 SQLite 키·스키마와 저장 순번을 유지한다. 새 입력을 늦은 복구로 덮지 않는다. 제품 설치·사용자 DB·실제 AI 계정을 변경하지 않는다.

가정: 후보의 같은 revision·선택에 대한 명시적 재선택은 기존 지시·직접 수정 내용을 유지하려는 행동이다. 실패 요청 복구에서 대상이 없거나 모호하면 현재 초안 대신 재선택 안내를 표시한다.

## 대안과 결정

| 문제 | 대안 A: 장점 / 단점·위험 | 대안 B: 장점 / 단점·위험 | 결정 |
| --- | --- | --- | --- |
| head 변경 후 재선택 | 키에 head 추가: 완전 분리 / 기존 지시가 별도 초안으로 남아 재입력 필요 | 명시적 재선택 때 대상 갱신: 지시 보존 / 준비 문맥 무효화 필수 | B. 기존 키 유지, 최신 대상 갱신과 확인 정보 해제 |
| 실패 요청 초안 | 화면 전환 값에 전체 요청 전달: 경로 명시 / 여러 패널 타입·상태 확장 | 저장소에서 실패 요청과 정확히 일치하는 대상 조회: 변경 작음 / 부재·중복 처리 필요 | B. 문서·작업·버전·대상·좌표·인용으로 유일한 초안만 활성화 |
| 큰 초안 | 저장 상한 확대: 변경 작음 / 중복 저장·다른 큰 초안의 같은 실패 잔존 | 원문 선택 저장 전 직렬화 크기 검사와 명시적 복구: 상한 유지 / 복구 UI 필요 | B. 저장 실패는 유지하고 크기 초과 초안만 사용자 행동으로 비움 |

영향: 선택 작성의 대상 채택과 실패 복구 진입만 바꾸며, 서버의 head/revision 검증은 유지한다. 초안 저장소에는 조건부 비우기를 추가하고 일반 I/O 실패는 기존 재시도 정책을 유지한다. 본문·인용·지시는 로그에 기록하지 않는다.

## 작업과 검증

- [x] 회귀: 같은 revision에서 head 변경 후 재선택, 지시·직접 수정 보존, 이전 확인 무효화.
- [x] 회귀: A 실패 → B 초안 → A 열기, 대상 부재·모호함·다른 문서/작업 차단, B 내용 보존.
- [x] 회귀: JSON 이스케이프 후 크기 초과 사전 차단, 해당 초안만 비우기, 늦은 복구의 새 입력 덮어쓰기 차단, 다른 초안 저장 재개.
- [x] 프런트 단위·타입·린트·빌드와 관련 native 성공/실패 흐름.
- [x] 변경 리뷰·실행 결과 기록과 일반 native 빌드 복원.

실제 IME·VoiceOver·작성자 사용성 평가는 기존 SPEC의 별도 미완료 항목으로 유지한다.

## 구현과 검증 기록

- `useSelectedRequest`는 동일 키의 이전 head를 명시적 재선택 때만 갱신한다. 서버의 stale 검사를 완화하지 않는다.
- 실패 복구는 `failed-selection-draft`에서 대상의 소유·head·종류·제안/revision·좌표·인용을 비교한다. 확정 문맥은 요청에 원래 표시 묶음이 없으므로 유일한 일치만 허용한다. 복수 일치나 부재에서는 현재 초안을 열지 않고 재선택을 안내한다.
- `serialization`은 Rust와 같은 3 MiB의 직렬화 UTF-8 상한을 사용한다. 원문 범위 고정은 기존 초안을 바꾸기 전에 검사한다. 일반 입력의 크기 초과는 저장 실패로 보존하며 자동 삭제하지 않는다.
- 복구 버튼은 실패 당시 객체와 현재 값을 비교한 뒤 해당 키만 비운다. 다른 문서/작업의 초안과 더 새로운 입력을 덮지 않는다. 일반 I/O 실패에는 비우기를 제시하지 않는다.
- 5개 실패하는 회귀 검사를 먼저 확인했다. 확정 문맥·재작성 대상, 부재·모호함·다른 문서/작업, 다른 종류 초안, UTF-8/JSON 크기 경계와 일반 요청 편집 검사를 더해 새 단위 회귀 10개가 통과했다. 전체 TypeScript 122개·종료 검사 4개와 타입 검사·린트가 통과했다.
- native E2E에 `ux-recovery`를 추가했다. A 실패 → 다른 선택 B 초안 → A 복구, 다른 그룹 승인 → A 재선택 → 새 미승인 revision, 크기 초과 → 이동 차단 → 해당 초안 비우기 → 다른 초안 보존·이동 성공을 검사한다. 원문 범위 고정의 크기 차단은 훅 회귀 검사로 검증한다.
- 초기 E2E는 새 대상 선택의 React 반영 전에 기존 입력란을 사용했다. 대기를 임의로 늘리지 않고 대상 ID·선택 좌표·인용이 실제로 바뀐 뒤 입력하게 수정했다. 별도 제안 이동은 단위 회귀, native는 같은 후보 안 서로 다른 좌표로 초안 격리를 검증한다.
- 실제 캡처에서 긴 복구 안내가 고정 32px footer 아래로 잘리는 것을 확인했다. 크기 초과 오류 상태만 footer 높이를 내용에 맞추고 스크롤·줄바꿈을 제공한다. 복구 버튼에 어떤 종류의 초안을 비우는지 표시한다.
- 복구 오류 상태에서 1440×900·1280×800·800×600 × 100/150/200%의 9개 조합을 통과했다. 가로 넘침 없음, 복구 버튼의 화면 내 위치와 실제 클릭 hit를 확인했다. `.artifacts/ux-followup/recovery-layout.json`과 9개 PNG에 관측값을 남긴다. WDIO 스크롤의 Web API 대체 경고 1회가 있었으며, 대체 후에도 실제 버튼 hit·위치 검사를 통과했다.
- 큰 입력을 유지한 9개 확대·캡처의 실측 시간이 30초를 초과해 `ux-recovery`의 WDIO 실행 제한만 75초로 정했다. 임의 지연을 추가하거나 검증 조건을 완화하지 않았으며 최종 시나리오 3개는 54.7초에 통과했다.
- 최종 관련 native 검증은 8단계·31항목이다. 최신 기능 빌드에서 기존 UX 4단계·14개, 제한 조정 후 복구 1단계·3개, 기존 사용성 1단계·10개, 정상 종료/재시작 2단계·4개가 각각 통과했다. 이전 전체 120개를 이번에 모두 재실행했다는 의미는 아니다. 기존 사용성 검사에서도 WDIO의 스크롤 대체 경고가 있었고 실제 화면·상태 검사는 통과했다.
- `npm run native:build`와 그 안의 TypeScript·프런트 production 빌드가 통과했다. E2E 기능 없는 일반 debug 바이너리로 복원했다. Rust·생성 계약·DB 스키마는 이번 보완에서 변경하지 않아 Rust 329개와 전체 native 120개를 새로 집계하지 않는다.
- 제품 변경 파일은 300줄 이내, 함수 본문은 50줄 이내다. 지연된 준비 결과의 조건부 쓰기, 복구 객체/현재 값 비교와 기존 저장 순번을 리뷰했다. PR·커밋·설치·사용자 DB 변경·실계정 호출은 하지 않았다.

실행 로그는 `/tmp/diffraft-ux-followup-{build,ux-final,recovery-final,usability,shutdown,normal-build}.log`에 있다. `ux-final`의 복구 항목은 30초 제한으로 실패했으며, 최종 통과 근거는 제한 조정 후의 `recovery-final`이다.
