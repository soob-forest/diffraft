## ADR-CODEX-007: 세션 유실 분류와 복구

| 대안 | 장점 | 단점·위험 | 결정 |
| --- | --- | --- | --- |
| 모든 resume 실패를 세션 유실로 처리 | 구현이 작다 | 인증·정책·네트워크 실패에도 정상 연결을 버린다 | 제외 |
| 확인된 유실 오류만 분류하고 실패 작업의 연결을 비활성화 | 기존 연결과 실패 원인을 보존한다 | 설치 버전의 오류 계약·경계 테스트가 필요하다 | 채택 |

공식 문서는 저장된 thread ID로 재개하는 계약을 설명하지만 유실 오류의 구체적 메시지까지 보장하지 않는다. 설치된 Codex 0.165.0에서 합성·미존재 ID의 응답을 확인하고, 검증한 코드·메시지 형태만 분류한다. 원문은 디코딩 경계에서 버리고 고정 오류 코드/메시지만 전달한다. 알 수 없는 오류는 연결을 변경하지 않는다.

실패 작업의 task·account_scope·requested_session_id에 일치하는 ACTIVE 행만 MISSING으로 변경한다. 작업 실패와 상태 변경은 한 트랜잭션으로 처리한다. 완료된 작업의 늦은 실패·중복 통지로 새 연결을 바꾸지 않는다. 자동 thread 시작이나 turn 호출 없이 실패를 보고하고, 다음 명시적 요청에서 로컬 맥락으로 새 thread를 시작한다.

영향도: Codex RPC 오류 디코딩·재개 경계와 공통 실패 저장 경계에 한정한다. 기존 Claude 연결은 공급자별 실행 기록으로 구분하고, 대화·문서 승인·저장은 변경하지 않는다.

## ADR-CODEX-008: 모델 목록과 선택 검증 분리

| 대안 | 장점 | 단점·위험 | 결정 |
| --- | --- | --- | --- |
| 사용할 수 없는 저장 모델을 기본값으로 교체 | 곧바로 요청 가능 | 사용자가 선택한 모델과 재시도 의미를 바꾼다 | 제외 |
| 조회는 현재 목록을 반환하고 실제 호출 전에 선택을 검증 | 저장 선택을 유지하면서 대체 모델을 고를 수 있다 | 호출 실패 시 구체적인 변경 안내가 필요하다 | 채택 |

목록 조회는 저장 모델·reasoning이 제거되어도 성공해야 한다. 연결 테스트와 실제 요청은 선택 검증에 실패하면 호출 전에 중단하고 모델 목록에서 새 선택을 저장하도록 안내한다. 모델·reasoning·공급자를 자동으로 바꾸지 않는다. 기존 설정 변경 감지와 늦은 성공 차단을 유지한다.

영향도: Codex 진단·모델 선택 검증과 관련 fixture/테스트에 한정한다. IPC 타입·기존 UI 구성은 유지한다.

## 작업과 검증

- [x] R1: 확인된 유실 응답을 비밀값 없이 분류하고, 다른 오류·다른 RPC의 오분류를 막는다.
- [x] R2: task·account·thread 범위의 상태 변경, 재시작·명시적 재시도·로컬 맥락 보존·늦은 실패를 회귀 검증한다.
- [x] R3: 제거된 저장 모델/effort에서도 목록 조회와 대체 선택을 허용하고 실제 호출은 차단한다.
- [x] R4: 변경 전 실패→수정 후 통과, 기존 Claude 회귀·정적 검사·관련 네이티브 E2E·일반 앱 빌드를 기록한다.

가정: 모델 목록 및 세션 경계 검증에는 가짜 App Server와 별도 DB를 사용한다. 설치 버전의 유실 오류 진단은 생성 턴 없이 수행한다. 사용자 문서·인증 파일·기존 thread는 변경하지 않는다.

근거: [OpenAI 공식 App Server 문서](https://learn.chatgpt.com/docs/app-server), [이전 구현 기록](codex-integration.md).

## 실행 기록

변경 전 Rust 회귀는 Codex 연결의 ACTIVE 잔존·재시작 후 복구 실패와 잘못된 RPC 오류 분류를 재현했다. 추가 모델 검사도 OutputInvalid를 반환해 실패했다. 네이티브 E2E 3개는 모델/effort 목록 차단 2건과 세션 유실 오분류 1건으로 모두 실패했다. 로그: `/tmp/diffraft-recovery-{session,rpc,model}-red.log`, `/tmp/diffraft-recovery-e2e-red.log`.

설치된 0.165.0의 빈 임시 홈에서 미존재 thread를 재개하면 JSON-RPC `-32600`, `no rollout found for thread id `와 합성 thread ID를 결합한 메시지, 구조화 오류 데이터 없음이 관측됐다. 해당 코드·접두사·전체 식별자 형식만 디코딩하고, 응답 ID가 일치하는 `thread/resume`에서만 SessionMissing으로 바꾼다. 원문 메시지는 Message에 남기지 않는다. `codex_missing_native`로 같은 계약을 명시적으로 통과했다. 인증·생성 턴은 사용하지 않았다.

실패 저장의 두 UPDATE는 작업 실패와 같은 트랜잭션을 사용한다. Codex 기록이 있는 작업은 Claude 연결을 바꾸지 않으며, 늦은 실패의 UPDATE 결과가 0이면 연결도 바꾸지 않는다. 주입한 DB 실패에서 작업 RUNNING과 기존 연결이 함께 보존되는 것을 확인했다. 재시작·명시적 재시도 fixture는 thread/start와 기존 USER/ASSISTANT 맥락 전달을 실제 입력에서 검사한다.

`connection::inspect(false)`는 저장 선택을 검증하지 않고 현재 목록을 반환한다. 테스트/실제 요청의 선택 검증은 공통 함수로 유지하고, 불가능한 선택은 모델 목록에서 새 선택을 저장하도록 안내한다. 목록 조회·실패 호출 이후 저장값이 유지되고 생성 턴이 없음을 앱에서 확인했다.

중간 E2E에서 동명 문서 중 과거 문서를 검사하던 테스트 오류를 발견했다. 새 시나리오는 제목 대신 현재 selectedDocumentId로 원문을 검사하도록 고쳤으며 Codex 전체 12개가 통과했다. 제품 동작 실패와 구분한다. 최종 전체 검사·일반 빌드 결과는 아래에 남긴다.
