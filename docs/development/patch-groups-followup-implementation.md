# PATCH 그룹 보완 구현·검증 기록

2026-11-06 Asia/Seoul · 상태: 보완 구현·자동/네이티브 검증·일반 빌드 복원 완료

기준: [보완 계획과 ADR-003/004](patch-groups-followup-plan.md), [SPEC](../../SPEC.md), [PG-21~28](../../TODO.md#5-후속-검토-보완-pg-2128).

## 변경과 영향

- `document/patch_moves.rs`: 파서가 식별한 완전한 최상위 일반 문단을 기준으로 출발·도착의 고유성을 확인한다. 변경 연산이 해당 문단 본문 전체를 소유할 때만 이동으로 연결한다. 내부 단어·접사·문장부호가 같다는 이유로 결합하지 않는다. 기존 연산과 본문 바이트를 수정하지 않는다.
- `document/patch_fences.rs`: 전체 원문의 파서 범위에서 fence와 본문 끝을 구분한다. 파서가 본문 밖에서 소비한 실제 닫는 구분자가 있어야 닫힘으로 본다. 인용·목록 접두사를 일괄 제거하거나 잘라낸 원문을 독립 문서로 다시 파싱하지 않는다.
- 구조의 빠른 비교보다 먼저 새 미완성 fence를 검사한다. 기존 미완성 블록의 여는 경계가 변경 후에도 보존되는 경우는 일반 문구 교정을 허용한다. 원문 오프셋은 연산의 길이 변화·변경되지 않은 앞뒤 문맥으로 대응한다.
- `patch_structure.rs`: 닫힘 상태를 구조 비교에 반영하고 구조 종료 이벤트도 비교해 중첩 관계를 보존한다. 기존 참조·그룹 전체 결정·저널 계약을 유지한다.
- 정책은 v2다. `patch_review_prepare.rs`에서 정책 정보 없음/v1인 전부 미처리·유효한 현재 활성 PATCH만 전환한다. 기존 그룹 revision을 증가시키며 동일 구성의 ID·proposal revision·코멘트를 유지한다. 미래 정책을 자동으로 낮추지 않는다.
- 전환 이벤트에 전후 정책·그룹 revision과 그룹 식별자를 기록한다. 문서 락과 트랜잭션으로 그룹·정책·이벤트를 함께 저장한다. 본문·응답·인증값은 기록하지 않는다.
- E2E는 소유한 합성 DB에서 v1 결합을 재현해 2그룹 전환·부분 결정·재시작을 검사한다. 인용문 정상 짝과 잘못된 후보 저장 실패·작은 확대 화면 오류·원문/요청 복귀를 실제 UI로 확인한다.

## 실패를 먼저 확인한 증거

| 재현 | 수정 전 결과 | 근거 |
| --- | --- | --- |
| 독립 단어 교정 2개 | 기대 2그룹, 실제 1그룹 | `patch-v2-before.log` |
| 닫는 구분자 단독 훼손 | 기대 오류, 실제 허용 | 같은 로그 |
| 인용문의 정상 fence 짝 변경 | 기대 성공, 실제 구조 오류 | 같은 로그 |
| v1 준비 전환 | 기대 정책 2/회차 8, 실제 정책 1/회차 7 | `patch-v2-prepare-before.log` |
| 파일 끝의 빈 컨테이너 접두사 | 기대 미완성 오류, 실제 허용 | `patch-v2-empty-before.log` |

네 재현과 정상 대조군을 임시 검사에서 정식 `patch_group_followup` 테스트로 옮겨 실행했다. 파일 끝 컨테이너 사례는 파서의 본문 끝 이후 남은 바이트가 실제 닫힘인지 추가 확인해 보완했다. `>`·공백만 남으면 닫힘이 아니다. 이는 ADR-003의 파서 문맥과 원문 좌표 보존 결정을 구체화한다.

초기 구현 검사에서 Rust 범위 값 이동 후 재사용 오류를 수정했다. 정적 검사에서는 저장 테스트 한 함수가 51줄이라 실패했고, import를 모듈 수준으로 옮겨 제한을 지켰다. 검사 실패를 통과 기록으로 계산하지 않는다.

## 적용 범위

일부 처리된 구형 묶음·기존 확정본·과거 기록은 자동 교정하지 않는다. 무관한 기존 미완성 Markdown을 전역 문법 오류로 처리하지 않는다. 새 스키마·새 IPC·추가 AI 호출은 도입하지 않았다. 설치된 사용자 앱·사용자 DB는 이 검증에서 변경하지 않는다.

실제 계정 응답 품질·한글 IME·VoiceOver의 기존 수동 미확인 항목은 자동 테스트나 캡처로 대체하지 않는다. 빌드 ID·소스/바이너리 해시와 E2E 실행 결과는 최종 검사 뒤 기록한다.

시도한 E2E 빌드는 `92a4bff309e47844-e2e`이며 소스 SHA-256은 `92a4bff309e478442c6dccbf1770398abf18382a736b208187c7bf66abaff31a`, 바이너리는 `436c032023b7cc2ebe9ee801484120e0f5d2f470108d530df2f81bfae4169151`이다. 이 잠금 상태의 시도는 제품 흐름 통과 근거로 계산하지 않는다.

일반 개발 빌드는 2026-11-06T03:01:29.091Z에 `92a4bff309e47844-debug`로 복원했다(exit 0). 소스는 위 E2E 시도와 같고 바이너리 SHA-256은 `46dc619b79e547747f525d9471f2946d76da52086b2e75b59b6b61f10180cce7`다. 이후 잠금 해제 뒤 E2E 빌드·화면 검증·일반 빌드 복원을 순차로 다시 수행했다. 설치 앱·사용자 DB는 변경하지 않았다.

## 잠금 해제 후 최종 검증

사용자의 잠금 해제 안내 후 `screenLocked=false`를 확인하고 다음 검사를 같은 최종 소스로 순서대로 실행했다.

| E2E 흐름 | 통과 |
| --- | --- |
| 검토 6 + PATCH 보완 4 + 별도 재시작 1 | 11개 |
| 재제안과 재시작 | 5개 |
| 부분 선택 전환과 재시작 | 6개 |
| 전체 재작성과 재시작 | 12개 |
| 기록 | 4개 |
| 복구와 재시작 | 2개 |
| 사용성·100그룹·창/확대 조합 | 10개 |

합계 50개 통과다. 800×600/200%의 코드블록 오류 전문과 복귀 버튼은 실제 bounds/hit 검사와 캡처 육안 점검으로 확인했다. 캡처는 `.artifacts/patch-v2-fence-error-800-2.png`다. WebDriver의 DOM 재생성에 따른 stale element 및 스크롤 Web API 재시도 경고는 기록했으며, 이후 실제 hit target·기대 상태 검사를 통과했다. 검사 조건을 완화하거나 실패를 건너뛰지 않았다.

검증 E2E 빌드는 `92a4bff309e47844-e2e` (2026-11-06T05:57:52.399Z), 바이너리 SHA-256은 `49bdbaf9a71c187d3d66dac309c7410f61007db6c76d98711cd1fcc395fb5fc7`다. 일반 개발 빌드는 마지막에 `92a4bff309e47844-debug` (2026-11-06T06:02:44.503Z)로 복원했으며 바이너리는 `8878c63e40e606dd92ea570178a6fd9c51b5fdbbd9b7519ebae498d43bc92612`다. 두 빌드의 소스 SHA-256은 `92a4bff309e478442c6dccbf1770398abf18382a736b208187c7bf66abaff31a`로 동일하다.

로그는 `.artifacts/patch-v2-unlocked-*.log`, 흐름별 exit code·실행 시각·개수는 `patch-v2-unlocked-status.json`, 빌드 출처는 `build-e2e.json / build-debug.json`에 남겼다. FA01~FA08의 순수·저장·UI 근거와 관련 기존 회귀를 확인하고 PG-21~28을 완료했다. 이번 실행에 설치 앱 교체·사용자 DB 전환·실계정 AI 호출은 포함하지 않았다.
