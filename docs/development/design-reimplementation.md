## ADR-REIMPL-001 · 표시 영역과 소유권

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 전체 상태를 App으로 올림 | 모든 DOM 영역에서 접근 가능 | 편집·검토 수명과 저장 경계를 광범위하게 변경 |
| 기존 소유자를 유지하고 React portal로 표시 영역만 이동 | 단일 모델과 조건 flush 유지, 변화가 작음 | DOM 순서·숨김·포커스·포털 대상 수명 검증 필요 |

두 번째를 선택한다. ReviewPanel은 중앙/오른쪽 상세/왼쪽 변경 목록을 소유하는 공통 React 경계다.
`useReviewPanel`을 중복 호출하지 않고 같은 panel 객체를 세 뷰에 전달한다.
작업 선택과 목차도 기존 소유자의 이벤트를 왼쪽 탐색 슬롯에 표시한다.
가정: 포털 대상은 App/DocumentWorkspace의 안정적인 DOM이며 문서 교체 시 함께 정리된다.

영향: App→Workspace→ReviewPanel/TaskPanel/EditingArea의 표시 위치와 포커스만 이동한다.
사전 조건은 유효한 문서/작업·flush 경계, 사후 조건은 같은 초안·선택·승인 대상이다.
조건 편집 DOM을 숨길 때 언마운트하지 않아 미저장 입력과 flush 등록을 유지한다.

## ADR-REIMPL-002 · 복원·출력 작업 영역

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 별도 화면 라우팅 | 시안의 전체 작업 영역과 직접 대응 | 기존 모달의 취소·포커스·확인 무효화 경계 재작성 |
| 넓은 모달 안에 버전 목록/비교 또는 미리보기/출력 패널 | 시안의 읽기 구조와 기존 보호 동작 유지 | 앱 배경이 보이는 표현 차이 |

후자를 선택했다. S07은 왼쪽 버전 탐색/오른쪽 비교, S10은 왼쪽 확정본 미리보기/오른쪽 저장·복사다. 중립 배경과 넓은 작업 영역을 사용하며 좁은 창에는 세로 흐름으로 전환한다. 모달 자체를 없애는 것이 사용자의 요구라는 근거는 없다. 원본의 본문 구조를 좁은 확인창으로 대체하지 않는다.

## ADR-REIMPL-003 · 검토 수명·포커스·확대

- 모드 전환 시 언마운트하면 단순하지만 선택/보기/스크롤이 초기화된다. 마운트를 유지하고 hidden으로 전환하는 안을 선택했다. 포털 탐색은 활성 모드에만 표시한다. 형제 ReviewResume/ReviewPanel은 `resume:`/`review:` 키를 분리한다. 중복 키 때문에 재개 배너가 남은 중간 캡처는 최종 증거에서 교체한다.
- 임의 지연 focus와 실제 패널 가시성 의존 focus를 비교했다. 후자를 선택해 재작성 요청 번호·상세 탭 표시·잠금 해제 후 입력에 포커스한다. 기존 작은 창 실패를 재현한 뒤 사용성 10개에서 통과했다.
- 확대에서 고정 본문 높이를 유지하면 도구가 비교를 가린다. 글꼴 축소 대신 폭950px 이하/높이600px 이하에 자연 높이와 320px diff를 두고 바깥 스크롤로 접근한다. 400px뿐 아니라640/720px 확대 구간도 포함한다. 버튼뿐 아니라 실제 diff 중앙 hit target을 검사한다.
- 본문 그룹 제목은 읽기 전용 표시 장식이다. 원문 텍스트나 byte/UTF-16 좌표를 바꾸지 않는다. 같은 높이를 행 번호에 적용하고 좌우 정렬·선택·스크롤 회귀로 확인한다.

## ADR-REIMPL-004 · 연속 요청 중단

이전 500ms 폴링 화면의 실행 ID로 중단하는 안은 단순하지만 빠른 후속 요청 때 오래된 ID를 참조할 수 있다. 클릭 시 현재 실행 상태를 읽고 해당 실행 ID로 중단하는 안을 선택했다. 기존 Rust의 단일 실행·종료 확인·늦은 결과 거부 규칙은 유지한다. `rewrite-cancel`의 전체 실행 실패와 단독 재현 통과를 구분하며 최종 회귀에서 다시 확인한다. 새 자동 재시도는 없다.

## ADR-REIMPL-005 · 본문 그룹 클릭과 행 번호

본문 클릭은 텍스트 선택 이벤트만 기다리는 안과 변경 행의 그룹 ID를 별도로 선택하는 안을 비교했다. 전자는 읽기 전용 WebView의 단순 클릭에서 선택 이벤트가 없으면 동작하지 않는다. 후자를 선택하여 유효한 그룹 ID만 반영하고 인용 선택·문자 좌표·승인 동작은 변경하지 않는다. `design`의 본문 클릭 검사가 먼저 실패한 뒤 수정했다. 그룹 제목의 38px 높이는 border-box로 명시해 행 번호 패딩과 맞춘다. 영향 경로는 DiffPane→DiffViewer→ReviewPanel→useNavigation이며, 사후 조건은 클릭한 그룹의 상세 표시와 원문/드래그 인용 불변이다.

## 시각 자료와 검증 경계

마감 판단: 좁은 창에 승인 도구를 고정하면 최소 비교 높이를 다시 침범하므로 자연 높이/스크롤을 유지한다. 실제 반복 검토 비용은 사용자 평가에 남긴다. 색은 새 팔레트 대신 기존 `#46566b`를 탐색/하단 보조 글자에 적용했다. 기존 `#607083`의 실측 대비 4.49:1(탐색)/4.30:1(하단)을 개선하며 흰 바탕의 보조 글자는 유지한다. 완료 안내는 이동한 오른쪽 처리 기록을 가리키고 F7 안내는 이전/다음 버튼 툴팁으로 제공한다. 이 변경은 승인 대상이나 키보드 동작을 바꾸지 않는다.

- [3종 비교](../design/design-reimplementation.html): 원본 S00~S10 / 변경 전 보존 / 재구현 캡처. 서로 다른 분기·버전·배율은 화면별 설명에 표시한다.
- [19개 상태 목표](../design/reimplementation-states.html): U01~U06의 조건·실패·승인·코멘트·연결·작은 창 변형. 실제 앱이 아닌 정적 설계다. 착수 이후 보완했으므로 R0의 ‘코딩 전 확보’를 사후 완료로 소급하지 않는다.
- 기준 캡처는 48개 파일을 별도 보존했다. 개별 촬영 시각이 없는 기존 파일은 복사 시각/역사적 캡처라고 명시한다. 새 파일의 촬영 시각·SHA-256은 캡처 manifest에 기록한다.
- 비교 자료 정적 검사 8개 통과. Chrome headless에서 11개 선택, 단독 보기, 확대/Esc/포커스 복귀, 680px 가로 넘침 없음, 19개 목표 상태 렌더를 확인했다. CUA 앱/브라우저 목록은 비어 있어 독립 Chrome 임시 프로필을 사용했고 종료·삭제했다.
- 네이티브 창 visible 선행 조건을 유지한다. 화면 잠금으로 중단된 실행은 기능 실패/통과 수에 합치지 않는다. VoiceOver 제외. 아래 2026-10-29 추가 검증 전에는 IME·OS 대화창·5명 평가를 미검증으로 유지했다.

## ADR-REIMPL-008 · 긴 작업명과 WKWebView 내부 넘침

## ADR-REIMPL-009 · 접힌 문맥의 변경 위치 이동

Problem 1-Pager: 사용자가 준비한 미처리 제안으로 일반 설치본을 검사했다. 긴 표의 중간에 행을 추가한 제안에서 F7이 전체 문맥에서는 이동하지만 기본 접힘에서는 이동하지 않았다. 목표는 F7/Shift+F7 및 선택 위치 이동이 실제 변경 행을 가리키는 것이다. 비목표는 자동 문맥 펼침, 승인·거절, 사용자 원문 변경, AI 재요청이다. 기존 단일 선택 상태와 코멘트 초안 보호를 유지한다.

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 이동할 때 제안 전체 범위를 펼침 | 기존 전체 범위 선택 유지 | 긴 표·문맥을 강제로 펼쳐 보기 상태와 읽기 위치 변경 |
| 선택 그룹의 첫 실제 변경 행으로 이동 | 접힘 유지, 추가만 있는 제안도 이동 가능 | 변경 전/후 중 실제 행이 있는 쪽을 선택해야 함 |

두 번째를 선택한다. 가정은 ‘변경 위치로 이동’의 대상이 제안 블록 전체가 아니라 실제 추가/삭제 행이라는 것이다. `useReviewPanel.choose → groupJumpSelection → DiffPane` 경로에 적용한다. 기존 `beforeRanges[0]` 전체 범위는 접힌 시작점을 포함해 `displaySelection`이 null이 된다. 기존 행/그룹 매핑을 재사용하고 실제 행의 시작점만 선택해 코멘트 인용의 기본 전체 범위는 유지한다. 연속 이동 serial은 시각 대신 증가값으로 구별해 같은 밀리초의 이동도 누락하지 않는다. 새 I/O·락·재시도는 없다. 사후 조건은 접힘 유지·변경 행 이동·승인 상태/원문 불변이다.
