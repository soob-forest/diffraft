# 선택 팝오버 시안 대조와 구현 결정

2026-11-02 · T17 기준과 구현 대조 완료 · 실제 입력 수동 인수 별도

Problem 1-Pager와 대안은 [작업 계획](selection-popover-plan.md)을 따른다. 목표는 선택 위치의 행동 → 고정 인용/지시 → 확인 → 새 미승인 후보이며, 원문/후보의 승인 계약을 유지한다.

## 대조표

| 시안 | 확인한 차이 | 구현 기준/작업 |
| --- | --- | --- |
| 1 선택 요청 | 수정·코멘트 대신 범위 확장 세 버튼, 상단 중복 | 수정 강조·코멘트 보조, 확장은 더보기로 이동, 상단 중복 제거(T18) |
| 2 확인 | 수정/문맥 구분이 긴 설명·접힌 전문에 섞임 | 수정 인용·허용 범위·문맥 요약·저장 코멘트·모델·영향을 순서대로 표시(T22) |
| 3 새 후보 | 일반 상세로 복귀하고 완료 행동의 위계가 약함 | 새 미승인 후보·기존 제안/원문 보존·이전 후보 비교·다시 다듬기·별도 승인 표시(T22) |
| 4 잘못된 선택 | 범위 확장과 수정 버튼이 실패 안내와 섞임 | 유효하지 않은 수정은 차단, 원인/재선택 안내, 코멘트 인용과 구분(T18) |
| 5 원문 선택 | 고정 버튼→일반 생성이라 기존 제안 보관 가능 | 선택 옆 수정→confirmed 선택 요청, 기존 제안 보존. [신규 화면안](../design/ux-proposal/source-selection-popover.html)(T19~T21) |
| 6 편집 영향 | 실제 문서/작업 영향 수를 사용 | 실제 집계 유지, 후보 수정/검토로 이동. 합성 건수 3개에 고정하지 않음(T22) |
| 7 과거 비교 | 이력 비교는 이미 중앙에 제공 | 읽기 전용·당시 기준·복귀 유지, 문구/위계 대조(T22) |
| 8 완료/대화 | 실제 결정 수·결과 링크는 제공 | 실제 상태·정확한 결과 참조 유지, 완료 행동과 현재 상태를 분리(T22) |
| 9 요청 종류 | 수정 제안/설명만으로 문구 다름 | 부분 수정/설명/전체 재작성, 모델·범위·초안 상태·보관 영향 명시(T22) |

의도적 예외: 드래그는 문장 전체가 아닐 수 있어 ‘선택한 1문장’을 임의 표시하지 않는다. 정확한 인용과 문자 수를 쓴다. 문서 제목·버전·개수·모델은 실제 저장값으로 표시한다. 기본 색·글꼴과 패널 크기는 기존 디자인 계약을 유지한다.

## 대상·초안 결정

| 대안 | 장점 | 단점/위험 |
| --- | --- | --- |
| 기존 confirmed 키를 시작 시 일괄 이전 | 새 키로 통일 | 충돌·저장 중단 시 데이터 손실 및 CAS 경합 위험 |
| 기존 키를 호환 조회하고 신규 대상에만 canonical 키 사용 | 기존 기록을 덮지 않고 작은 변경 가능 | 동일 범위의 과거 초안이 여러 개면 명시적 선택 필요 |

두 번째 안을 택한다. confirmed 식별은 문서·작업·head·범위·정확한 인용이며 묶음은 필수가 아니다. 새 키는 묶음 없는 형식, 기존 7요소 키는 계속 읽는다. 동일 범위의 과거 지시가 여러 개면 선택지를 제공하고 임의 합치기/삭제를 하지 않는다. 후보/rewrite 키는 유지한다.

영향: 대상 타입·키 조회·active 인덱스·decode·실패 복구를 함께 변경한다. 원문 작성은 기존 selected-generation 실행기를 사용하며 일반 생성의 보관 의미로 대체하지 않는다. DB 스키마는 추가하지 않는다.

## 일반 release 검증 경계

| 대안 | 장점 | 단점/위험 |
| --- | --- | --- |
| HOME 환경변수만 바꾸고 일반 앱 실행 | 제품 코드 변경 없음 | macOS 앱 데이터 경로가 바뀐다는 보장이 없어 사용자 DB 접근 위험 |
| 명시적 `--verification-workspace`와 소유 임시 폴더 검사 | 일반 release 자체를 같은 코드로 격리 검증 | 작은 경로 검증 경계와 회귀 테스트 추가 필요 |

두 번째 안을 택한다. 절대 경로·실제 임시 폴더 하위·사용자 소유 0700 폴더·고정 마커·심볼릭 링크 거부를 모두 확인한다. 잘못된 인자는 일반 사용자 DB로 폴백하지 않고 초기화를 중단한다. AI 가짜 공급자나 테스트 IPC를 일반 release에 추가하지 않는다.

빌드 식별자는 제품 소스·설정·잠금 파일의 정렬된 내용 해시로 만들고 빌드 시각·일반/E2E 프로필과 함께 앱 정보에 표시한다. 실행 파일 해시는 빌드 후 별도 manifest에 기록한다. 빌드 시각은 UTC로 저장하고 앱에서는 시간대를 포함해 표시한다.

## 일반 범위 고정 유지

기존 고정 버튼을 없앤 뒤 일반 요청의 범위 종류 변경만 유지하는 안은 원문 인용을 문서 왕복 후 이어 쓰는 동작을 잃는다. 따라서 일반 요청은 기존 ‘범위 확인’이 저장된 원문의 정확한 선택을 고정하도록 연결한다. 새 원문 팝오버는 별도의 confirmed 요청을 계속 사용한다. 범위 확인은 AI를 실행하지 않으며 저장·인용·크기 검증 실패에는 성공 표시하지 않는다.

## 확대 시 본문 가시성

초기 9개 조합 검사는 팝오버의 viewport 경계·버튼 hit target만 확인해, 800×600·200%에서 편집기 높이가 소진된 상태를 놓쳤다. 실제 PNG 대조에서 발견했으며 선택 강조 중앙의 hit target이 편집기에 속하는지 인수 조건에 추가한다.

헤더를 고정하고 편집기를 0까지 줄이는 안은 행동은 눌러도 읽는 대상이 사라진다. 낮은 높이에서 최소 편집 공간을 확보하고 작업 영역을 세로 스크롤하는 안을 선택한다. 팝오버는 아래 공간이 부족하면 선택 행 위로 뒤집어 본문을 덮지 않게 한다. 전체 viewport 안으로만 단순 이동하는 방식과 구분한다.

키보드 포커스가 자동 스크롤을 일으켜 팝오버 닫기와 경합하는 경우를 보완한다. 스크롤 중 팝오버를 계속 유지하는 안은 기준 위치가 낡을 수 있으므로, 이미 측정해 배치한 버튼의 포커스 이동에 `preventScroll`을 적용하고 사용자 스크롤에는 계속 닫는다.

## 완료 화면의 선택 안내 수명

배경/문제: 최종 합성 화면 대조에서 모든 제안을 거절한 뒤에도 이전의 잘못된 선택 안내가 남았다. 목표는 현재 선택·현재 검토에 속한 안내만 표시하는 것이며 승인·초안·이력 저장은 변경하지 않는다. 제약은 실패 지시를 보존하고 현재 작성 중의 구체적 오류를 숨기지 않는 것이다.

상태를 변경하는 모든 호출에서 메시지를 지우는 안은 직접적이지만 새 호출 누락과 경합 위험이 있다. 검토 비교 영역의 선택 안내를 유효한 남은 그룹이 있는 동안만 표시하는 안은 작은 변경으로 완료/과거/기준 변경 화면을 보호한다. 두 번째 안을 채택한다. 작성 폼의 오류·지시는 유지하고 검토 상단의 임시 선택 안내에만 적용한다.

영향: `ReviewComparison.tsx`의 상단 선택 피드백 표시를 제한한다. 완료 상태 E2E에 이전 안내 부재를 먼저 추가해 실패를 확인한 뒤 관련 UX·선택 팝오버 검사를 다시 실행한다.

## 최종 화면 대조

[실제 화면 1~9](../usage/ux/README.md)와 [원문 추가 화면](../design/ux-proposal/source-selection-popover.html)에 각 상태의 합성 PNG를 연결했다. 기본 1440 너비의 과업별 캡처와 별도 9개 창/배율 검사를 사용했다. 실제 PNG 크기는 manifest에 남기며 시안과 픽셀 단위로 동일하다는 판정은 하지 않는다.

| 화면 | 반영 결과 | 의도적 차이·검증 근거 |
| --- | --- | --- |
| 1 | 선택 옆 강조 수정·보조 코멘트, 오른쪽 고정 인용/지시 | 팝오버와 작성은 순차 상태라 별도 캡처. 문장·문단은 더보기. 실제 선택 문자 수를 사용 |
| 2 | 작성 필드를 확인 내용으로 교체, 인용·지시·모델·문맥·영향 표시 | 문맥은 실제 준비 스냅샷. 목표·조건·대화 등이 포함될 수 있어 ‘해당 문단만 전송’으로 단순화하지 않음 |
| 3 | 새 후보 rN·미승인, 이전 후보 비교·재요청·승인 경로 | 승인은 기존 그룹 바 하나를 사용해 중복 위험 행동을 추가하지 않음. 보존 여부는 저장값 검사로 입증 |
| 4 | 유효하지 않은 선택의 원인·재선택, 자동 확대 차단 | 캡처는 변경 전 인용 사례. 혼합 선택은 별도 좌표/계약 검사. 검토 완료 뒤 임시 선택 안내 제거 |
| 5 | 원문 선택 팝오버→confirmed 새 부분 제안, 첫 작업·초안 충돌·겹침 처리 | 최초 일반 생성 시안은 설계 이력으로 보관. 신규 화면이 현재 흐름. 일반 범위 확인은 별도 유지 |
| 6 | 문서 전체 미승인 제안·승인 그룹 영향과 작업/검토 이동 | 실제 집계·버전을 사용. 입력 모달이나 타이핑 차단을 추가하지 않음 |
| 7 | 중앙 읽기 전용·이전 후보 비교·검토 복귀 | 캡처는 revision 비교. 보관된 묶음은 당시 base와 비교하며 이유를 추정하지 않음 |
| 8 | 실제 결정 수·검토 완료·확정본 보기·정확한 대화 결과 연결 | 합성 사례는 승인 0/거절 3. 내보내기는 문서 공통 상단 행동을 재사용 |
| 9 | 부분 수정/설명/전체 재작성·AI·범위·초안 상태·첫 지시 보존 | 모델·문서·버전·건수는 실제 저장값. 일반 생성/재작성의 기존 제안 보관 영향은 확인에 유지 |

원문 800×600·200%의 선택 강조와 팝오버가 함께 보이는 PNG를 직접 확인했다. 일반 release의 합성 작업 공간에서도 원문 선택·Shift+F10→Enter·초안 보존·선택 복귀와 diff 선택의 코멘트 인용을 확인했다. 생성·승인 호출은 하지 않았다.

로컬 HTML을 브라우저에서 여는 요청은 URL 정책에 의해 차단되어 해당 페이지의 직접 렌더링은 검증하지 못했다. 문서에 삽입한 원본 앱 PNG는 별도로 열어 대조했다. 실제 IME·VoiceOver·작성자 평가는 기능 검사·디자인 대조와 별개로 남긴다.
