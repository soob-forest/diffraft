소스 detector 1회 결과는 `apps/desktop/.artifacts/codex/impeccable-source.json`의 빈 배열이다. WKWebView는 CDP를 제공하지 않아 detector의 렌더링 검사는 수행하지 않았다. 실제 화면은 WDIO로 표시·크기·Webview.setZoom을 조작하고 캡처와 DOM 치수를 함께 검토했다. 발견 없음만으로 시각 검증을 대체하지 않았다.

기존 색상의 단색 대비 계산: 본문 15.46:1, 보조 6.24:1, 오류 6.99:1, 성공 6.50:1. 실제 OS select 팝업은 별도 레이어이므로 앱 캡처에 포함되지 않는다. 픽셀 기반 전체 WCAG 적합성이나 VoiceOver 통과를 주장하지 않는다.

`settings-error-<width>-<zoom>.png`, `request-<width>-<zoom>.png`와 성공 연결 캡처를 `.artifacts/codex/`에서 확인했다. 확대 상태에서는 제목·상태·버튼을 내부 스크롤로 이동하며 모델 선택과 확인 버튼에 도달한다. 긴 한국어 안내가 줄바꿈되고 선택값이 잘리지 않는다. 원문·후보는 생성 실패·중단·승인 전에도 유지된다.

검토 중 보완: 빈 상태 문단의 과도한 여백 제거, 기존 모델 select 스타일 공유, 공급자 하위 제목 위계 정리, 고정 모델의 진행 표시, 실패 선택 보존, 늦은 연결 성공 차단. 미수정 제품 결함은 발견되지 않았다. 별도 CGEvent 검사기는 macOS 접근성 권한으로 실행되지 않았다. 이후 승인된 Computer Use 도구로 격리한 테스트 앱을 직접 조작하여 실제 OS 메뉴·Tab/Shift+Tab·방향키·Return·Space·Escape, 저장·재열기·포커스 복귀를 확인했다. 임시 DB의 저장 모델도 대조했고 앱·테스트 데이터를 정리했다. 증거는 `.artifacts/codex/manual-keyboard.json`과 해당 도구의 AX/화면 관측이다. 이 통과를 별도 검사기 자체의 실행 성공으로 바꾸어 기록하지 않는다.
