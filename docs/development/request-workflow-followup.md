## Problem 1-Pager와 영향

배경: 1차 구현과 설치를 마쳤으나 독립 검토에서 진입점별 초안·포커스·확인 수명 결함을 찾았다. 문제: 목적과 입력 위치가 경로에 따라 달라지고 본문 클릭으로 선택 수정을 닫을 수 없다. 목표: 같은 대상·목적의 입력을 보존하고 명시적 실행 전 재확인하며 자연스럽게 선택을 해제한다. 비목표: 저장 스키마·공급자·승인 계약 재설계. 제약: 기존 데이터·초안·실행 중 요청 보존, 실패 선행 회귀, 구조 제한과 네이티브 순차 검사.

영향: `request-targets → RewriteForm/RequestTargets`의 종류별 복원, `WorkspacePanels → RequestForm`의 입력 포커스, `useRegeneration`의 확인 수명, 원문/diff의 선택 UI와 작성기 닫기 경계를 보완한다. 서버 승인·생성 API 계약은 유지한다.

ADR-WF-012~020의 대안 비교와 선택을 따른다. 작은 경계 보완은 기존 실행 계약을 유지하나 경로별 회귀가 필요하다. 작성기 전면 통합은 표현을 줄이나 초안·보관·복귀 회귀가 커서 이번에는 선택하지 않는다. 본문 클릭 취소는 편집기 내부의 완료된 단순 클릭으로 한정한다. 동명 작업의 순번은 현재 목록의 표시용이며 이름·목표·식별자를 변경하지 않는다.
