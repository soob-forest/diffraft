# Codex 연동 구현 기록

작성일: 2026-10-30 · 기준: SPEC 11절, TODO C0~C5 · 상태: R0·C0~C5 구현·검증 완료 (현재 계정/0.165.0 범위)

## 초기 기반 변경의 Problem 1-Pager

- 배경: 현재 앱은 Claude 전용이며 로컬 사용자는 Codex의 ChatGPT 인증을 사용한다.
- 문제: 공급자별 모델·인증·프로토콜과 세션 경계 없이 실행기만 교체하면 기존 요청과 인증 경로가 섞인다.
- 목표: 공급자/모델 타입과 Codex의 계정·모델·JSONL 메시지 검증 경계를 먼저 구현한다.
- 비목표: 이번 기반 변경에서 기존 Claude 저장 데이터 변환이나 생성 경로의 미검증 전환을 하지 않는다.
- 제약: 비밀값·원문 오류를 로그로 내보내지 않는다. 외부 시스템 없는 계약 테스트와 실제 로컬 진단을 구분한다.

## ADR-CODEX-002: 기존 인증과 설정 상속

| 대안 | 장점 | 단점·위험 | 결정 |
| --- | --- | --- | --- |
| 앱 전용 Codex 홈에 인증 파일 복사 | 사용자 설정 격리가 쉬움 | 토큰 복제·갱신 불일치·별도 인증 관리 | 제외 |
| 기존 인증 재사용 + 실행별 제한 + 적용 설정 검증 | 사용자 인증을 Codex가 관리 | 상속된 MCP·훅·엔드포인트를 별도 확인해야 함 | 채택 |

2026-10-30 공식 문서와 설치된 `codex-cli 0.165.0`의 생성 스키마를 대조했다. `initialize`, `account/read`, `config/read`, `model/list`를 실제 표준 입출력 연결로 호출했다. 계정 방식은 `chatgpt`, 모델 목록은 8개·기본값 1개·추가 페이지 없음이었다. 계정 식별자·이메일·설정 원문은 기록하지 않았다. 생성 턴은 실행하지 않았다.

중요한 관측: `-c mcp_servers={}`는 기존 MCP 2개를 제거하지 않는다. 빈 테이블을 제한 성공으로 간주하지 않고, 설정에 존재하는 서버별 `enabled=false`와 적용 결과 검증이 필요하다. 훅·플러그인 feature의 실행별 비활성화는 적용 설정에서 확인했다. 읽기 전용만으로 도구 차단을 주장하지 않는다.

## ADR-CODEX-003: 공급자별 요청 모델

Claude 모델 enum에 GPT 모델 이름을 계속 추가하는 방법은 변경량이 작지만 공급자/모델의 잘못된 조합과 모델 목록 갱신을 처리하기 어렵다. 공급자로 태그된 `ProviderModel`을 추가하여 Claude 별칭과 Codex의 검증된 모델 ID·reasoning 값을 분리한다. 기존 `ModelSelection`의 직렬화는 유지하고 저장 요청으로의 연결은 C1 후속에서 마이그레이션과 함께 수행한다.

영향도: 새 기반 모듈과 생성 계약을 추가한다. 기존 Claude 실행·설정·DB 스키마의 동작은 유지한다. 기존 프로세스 시작·종료와 lease의 가시성만 crate 범위로 확장하여 Codex 연결도 같은 종료·재시작 복구 보호를 사용한다. Codex 프로토콜은 스트림 조각/복수 메시지, 응답 ID, 성공/실패 메시지 구분을 검증하고 외부 오류 원문 대신 고정 메시지를 반환한다.

## 초기 구현 기반 모듈 — 2026-10-30

- `domain/provider.rs`: 공급자 태그 모델, 명시적 reasoning 타입, 모델/스레드 식별자 경계. 구체적 Codex 모델·effort는 카탈로그 결과로 확정한다.
- `codex_adapter/account.rs`: 관리형 ChatGPT 인증·공식 origin·계정/워크스페이스 식별 확인. 원문 이메일 대신 범위 해시를 반환하고 정보가 없으면 연결을 거부한다.
- `catalog.rs`: 페이지·항목 수 상한, 반복 커서·중복 모델·잘못된 기본값 거부, 숨겨진 모델 제외, 지원 effort 확인.
- `policy.rs`: 실행별 제한 구성과 적용된 설정 재검증. 기존 MCP별 비활성화, 공식 ChatGPT URL 정규화, API 키/다른 공급자 경로 거부. 이 검사는 전체 도구 미사용 입증을 대체하지 않는다.
- `protocol.rs`, `transport.rs`: JSONL 조각·UTF-8·응답 ID 검증, 비동기 알림 구분, 출력 2 MiB·큐 1,024개 제한, nonblocking 읽기/쓰기·취소·타임아웃·stderr 배수. 프로세스 lease를 확보하고 명시적 close에서 종료 실패를 보고한다. Drop은 정리 실패 시 lease를 남겨 복구 없이 다음 실행으로 넘어가지 못하게 한다.
- 진단용 native 테스트: 실제 앱 서버를 열어 기존 계정과 모델 목록을 조회하고 실행별 제한이 적용되었는지 검사한다. 생성 thread/turn은 시작하지 않는다. 일반 테스트에서는 ignored이며 명시적으로 실행한다.

진단 연결의 전체 제한은 20초, fixture 연결은 3초다. 기존 프로세스 그룹 종료 유예·재확인 경계를 재사용한다. 생성 턴의 제한 시간·중단 RPC·승인 요청 응답·세션 저장은 C2에서 별도로 연결해야 한다. 진단용 `Peer::call`은 알림을 버리므로 생성 이벤트 처리에 그대로 사용하지 않는다.

## 초기 검증과 남은 작업 — 2026-10-30

2026-10-30 초기 기반 시점에는 로컬 native 진단 1개가 통과했다. 계정/워크스페이스 식별, 모델 기본값·지원 effort와 실제 제한 적용을 제품 기반 모듈로 검사했다. 토큰·사용자 설정 파일을 변경하지 않았고 생성 호출은 없었다. C0의 도구 제한 입증·최소 지원 버전 확정과 C1의 설정/저장 요청/DB 연결, C2~C5는 아직 완료하지 않았다. 새 타입과 파서가 존재하는 것만으로 앱에서 Codex 생성이 가능하다고 표시하지 않는다.

Rust 테스트 로그: `/tmp/diffraft-codex-native-tests.log`. 생성 계약은 Rust exporter로 갱신했다. UI·DB 변경이 없어 이번 단위에서 네이티브 UI E2E나 앱 패키지 빌드는 실행하지 않았다. 신규 타입이 기존 요청에 연결되는 다음 단계에서 마이그레이션·모든 생성 경로를 다시 검증한다.

중간 실패와 수정: SHA-256 결과를 바이트별 16진수로 인코딩하도록 수정했다. 공식 URL의 끝 슬래시를 사용자 지정 경로로 오인한 검사는 실패 회귀 테스트 후 URL 파싱으로 보완했다. CLI의 `-c` 키에 JSON 따옴표를 붙이면 의도한 설정이 적용되지 않아, native 테스트에서 TOML inline table 값으로 전달하고 실제 적용 결과를 검사하도록 수정했다. stderr 과대 출력 fixture는 정상 결과를 먼저 반환하지 않도록 조정하고 전송 계층은 stderr를 비블로킹 방식으로 끝까지 배수하여 출력 상한을 확인한다.

근거: [App Server](https://learn.chatgpt.com/docs/app-server), [Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference). 설치 버전 스키마는 Git 제외 경로 `apps/desktop/.artifacts/codex-contract/schema/`에 생성했다.

## ADR-CODEX-006: 요청 저장과 실행 격리

기존 Claude 모델 문자열과 세션 테이블을 범용 구조로 일괄 변환하면 과거 요청의 의미와 재시도 호환성이 바뀔 위험이 있다. 새 요청은 공급자 태그를 저장하고 과거 문자열은 읽을 때만 Claude로 해석한다. Codex 세션은 별도 테이블에서 작업·계정 범위로 구분하고 공통 작업 기록에는 검증한 모델 JSON을 저장한다. 공급자 설정은 DB에, 기존 Claude 모델 설정은 원래 파일에 유지하여 손상된 Claude 설정이 Codex 사용을 막지 않게 한다.

실제 검증에서 `project_doc_max_bytes=0`이 전역 `AGENTS.md`를 차단하지 않음을 합성 표식과 로컬 요청 수신기로 확인했다. 인증 복사 없이 전용 홈을 만드는 대안은 기존 인증 갱신과 파일 격리가 충돌한다. 사용자 전역 파일 변경은 다른 Codex 실행에 영향을 준다. 따라서 macOS의 프로세스별 Seatbelt 정책으로 전역 `AGENTS.md`·`AGENTS.override.md`의 읽기만 거부한다. 원래 경로와 심볼릭 링크의 정규화 경로를 함께 제한하고 인증·설정은 Codex가 그대로 관리한다. thread 응답의 지침 출처가 비어 있는지도 검증하며, 격리가 불가능하면 생성 전에 실패한다.

영향도: Codex App Server 시작 경계와 합성 격리 테스트에 한정한다. 기존 Claude 프로세스에는 적용하지 않는다. 중첩된 Codex 권한 프로필의 범위 밖 읽기·쓰기 제한은 별도 native 계약으로 재검증한다.

같은 합성 실험에서 `skip_host_skill_discovery=true`만으로는 Codex 홈의 스킬 목록을 제거하지 못했다. 전역 스킬 폴더도 프로세스별로 읽기를 거부하고, 실제 `skills/list`에 활성 항목이 없음을 생성 전 확인한다. 계정 없는 로컬 추론 수신기에서 동일 기능 제한을 적용한 CLI 요청의 도구 목록은 부수효과 없는 `request_user_input` 하나였다. `debug prompt-input`의 도구 표현은 실제 추론 요청과 달라 단독 증거로 사용하지 않는다. 실제 App Server의 생성·도구 유도·외부 관측도 별도로 검증한다.

## 수정 실행 기록 — 2026-10-31

R0~C5의 실제 연결 변경은 설정 IPC → 구체적인 공급자/모델 확인 → 저장 요청 → 공통 실행 분기 → 계정 범위 세션 → 검증된 결과 등록까지 포함한다. Claude 어댑터와 승인·파일 저장 경계는 유지한다. 새 schema 8은 이전 DB를 먼저 백업하고 원래 요청 JSON을 보존한다. 설정의 개별 열만 갱신하여 동시 저장 유실을 막는다.

- R0: lease 토큰 교체 회귀의 첫/반복 close 실패와 빈 send 거부를 먼저 재현했다. 종료 결과를 캐시하여 반복·Drop이 오류를 성공으로 바꾸지 않는다. 종료 확인 실패 시 복구용 lease를 유지한다.
- C1~C2: 공급자 태그와 과거 Claude 문자열 읽기, 세 종류의 요청 고정, 모든 생성 모드, 계정별 불투명 thread, 명시적 재시도·중복 완료·원자적 저장을 연결했다. 로그인은 기존 ChatGPT 인증을 재사용하며 API 키를 감지하면 중단한다.
- C3: 설치된 Impeccable Operate·craft-floor·clarify·harden·audit·polish 기준으로 공급자/모델/경로·상태·사용량 안내와 확인/진행/복구 표시를 추가했다. 설정 저장은 모델을 호출하지 않는다. 포커스 복귀 시 테스트 성공을 무효화한다.
- 추가 회귀: SQLite CHECK의 NULL 결과가 불완전한 Codex 모델 객체를 허용했다. 실패 테스트 후 COALESCE로 차단했다. 실제 재개에서 이전 턴의 사용량 알림이 새 턴 ID를 고정하던 결함도 실패 테스트 후 관련 생성 이벤트에서만 ID를 연결하도록 보완했다.

### 실행 제한의 증거와 한계

| 경계 | 관측 |
| --- | --- |
| 인증 | 기존 관리형 ChatGPT 계정·공식 origin·범위 해시 확인. 앱에서 인증 파일이나 토큰을 읽거나 복사하지 않음 |
| 지침·스킬 | 합성 전역 AGENTS 심볼릭 링크·스킬 표식의 모델 문맥 유입 실패→격리 후 부재. 실제 thread 지침 출처와 활성 skills/list도 검사 |
| 모델 도구 | 실제 App Server의 추론 요청을 합성 로컬 수신기로 관측. 파일·셸·웹·MCP·플러그인 도구가 제공되지 않음. 부수효과 없는 request_user_input만 허용 가능하며 앱은 서버 도구 요청을 실행하지 않음 |
| MCP·알림 | 합성 Codex 홈의 더미 실행 표식이 생성되지 않음. MCP 서버별 enabled=false 및 notify=[]가 실제 요청에 적용됨. 별도 bootstrap 탐색에서도 상속 서버는 발견되었지만 더미 명령은 실행되지 않음 |
| 훅·플러그인 | 시작부터 feature 비활성화와 적용 설정·미제공 도구 확인. 제3자 패키지 각각의 내부 동작을 검증했다는 의미는 아님 |
| 파일 권한 | 독립 named profile에서 임시 허용 폴더 읽기 성공, 범위 밖 읽기·쓰기 실패. 전역 지침 격리와 중첩 시 command/exec 자체도 실행 불가였으며 제품은 이 RPC를 제공하지 않음 |

검증 버전은 `codex-cli 0.165.0`이다. 현재 계정에서 모델 8개·기본값 1개를 조회했고 실제 생성은 기본 모델 `gpt-6.1-sol`, effort `low`로 수행했다. 앱 중단·정리 960ms와 직접 턴 중단·정리 274ms를 측정했다. 모든 모델·계정·향후 버전의 권한이나 품질을 보장하지 않는다. 전체 App Server 연결은 120초, 중단 RPC 대기는 최대 3초이며 이후 소유 프로세스 종료를 확인한다. Claude의 기존 60초 제한은 유지한다.

### 최종 리뷰 메모

- 연결 테스트는 시작 시점의 저장 공급자·모델·경로를 고정하고, 종료 후 다시 저장값과 대조한다. 설정 변경 시 이전 성공을 반환하지 않는다. 가짜 서버의 준비/해제 파일로 순서를 제어한 실패→수정→통과 E2E를 추가했다.
- 실행 결과 재시도는 저장된 요청의 태그 모델을 따른다. 기존 Claude 모델 E2E의 문자열/이전 레이블 기대는 새 공급자 태그 계약으로 갱신했다. 과거 저장 문자열의 호환성은 별도 Rust 회귀로 유지한다.
- 실제 OS 키보드는 선택 실행 `codex-keyboard`다. System Events 자동화 대기와 별도 CGEvent 검사기의 접근성 권한 거부를 확인했다. 이 환경에서 검사기 권한을 앱 동작 결함으로 해석하지 않으며 일반 합성 E2E와 분리한다. 승인된 Computer Use 도구로 실제 OS 키보드·메뉴·저장·포커스 복귀를 별도로 통과했다.
- Impeccable 소스 검사는 발견 0개다. CDP가 없는 WKWebView에서는 실제 캡처·치수와 수동 검토를 병행했다. [UI 검토 기록](codex-ui-review.md)에 검증 범위와 남은 항목을 명시했다.
