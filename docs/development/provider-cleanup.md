## ADR-CODEX-012: 최소 정리 범위

| 대안 | 장점 | 단점·위험 | 결정 |
| --- | --- | --- | --- |
| 공급자별 훅과 실행기를 공통 프레임워크로 전면 통합 | 중복 형태를 크게 줄인다 | 기존 인증·저장·세션의 차이를 숨기고 회귀 범위가 커진다 | 제외 |
| 참조로 확인한 불필요 경로와 내부 노출만 제거 | 변경이 작고 실제 동작과 검증을 보존한다 | 비슷한 형태의 코드 일부는 목적에 따라 남는다 | 채택 |

Catalog 대안도 비교했다. resolve(selected)를 유지하면 기존 테스트 수정은 적지만, 실제 제품에서 쓰지 않는 선택 분기가 남고 저장된 effort 대신 기본값을 고를 여지가 있다. default_model()로 역할을 좁히고 명시적 선택은 기존 validate_choice()로 검증한다. 명시적·숨김·미지원 선택 테스트는 실제 검증 경로로 옮긴다.

가정: publish=false인 앱 내부 Rust API의 저장소 내 호출자가 대상이다. 공개 IPC·저장 JSON·DB·생성 TypeScript 계약은 변경하지 않는다. 테스트 전용 실행기·네이티브 계약은 실제 검증에 쓰이므로 유지한다.

영향도: 모델 카탈로그와 그 호출자·관련 테스트, 연결 다음 행동 함수와 호출자, Claude/Codex 연결·설정 훅의 반환값에 한정한다. UI가 소비하는 상태·동작은 그대로 유지한다.

최종 크기 검토: 네이티브 중단 테스트가 52줄이므로 시간 상한 assert와 겹치는 성공 시간 로그만 제거한다. 로그를 유지하면 관찰값은 보이지만 소비하는 호출자가 없고 함수 제한을 넘는다. 상한 검증은 그대로 유지하며 실행 동작·오류·소유권 검증을 바꾸지 않는다.

## 정리와 검증

- [x] Catalog의 미사용 selected 조회 분기를 제거하고 default_model()로 좁힌다.
- [x] connectionNextAction의 미사용 tested 인자를 제거한다.
- [x] 연결/설정 훅에서 UI가 쓰지 않는 내부 setter·ref·저장 함수를 반환하지 않는다.
- [x] 네이티브 중단 테스트의 중복 성공 시간 로그를 제거하고 시간 상한 검증을 유지한다.
- [x] 단위·Rust·정적·계약 검사와 관련 네이티브 E2E, 일반 앱 복원/테스트 코드 제외를 확인한다.

검증은 2026-11-01에 실행했다. 로그는 `/tmp/diffraft-cleanup-*.log`, 제품 제외 결과는 `/tmp/diffraft-cleanup-product-exclusion.json`에 남겼다. 관련 E2E는 합성 CLI를 사용했으며 실제 계정 호출·사용량 소비는 하지 않았다.

리뷰: 기본 모델을 고르는 조건은 기존 resolve(None)와 같다. 저장된 명시적 모델·reasoning은 validate_choice()로 검증하고 그대로 사용한다. 훅의 잠금·마운트 검사·설정 변경 시 무효화·취소·저장 처리에는 변경이 없다. 성공·실패·중단·재시도·재시작 E2E가 이 경로를 확인한다. 마지막 변경은 테스트 성공 로그 제거뿐이므로 해당 테스트 대상의 컴파일·Clippy와 포맷을 다시 확인했다.
