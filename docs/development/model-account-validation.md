## ADR-T7-001: 검증 경계와 대안

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| CLI를 직접 실행해 출력 검사 | 작은 독립 검사로 CLI 동작 확인 | 앱의 요청 저장·세션·승인 전 불변 계약을 우회한다. |
| 제품 launcher를 호출하는 별도 ignored 통합 검사 | 실제 진단·인자·파서·DB 경로를 함께 검증 | 계정·네트워크에 의존하므로 기본 자동 검사로 사용할 수 없다. |

두 번째를 선택한다. 기존 CLI 버전 간 재개 검사는 유지하고 모델 검사를 별도 파일에 둔다.
가정: 이번 미완료 TODO 진행 요청은 설치된 공식 구독 계정에서 합성 요청을 명시 실행하는 범위를 포함한다.
각 테스트는 별도 임시 폴더·작업을 소유하며 전역 환경·기본 모델·CLI 설치를 변경하지 않는다.
최소 버전과 최신 버전은 각각 실제 바이너리로 확인해야 하며 설치된 버전을 최신으로 단정하지 않는다.

영향도: 제품 코드는 변경하지 않는다. 테스트는 `generation::execute → CliLauncher::Installed → connection::prepared → profile::model_arguments`를 통과한다.
성공·실패 모두 요청 모델과 원문 보존, 프로세스 lease 해제를 검사한다. 재개는 앱 재시작 뒤 같은 세션·기존 후보·대화 보존을 확인한다.
중복·재시도 위험은 별도 임시 DB와 `--test-threads=1`로 제한하며 자동 재요청을 추가하지 않는다.

## 실행과 판정

`apps/desktop/src-tauri`에서 프로젝트 Rust 환경을 설정한 뒤 실행한다.

```sh
DOCREVIEW_TEST_CLI=/absolute/path/to/official/claude cargo test --locked \
  --test model_selection_native -- --ignored --test-threads=1 --nocapture
```

선택한 경로는 절대 경로여야 한다. 제품 진단이 공식 서명·최소 버전·필수 옵션·공식 구독 인증을 확인한다.
명시 실행은 네 모델 PATCH와 Sonnet PATCH→Opus EXPLAIN의 최대 여섯 요청을 사용한다.
모델 선택 검사는 선택 모델·성공/오류 코드·CLI 버전·소요 시간만 출력한다. 별도 관측 검사는 검증한 `modelUsage`/`canonicalModel` 식별자도 출력한다. 선택값으로 응답 모델이나 fallback 발생 여부를 추정하지 않는다.
기본 검사에는 CLI 실행 전 실패의 데이터 보존 검사만 포함한다.

공식 [모델 설정](https://code.claude.com/docs/en/model-config)과 [CLI 참조](https://code.claude.com/docs/en/cli-reference)를 재확인했다.
별칭·`--model`·`--effort`·`--resume`의 문서 계약과 설치된 바이너리의 관측 결과를 구분한다.

## T7-05 후속 Problem 1-Pager 및 ADR-T7-002

배경: 요청별 모델·세션 검증은 통과했으나 실제 CLI의 오류·fallback·응답 메타데이터는 관측하지 않았다.
문제: 제품 파서는 응답 본문과 세션만 반환하므로 기존 테스트에서 메타데이터를 확인할 수 없다.
목표: 공식 CLI의 원시 응답을 메모리에서 검사하고 모델 사용 메타데이터·사용 불가 오류·명시적 CLI fallback을 관측한다.
비목표: 사용자 계정/조직 정책 변경, 사용 한도 소진 유도, 안전 분류기를 자극하는 문서, 제품 모델 목록·자동 재시도 변경.
제약: 합성 연결 입력·임시 cwd만 사용하며 원시 응답·오류·인증값을 출력하거나 저장하지 않는다.

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 제품 응답 계약에 실제 모델 추가 | 사용자 표시까지 가능 | 데이터·UI 범위가 늘고 다중 모델 사용을 단일 실제 모델로 잘못 표시할 수 있다. |
| 별도 ignored 관측 검사에서 제한된 메타데이터 추출 | 제품 계약을 유지하고 CLI 증거를 수집한다. | 제품의 저장·완료 흐름을 검증하는 기존 T7 검사와 함께 해석해야 한다. |

두 번째를 선택한다. 공식 CLI와 제품 `connection::prepared → guarded_process::run → result::completion`을 재사용한다.
가정: 지원 목록 밖의 과거 모델에 대한 사용 불가 응답은 모델 가용성 오류의 관측이며 현재 계정의 권한 제한과 같다고 단정하지 않는다.
테스트 전용으로만 과거 모델과 `--fallback-model`을 지정하며 제품은 네 선택값과 기존 인자를 유지한다.
영향도: 변경은 테스트·문서에 한정한다. 응답에서 모델 사용 식별자만 검증해 추출하고 원문·응답·원시 오류를 로그에 남기지 않는다.
관측되지 않은 정책 제한·fallback은 완료로 표시하지 않으며, 실제 서비스 결과에 따라 후속 상태를 갱신한다.

## T7-05 관측 결과

공식 [모델 폐기 이력](https://platform.claude.com/docs/en/about-claude/model-deprecations)에 있는 과거 모델 `claude-3-7-sonnet-20250219`를 테스트 전용 기본 모델로 지정했다.
제품 `Sonnet` 선택의 의미를 바꾼 것은 아니다. 두 바이너리 모두 동일한 합성 연결 입력과 제품의 도구·MCP·safe mode 제한을 사용했다.

| 검사 | 최소 2.1.295 | 최신 대상 2.1.314 |
| --- | --- | --- |
| 과거 모델, 명시적 fallback 없음 | exit 1, 가용성 오류, 출력 모델 사용 0건 | 동일 |
| 같은 모델 + `--fallback-model haiku` | 검증된 EXPLAIN 성공, Haiku 사용 메타데이터 | 동일 |
| 기본값·Sonnet·Opus·Haiku 메타데이터 | 네 요청 모두 성공, `modelUsage` 및 `canonicalModel` 존재 | 동일 |
| ignored 관측 검사 | 3개 통과, 합성 호출 시도 6회 | 3개 통과, 합성 호출 시도 6회 |

이 관측에서 CLI 기본값의 사용 모델은 `claude-opus-5-5`, Sonnet은 `claude-sonnet-5-5`, Opus는 `claude-opus-5-5`, Haiku는 `claude-haiku-5-5`로 보고됐다.
명시적 fallback 요청의 사용 모델은 `claude-haiku-5-5`였다. 이는 해당 시점·계정의 CLI 응답 메타데이터이며 별칭의 영구 매핑이나 모든 계정의 기본값이 아니다.
각 요청은 새 임시 cwd를 사용하므로 이전 대화의 누적 사용 모델과 혼동하지 않는다.

과거 모델 실패는 제품 파서에서 `UNKNOWN_ERROR`로 분류됐다. 모델 부재와 계정 권한 부족을 구별할 근거가 없어 `RATE_OR_POLICY`로 바꾸지 않았다.
출력 모델 사용이 없는 실패와 fallback 지정 후 Haiku 출력 사용이 있는 성공을 함께 확인했다. 제품 실행 인자에는 `--fallback-model`을 추가하지 않았다.

한계: 현재 계정에서 네 선택값은 모두 사용 가능했다. 실제 계정/조직 403·사용 한도 429·서비스 과부하 529·콘텐츠 분류기 자동 fallback은 유발하거나 관측하지 않았다.
이번 완료는 모델 가용성 오류·명시적 CLI fallback·응답 메타데이터 관측 범위다. 모든 정책·서비스 오류의 실계정 검증 완료를 의미하지 않는다.
CLI `modelUsage`는 CLI가 보고한 사용 정보이며 서버 내부 라우팅의 독립적인 증명은 아니다. 제품은 계속 요청 모델만 저장·표시한다.

추가한 기본 자동 검사는 메타데이터 크기·타입·식별자 제한, 원문·오류·세션·계정 필드 제외, 성공 답변의 오류 오인 방지를 확인한다.
성공 답변을 가용성 오류로 오인하는 검사를 먼저 실패시킨 뒤 실패 envelope에서만 판정하도록 수정했다.
관측 검사 6개(두 CLI 버전에서 각각 3개)가 통과했다. 최종 코드는 `--features test-support --test cli_result --test model_observation_native`로 확인해 자동 검사 9개 통과·실계정 검사 3개 ignored를 확인했다.
전체 target의 clippy(`-D warnings`)·fmt·`git diff --check`도 통과했다. 앞 절의 Rust 전체 251개·프런트엔드 88개는 이전 T7 단계의 실행 결과이며 이번 테스트 추가 후 전체 재실행 결과로 표기하지 않는다.
