## 대안과 결정

| 경계 | 대안 A: 장점 / 위험 | 대안 B: 장점 / 위험 | 결정 |
| --- | --- | --- | --- |
| 요청 수명 | 패널을 항상 mount하고 숨김: 작은 변경 / 작업 변경·문서 이동의 수명을 여전히 UI에 의존 | 요청 hook을 문서 workspace로 이동: 명시적 수명 / 완료 소유자 검사 필요 | B. 폼은 표시와 입력만 담당 |
| 작업 변경 | 전체 workspace 재생성: 초기화 명확 / 다른 UI·진행 요청까지 재생성 | 작업 변경 시 임시 선택 UI만 해제: 초안 보존 / 첫 작업 인계 예외 필요 | B. visible·popup·captured·대상 변경 선택지를 해제 |
| 늦은 완료 | 항상 결과로 이동: 결과 즉시 노출 / 다른 작업으로 이동한 사용자를 되돌림 | 제출 문서·작업이 현재 소유자일 때만 이동: 현재 작업 보존 / 과거 결과는 대화에서 확인 | B. 기존 대상 초안 CAS 정리와 화면 이동을 구분 |

가정: 같은 문서·작업의 보기 왕복은 진행 중 요청을 유지한다. 다른 작업으로 명시 이동했다면 이전 요청의 완료가 현재 작업 화면을 바꾸지 않는다. 첫 작업을 명시 생성한 경우에는 같은 선택으로 작성창을 이어간다. 지시는 저장소에 유지하고 임시 표시 상태만 초기화한다.

영향: DocumentWorkspace → useSourceRequest → 상위 원문 생성 hook으로 결과 콜백을 연결한다. SourceRequestPanel의 로컬 생성 hook을 제거하고 선택 hook의 작업별 임시 상태를 초기화한다. Rust·DB 저장 경로는 변경하지 않는다.

## 구현 리뷰

- `useSourceGeneration`을 `useSourceRequest`에서 호출한다. 원문 패널이 보기 전환으로 제거돼도 생성 hook은 문서 workspace에 남아 실행 잠금·오류·완료를 처리한다. 확인 화면은 상위 busy도 반영한다.
- 완료는 제출 당시 문서·작업과 현재 소유자가 같을 때만 화면을 이동한다. 다른 작업으로 이동했다면 기존 제출 초안만 CAS로 정리하고 현재 화면을 유지한다. 오류도 해당 작업에서만 표시한다.
- 작업 변경은 visible·popup·captured와 선택 hook의 replacement·choices·message를 초기화한다. 대상별 영속 초안은 유지한다. 첫 작업 생성은 내부에서 발급한 작업 ID일 때 같은 작성창과 인용을 명시 인계한다.
- 정식 native에 두 결함의 실패 회귀와 성공·실패·다른 작업 완료 시나리오 4건을 등록했다. 초기 실행의 테스트 간 작업 선택 의존을 제거해 각 검사 시작 작업을 고정했다. 지연 실패 fixture를 E2E 전용 Rust 허용 목록에 등록한 뒤 요청이 실제 RUNNING인지 확인했다. 지원되지 않은 fixture의 실행 전 오류를 제품 실패로 집계하지 않았다.
- 요청 hook을 상향한 뒤 성공 메시지가 다음 작성에 남지 않도록 완료 시 메시지 소유자를 해제한다. 해당 단위 회귀의 실패를 먼저 확인했다. 성공·실패 PNG는 전역 생성 상태와 초안 저장 표시까지 안정된 뒤 캡처한다.

## 검사 범위

단위 검사는 같은 문서·작업의 재렌더 완료, 다른 문서/작업의 늦은 완료 무시, 실패 메시지의 소유자 복원을 확인한다. native 검사는 원문 요청의 성공과 지연 실패, A/B 전환 후 A 초안 복귀와 대상 변경 안내 해제, A 실행 중 B로 이동한 뒤 현재 작업 보존을 확인한다. 모든 사례에서 확정본 파일·버전을 보존한다. 첫 작업 인계·초안 재시작·겹침 이동은 기존 팝오버·전환 회귀와 함께 검사한다.

Rust 제품 저장·승인·공급자 계약과 DB 스키마는 변경하지 않았다. 이번 Rust 수정은 E2E 전용 지연 실패 응답 허용 목록 한 항목이며 일반 release에는 포함하지 않는다. 직전 검토의 Rust 333건 통과·30건 ignored는 재실행 수치로 집계하지 않는다.
