# 문서 상태 실패 복구

## Problem 1-Pager

- 배경: 완료·제거 상태는 localStorage, 선택 문서는 SQLite, 편집 중 본문은 메모리에 있다.
- 문제: 목록 읽기 실패 후 빈 상태 저장, 복원 실패 후 선택 문서 변경, 저장본 목차와 편집본 미리보기의 위치 불일치를 재현했다.
- 목표: 읽지 못한 설정을 덮어쓰지 않고 복원 실패 시 이전 선택을 유지하며 현재 편집본의 목차로 이동한다.
- 비목표: 저장소 통합·스키마 변경, 문서 삭제, 설치 앱 교체, 전체 화면 재설계.
- 제약: v1 설정 호환, 원문·이력·커서 보존, 기존 navigation lock·flush 사용, 실패와 재시도를 실제 WKWebView에서 확인한다.

## 대안과 ADR

| 문제 | 대안 | 장점 / 단점 / 위험 |
| --- | --- | --- |
| 목록 읽기 실패 | 재실행까지 모든 변경 차단 | 단순 / 일시 오류도 재실행 필요 / 복구 안내 누락 |
| 목록 읽기 실패 | 변경 전 미로드 상태만 다시 읽기 (선택) | 재시도로 복구·기존 ID 보존 / 로드 상태 필요 / 검증 전 상태 할당 금지 |
| 복원 실패 | 목록 복원부터 저장 | 선택은 유지 / native 실패 시 목록이 먼저 변경 / 다른 부분 실패 발생 |
| 복원 실패 | 이전 선택을 보관하고 실패 시 복구 (선택) | 기존 저장 구조 유지 / 보상 호출 필요 / 보상도 실패하면 명시적 오류 필요 |
| 목차 | 저장 완료까지 목차 비활성화 | 최소 변경 / 저장 중단 시 탐색 불가 / 사용 흐름 제한 |
| 목차 | 미리보기와 같은 Markdown 파서로 편집본 목차 렌더 (선택) | 저장과 무관한 정확한 탐색 / 목차 파싱 추가 / deferred 내용 불일치 시 이동 차단 필요 |

- 가정: localStorage 읽기 실패는 빈 설정과 다르다. 성공적으로 읽고 검증한 후에만 변경할 수 있다. 일시 오류는 다음 명시적 작업에서 재시도한다.
- 선택 복구는 현재 화면의 문서 ID를 우선하며, 화면이 비어 있으면 저장된 선택을 사용한다. SQLite와 localStorage 사이의 분산 트랜잭션은 도입하지 않는다. 보상 실패는 숨기지 않고 원래 오류와 함께 안내한다.
- 목차는 저장본의 업무용 섹션 정보와 분리한다. 현재 보기에서 쓰는 같은 편집 내용·GFM 파서·BOM 보정 위치를 사용하고 링크·이미지는 목차에서 실행/로드하지 않는다. deferred 렌더를 기다리는 동안은 목차 버튼을 비활성화한다.

## 호출 경로와 영향도

- `DocumentList.load → complete/forget/restore → save`: 로드 성공 여부와 검증 완료 후 상태 할당을 보장한다. v1/v2 ID, 쓰기 실패 시 메모리 상태는 유지한다.
- `workspaceActions.navigate → select_document → workspaceSnapshot → list.restore`: 후속 실패 시 선택을 보상하고 화면은 교체하지 않는다. flush와 잠금으로 입력 저장·중복 실행 방지는 유지한다.
- `EditingArea → DocumentOutline / Preview`: 동일 편집 스냅샷에서 목차와 렌더 위치를 계산한다. 원문 SourceEditor와 검토/범위 계산의 저장본 heading 계약은 바꾸지 않는다.

## 검증

- 수정 전 목록 읽기/형식 실패 후 변경과 실패한 복원의 선택 보상 회귀 5개가 실패했다. 실제 WKWebView에서는 저장이 중단된 편집본에 여전히 저장본 제목이 표시되는 회귀도 먼저 실패했다.
- `npm run test:unit`: 91개 파일·355개 테스트와 Node 스크립트 9개 통과. 초기 읽기 재시도·잘못된 설정 보존·다음 문서 선택 전 로드, 후속 snapshot 실패·선택 복구 자체의 실패 안내를 포함한다.
- `npm run typecheck`, `npm run lint`, `git diff --check`: 통과. 의존성과 Rust·SQLite·IPC 계약 변경은 없다.
- `document-navigation`: 4개 통과. 실제 SQLite 잠금으로 자동 저장을 중단한 상태에서 편집본 제목·미리보기 포커스·원문 커서 이동과 저장 재시도를 검증했다. 기존 중복/setext 제목·BOM·CRLF·한글/emoji 위치, 대상 부재 안내, 작은 창과 스크롤 검증도 유지했다.
- `document-management`: 5개 + 재실행 1개 통과. localStorage 쓰기 실패 후 현재 화면과 SQLite 선택이 같으며 재시도가 성공한다. 기존 메뉴·완전 제거·같은 파일의 ID와 이력 복구도 통과했다.
- 별도 원인 재현 검사 2개 통과: 복원 쓰기 실패 직후에도 이전 선택을 보존하고 실제 프로세스 재실행 후 같은 문서가 열린다. 수정 전 `document → review`, 수정 후 `document → document`였다. `.artifacts/bug-audit/green-restore-restart.log`에 격리된 합성 문서의 결과를 보관했다.
- 기존 `export` 5개 + 재실행 1개 통과. 내보내기 전용 미리보기·승인/외부 변경 경계·작업 파일 경로/이력 복원을 확인했다. 이번 관련 네이티브 검사는 총 18개다.
- 화면 확인: 1440×900의 저장 중단·현재 목차·제목 포커스와 800×600의 미리보기 탐색 캡처를 확인했다. `.artifacts/document-navigation/{live-outline,unsaved-outline,preview-compact}.png`. Impeccable 화면 검사에 새 결정적 문제는 없다. 실제 한글 IME·VoiceOver 수동 인수는 수행하지 않았다.
- SQLite와 localStorage가 동시에 실패해 선택 보상도 거부되면 원래 오류와 복구 실패를 함께 안내하고 재선택을 요청한다. 두 저장소 사이의 프로세스 강제 종료 원자성은 이번 변경의 보장 범위가 아니다.
- Vite의 기존 메인 청크 500 kB 초과 경고는 유지된다. 드라이버의 stale element 재시도 경고 후 탐색 검사는 통과했다.
- `npm run native:build` 통과. E2E 실행 파일을 일반 debug 빌드로 복원했다. 소스와 일반 빌드까지 반영했으며 설치 앱·실제 사용자 문서와 기존 SPEC/TODO 수정 사항은 변경하지 않았다.

## 후속 Problem 1-Pager — 부작용 보완

- 배경: 실패 복구 수정의 추가 검토에서 새 문서 생성 차단과 각주 목차의 잘못된 이동, 닫힌 목차의 입력 중 전체 파싱을 재현했다.
- 문제: 공통 목록 로드 검사가 문서 작업까지 차단한다. 자동 생성 제목에는 원문 위치가 없다. 숨긴 목차도 편집 때마다 렌더된다.
- 목표: 설정을 덮어쓰지 않고 문서를 열고 생성하며 오류 안내를 유지한다. 유효한 원문 제목만 이동하고 닫힌 목차의 파싱 비용을 없앤다.
- 비목표: 설정 초기화, 저장소/파서 교체, 검토 탐색의 마운트 동작 변경, 설치·커밋·push.
- 제약: 목록 쓰기 실패 시 선택 보상과 flush/잠금을 유지한다. 읽기 실패 뒤 복구한 상태 변경에도 현재 편집기와 목록의 선택을 맞춘다.

### 대안과 ADR

| 결정 | 대안 | 장점 / 단점 / 위험 |
| --- | --- | --- |
| 설정 오류 | 잘못된 설정 초기화 | 사용 즉시 재개 / 기존 상태 유실 / 제거한 문서가 다시 나타남 |
| 설정 오류 | 읽기 실패만 허용하고 설정 변경 없이 열기 (선택) | 문서 작업·원래 설정 보존 / 복원 상태는 적용되지 않음 / 사용자에게 계속 안내 필요 |
| 각주 | NaN을 0으로 보정 | 간단 / 잘못된 의미 / 원문 맨 앞으로 이동 |
| 각주 | 유효한 위치가 있는 제목만 수집 (선택) | 실제 원문과 일치 / 생성 제목은 목차에서 제외 / 버튼에서도 위치 검증 필요 |
| 성능 | 모든 outline 포털을 닫을 때 제거 | 간단 / 검토 탐색도 제거 / 검토 상태·키보드 회귀 위험 |
| 성능 | 문서 목차만 펼칠 때 마운트 (선택) | 입력 중 파싱 제거 / 다시 열 때 한 번 파싱 / 열린 뒤 실측 배치 필요 |

- 가정: 읽지 못한 목록은 상태를 바꾸지 않고 문서를 여는 모드로 취급한다. 성공 안내와 별개로 목록 오류를 유지하며, 완료·제거는 읽기가 복구될 때까지 실패한다. 정상 로드 후 쓰기 실패는 기존처럼 문서 선택을 보상한다.
- 복구 후 완료/제거가 현재 열린 문서를 숨기는 경우 다음 표시 문서를 먼저 읽고, 목록 저장 성공 뒤 편집기를 교체한다. 원문 저장은 기존 flush 경로에서 선행한다.
- 펼침 상태는 NavigationProvider와 native details toggle을 동기화한다. EditingArea의 문서 목차만 마운트를 제한하고 UnitReview/ReviewComparison 포털은 유지한다. 새 문서에 이전 펼침 상태를 넘기지 않는다.

### 영향도

`workspaceActions.navigate/run`의 오류 반환을 분리한다. `complete/forget`의 읽기 검사는 상태 변경 경계에 둔다. `DocumentOutline`은 위치 검증을 추가하고 `DocumentNavigation → NavigationProvider → EditingArea`의 펼침 상태로 생성을 제한한다. native 계약·의존성·원문 저장 형식은 유지한다.

### 후속 검증 결과 — 2026-11-12

- 새 단위 회귀 8개를 수정 전 실패시켰다. 설정 형식/읽기 오류 중 생성·열기·취소, 원래 설정 보존, 완료·제거 차단, 읽기 복구 후 표시 문서 일치, 생성된 각주 제목 제외를 확인했다.
- 최종 `npm run test:unit`: 92개 파일·365개와 Node 스크립트 9개 통과. `npm run typecheck`, `npm run lint`, `git diff --check` 통과.
- 관련 네이티브 E2E 58개 통과: 문서 탐색 6, 문서 관리·재실행 7, 기존 선택 복원 3, 내부 문서/패널 후속 4, 패널 6, 검토/그룹 13, 재작성 검토 12, 내보내기 6, 성능 1. 마지막 변경 후 탐색 6개와 내보내기 6개도 다시 통과했다.
- 실제 localStorage 형식 오류에서 새 문서를 생성하고 기존 파일을 열었다. 오류 안내는 유지하고 설정 원문은 덮어쓰지 않는다. 같은 상태의 완료는 실패하며 문서 선택은 유지된다. 복구한 설정 때문에 현재 문서가 숨겨지는 경우도 단위 검사로 검증했다.
- 각주 문서의 목차에는 원문 제목 `Main`, `Actual`만 표시한다. 원문 커서와 미리보기 포커스가 `Actual`에 도달한다. 각주 본문의 렌더링은 유지된다.
- 닫힌 목차는 마운트되지 않는다. 약 211 KiB(216,461자·ASCII) 편집본의 입력/저장 보존과 다시 펼쳤을 때 최신 목차 표시를 확인했다. 최종 beforeinput → 두 animation frame 측정은 30/19/30ms였다. 이전 리뷰의 목차 갱신 완료까지 측정과 종료 조건이 달라 배수 비교는 하지 않는다. 결과는 `.artifacts/document-navigation/input-after.json`에 있다.
- 초기 네이티브 실행에서 크기 변경 뒤 프레임/스크린샷 획득이 실패했다. 기존 실제 앱 PID 검증·전면 활성화·주 모니터 위치 복구 헬퍼를 탐색/문서 관리에도 적용하고 helper 준비 대상에 추가한 뒤 통과했다. 제품의 창 동작은 바꾸지 않았다.
- 1440×900·800×600 화면을 확인했다. 오류 안내가 있는 작은 창도 가로 넘침 없이 편집할 수 있다. 캡처는 `.artifacts/document-management/preference-warning-compact.png`, `.artifacts/document-navigation/{footnote-outline,preview-compact}.png`다. 실제 한글 IME·VoiceOver 수동 인수는 범위에 포함하지 않았다.
- 최종 `npm run native:build` 통과. debug 실행 파일은 일반 앱으로 복원했다. 기존 Vite 메인 청크 500 kB 초과 경고와 드라이버의 stale element 재시도 안내는 유지된다. 설치 앱·사용자 문서·기존 SPEC/TODO 수정 사항은 변경하지 않았다.
