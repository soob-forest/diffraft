# 요청 복원과 초안 격리 보완

2026-11-02 · 상태: 구현 및 자동 회귀 검증 완료

이 문서는 초안 격리 보완 단계의 체크포인트다. 아래 수치와 설치 미수행 표시는 당시 기준이며 최신 동작·검증·설치본은 [UX 개선 현재 상태](ux-status.md)를 따른다.

## Problem 1-Pager

- 배경: 요청 종류별 초안·첫 확인·원문 선택이 재실행 후에도 같은 의미로 이어져야 한다.
- 문제: 실패 요청 편집이 현재 종류를 유지한다. 늦은 확인 저장이 첫 준비 플래그를 되살린다. 세션 epoch가 영속 원문 선택을 무효화한다. 잘못된 초안 하나가 전체 복원을 막는다.
- 목표: 종류와 입력을 함께 복원하고 새 입력을 보호하며, 정확한 원문 선택을 복원한다. 손상 항목은 보존·잠금·명시적 초기화로 격리하고 정상 항목은 계속 사용한다.
- 비목표: 자동 AI 실행, 버전 검사 완화, 손상 기록 자동 삭제, DB 스키마 변경, 제품 설치·실계정 호출·일반 사용자 DB 접근.
- 제약: 기존 SQLite 키·저장 순번·단일 생성·확정본 불변 계약을 유지한다. 제품 파일 300줄·함수 본문 50줄 제한을 따른다.

가정: 실패한 일반 요청의 편집은 같은 요청 종류를 이어가려는 행동이다. 다른 종류의 초안은 보관하고, 복원할 종류에 다른 지시가 있으면 명시적으로 교체한다. 원문 선택은 전체 원문 스냅샷과 정확한 인용이 같을 때 새 확인을 준비할 수 있다.

영향: 일반 요청 초안의 편집·확인 갱신, 고정 원문 선택 유효성, 초안 복원/쓰기 경계와 관련 폼의 잠금 표시를 변경한다. 격리 원본은 DB에 유지하며 명시적 초기화도 CAS 저장에 성공한 뒤에만 입력 잠금을 푼다. 로그에 원문·지시·손상 JSON을 남기지 않는다.

## 구현 경계와 복구 동작

- 일반 요청은 최신 저장소 값에 함수형 갱신을 적용한다. 실패한 요청의 원래 종류를 선택하고, 그 종류에 다른 지시가 있을 때만 교체를 묻는다. 비동기 준비 결과는 현재 종류·지시가 같을 때만 확인에 사용한다.
- 영속 선택의 기존 직렬화 형식은 유지한다. epoch는 임시 드래그의 수명에만 사용하며 영속 선택은 전체 원문과 인용을 다시 검증한다. 동일한 문구를 다른 위치에서 검색해 대체하지 않는다.
- 알려진 형식 오류와 미지원 버전만 항목별로 격리한다. 그 외 오류는 전파하며 부분 hydrate도 하지 않는다. 잠긴 항목은 write/replace/update/clear 경로에서 보호한다. 정상 항목의 flush는 계속 허용한다.
- 초기화는 원래 저장 순번으로 빈 기록을 저장하는 CAS다. 성공한 뒤에만 원본 목록에서 빼고 입력 잠금을 해제한다. 실패하면 원본·잠금을 유지하며 동일 항목의 중복 초기화를 합친다. 복원 전에 생긴 새 입력은 CAS 초기화 뒤 별도로 저장한다.
- 저장 스키마·Rust 명령은 바꾸지 않았다. 원문·지시·손상 JSON은 로그에 기록하지 않고 원본 확인 UI의 읽기 전용 입력에서만 제공한다.

## 검증 범위

실패 테스트를 먼저 실행해 종류 미복원·준비 플래그 부활·epoch 선택 소실·손상 항목의 전체 hydrate 실패를 재현했다. 단위 검사는 초기화 실패·중복·새 입력 보호·쓰기 잠금·알 수 없는 오류 전파를 포함한다.

native 검사는 합성 문서·가짜 CLI와 실행기가 생성한 비공개 임시 DB만 사용한다. 새 두 프로세스 검사에서 실패한 재작성 종류 복원·모드별 보존과 교체 선택, 승인 후 선택 고정·문서 왕복, 첫 확인 취소·자동 실행 없음, 실제 재시작 후 선택 복원·격리와 정상 초안 저장·원본 확인·초기화 후 편집 재개를 확인한다. 손상 초안 복구 버튼은 1440×900·1280×800·800×600 × 100/150/200%에서 hit target·가로 넘침을 검사한다.

캡처·화면 측정은 `apps/desktop/.artifacts/draft-reliability/`에 둔다. 실행기 증명은 `.artifacts/native-build.json`이며 빌드 완료 후에만 생성된다. 일반 빌드·누락/오래된 증명·해시 변경·비소유 경로 차단은 Node 단위 검사로 확인한다.
