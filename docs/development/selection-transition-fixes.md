가정: 원문과 diff는 같은 confirmed 범위를 가리킬 때 실제 대상 초안을 공유하지만 각 화면이 마지막에 열었던 대상은 독립적이다. 기존 `active`는 diff 호환 키로 유지하고 원문은 `source-active`를 사용한다. 구형 confirmed 포인터는 원본을 삭제하지 않고 한 번 호환 복원한다. 실패 요청은 요청 종류에 맞는 화면으로 명시 복귀한다.

영향: Workspace 결과 콜백 → ReviewPanel → 선택 저장 콜백과 현재 결과 탐색을 연결한다. 선택 초안 포인터·첫 작업·실패 복구를 함께 바꾸며 대상 키는 유지한다. 원문·diff·재작성 비교의 비활성화가 예약된 팝오버 측정과 진행 중 드래그도 취소하도록 한다.

## 구현과 리뷰

- 직접 부분 저장도 기존 `openResult` 경로를 사용한다. 정확한 결과 조회 후 layout effect에서 그룹을 선택해 이전 승인 대상을 노출하지 않는다. 같은 묶음 재조회는 즉시 실행하고 중복 refresh로 조회를 다시 무효화하지 않는다.
- 원문과 검토의 활성 포인터만 분리했다. 기존 대상별 초안·CAS·손상 격리는 유지한다. 구형 confirmed 포인터는 유효성·소유자를 검사해 호환 복원하며 원본 기록을 삭제하지 않는다. 실패 복구는 요청의 종류에 맞는 화면으로 간다.
- 유효한 원문 선택의 우클릭만 기본 메뉴를 막는다. 빈 선택의 OS 메뉴와 복사 단축키는 유지한다. 보기·작성 상태 변경 시 원문과 diff의 팝오버와 예약 프레임을 취소한다. 드래그 중 비활성화 뒤 늦은 pointerup도 새 표시를 예약하지 않는다.
- 기존 네 화면 결함과 활성 포인터 회귀를 수정 전 실패로 확인했다. 드래그 중 전환도 단위 실패를 먼저 확인했다. 후속 테스트의 포커스 복귀·실제 후보 선택·저장된 revision 대기를 명시해 테스트 동기화 오류와 제품 결함을 구분했다. 숨은 diff 팝오버를 원문 팝오버로 오인하지 않도록 DOM 조회를 화면별로 제한했다.

[원문 복귀와 정확한 저장 결과 화면](../usage/ux/README.md#전환-경계-보완)을 실제 합성 앱 캡처로 추가한다. 화면의 보이는 문구만으로 데이터 보존을 판정하지 않고 저장 상태도 검사한다.

기존 앱은 정상 종료 후 일관된 0600 SQLite 백업과 이전 번들을 비공개 upgrade-backups에 보관했다. 검증한 번들을 임시 설치 경로에서 해시·서명 대조 후 교체했다. 사용자 문서로 기능 테스트하지 않았으며, 설치 앱은 저장된 원문 화면으로 열어 두었다.

일반 앱의 한국어 지시는 붙여넣기로 확인했다. 네이티브 문자 입력 도구의 한국어 문자열 전달은 이 검사에서 신뢰할 수 없어 실제 IME 조합 통과로 집계하지 않았다. Apple 공증 자격 환경은 없어 내부 ad-hoc 서명만 검증했으며 공개 배포 공증 완료를 뜻하지 않는다. [남은 실제 입력·작성자 인수](ux-native-validation.md)와 SPEC T16/T22는 계속 미완료다.
