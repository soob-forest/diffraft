# TO-BE 직접 이행 실행 기록

기준: [현재 TO-BE 계약](../design/design-guide.md#13-현재-to-be-계약) · [인수 기준](../product/acceptance-criteria.md#18-시안-이행-인수-조건). 2026-10-29 착수. VoiceOver 제외.

## Problem 1-Pager

- 배경: 사용자가 지정한 목표는 usability-comparison.html의 오른쪽 TO-BE 6개다.
- 문제: 이전 구현은 원본 S 시안과 기능 검사로 완료를 판정해 정보 구성·폼 적재·미감 차이를 남겼다.
- 목표: 고정한 `.mock.refined`와 실제 앱을 직접 비교하고 표시 구성과 동작을 함께 이행한다.
- 비목표: 새 디자인, 목표 목업 변경, DB/IPC 재설계, 자동 AI 실행·승인, 사용자 문서 수정.
- 제약: 원문/후보 분리·조건 flush·범위/revision 검증·단일 생성·초안 키·명시적 재시도를 유지한다.

## 기준과 증거

`capture-tobe.mjs`는 원본 HTML/JS/CSS를 변경하지 않고 Chrome 임시 프로필에서 `scene.after()`에 `.refined`를 적용한다. 비교 페이지 축소 없이1440×900/800×600로 렌더한다. `tobe-captures/target/manifest.json`에 원본4파일 SHA-256·각 PNG 해시·촬영 시각, scene별 JSON에 계산 스타일·영역 좌표를 기록한다. 합성 목표 캡처이며 실제 앱 증거와 구분한다. 기존 S PNG는 목표로 사용하지 않는다.

## ADR-TOBE-004 · 생략 기능의 표시 위치

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 기존 버튼·선택기를 그대로 상시 노출 | 접근 유지 | 목표의 간결한 위계·읽기 공간을 다시 침범 |
| 맥락별 보조 진입으로 이동 | 목표의 기본 화면과 기능 유지 | 키보드·발견성·초안/포커스 회귀 필요 |

후자를 선택한다. 저장·파일 위치는 제목 옆 문서 메뉴, 버전 기록은 본문 하단, 현재 작업 선택은 오른쪽 현재 작업 영역, 목차·그룹 전체 목록은 왼쪽 접힌 탐색으로 둔다. 이전 제안 묶음/통계는 검토의 보조 메뉴로 둔다. 생성 중단은 실행 중 앱 헤더에 유지한다. 파일 비교/내보내기는 목표 헤더의 주어진 자리를 따른다. 작업 패널 열기/닫기·문서 목록은 좁은 창 헤더에 제공한다. 선택 위치 복귀는 선택 제목의 보조 동작으로 유지한다.

가정: 목업은 동작하는 메뉴/목록의 모든 상태를 그리지 않았으므로 의미상 대응하는 진입점을 추가한다. 저장/작업 선택을 제거하거나 상태를 복제하지 않는다. 전문을 표시하는 방법은 아래 ADR-TOBE-002를 따른다. 코드 변경 전 호출 경로와 새 표시 위치를 확인하며 기존 데이터/요청 계약은 그대로다.

같은 실제 fixture의 before/after 상태는 유지한다. 목표는 정적 예시이므로 실제 빈 새 문서 목록·업무 상태·Markdown 문맥의 차이를 명시한다. 창 크기는 타이틀바 추정 대신 실제 viewport 피드백으로 맞췄다. 목표 Chrome1x와 실제 WKWebView의 디바이스 배율/글꼴 래스터화는 구분하며 CSS px로 실측한다.

TB1 영향도: App 탐색/DocumentWorkspace grid/DocumentToolbar의 표시 순서와 VersionHistory 위치를 바꾼다. 단일 model과 flush 호출·복원 확인의 수명은 유지하며 저장/위치 기능은 문서 메뉴로 옮긴다. 사후 조건은196px 탐색·패널 y50·360px·하단 버전 기록이며 새 네이티브 프레임 검사가 수정 전 실패했다(`tobe-frame-before.log`).

TB1 공통 프레임 회귀4개 통과(`tobe-tb1.log`), TypeScript 통과. 목표와 실제 프레임을 대조했다. 에디터/오른쪽 내부 면의 남은 이전 CSS는 TB2에서 정리한다. TB2 영향도는 TaskPanel의 표시 위치·TaskForm의 펼침 구조·ScopeBar의 편집 노출·RequestForm의 요청 종류 UI다. 조건 폼을 언마운트하지 않고 기존 flush와 draft 키를 유지하며 타입/범위 선택만 표시 컨트롤을 바꾼다. 추가 I/O·자동 전송·재시도는 없다.

TB3/TB4 영향도: 검토 도구 순서를 고치고 상세/코멘트/후보 수정/재제안의 표시 모드를 기존 단일 panel에 추가한다. 폼은 hidden으로 보존하고 기존 comment draft 키·revision/quote 검증을 그대로 사용한다. 코멘트 진입은 입력을 직접 보여주고 저장과 재제안 지시 작성을 분리한다. 인용4줄은 표시만 제한하며 저장 문자열·좌표는 변경하지 않는다. ResizeObserver는 각 인용의 실제 넘침만 감지한다. 기존 전문 상시 적재 대비 표시 모드 분리 안을 선택한 근거는 ADR-TOBE-001/002다. 검토 순서·상세 제목·인용16px 검사를 먼저 추가해 기존 빌드의 불일치를 확인한다.

## ADR-TOBE-005/006 · 실제 스크롤과 비교 문맥

- 005: 목업의 고정 패널은 마지막 문구가 보이지만 하단24px padding이 패널 밖으로 흐른다. 그대로 auto 스크롤에 적용하면 빈 여백 때문에 native 세로 스크롤이 생겨 필드가14px 좁아졌다. 스크롤바 숨김은 발견성을 해치므로 제외하고 실제 task-panel의 마지막 하단 여백만0으로 두었다. 내용·상단/좌우24px·오류 스크롤은 유지한다. 변경 후 client359/scroll359·높이818/818, 필드311px와 첫 화면 행동 노출을 확인했다.
- 006: TO-BE는 섹션 제목을 그룹 제목으로 보여주며 같은 Markdown 제목을 본문에 반복하지 않는다. 문자열의 #을 모두 숨기면 코드 주석을 잃으므로 제외했다. 실제 파서가 반환한 Heading.fromUtf16과 일치하는 변경 없는 제목·인접 구분 공백만 기본 비교에서 생략한다. 전체 문맥/명시적 펼침에는 원래 행을 모두 표시하고 코드 주석·코드의 빈 행은 보존한다. 수정 전 단위3개 실패 후 전체71개 통과. 단일 행 번호는 삭제=이전/추가=이후를 기호와 함께 표시하고 원래 좌표·승인 범위는 그대로다. 선택 제목은 키보드 가능한 선택 위치 복귀 버튼으로 유지한다.

TB3/4 기본 프레임·표시 순서·입력 가시성4개 네이티브 검사 통과(`tobe-tb34.log`). 전체 과업 회귀는 아직 미통과다. TB5 영향도: 재개 안내는 실제 미처리 개수/작업명으로 구성하고 실패 요청의 실제 instruction을 인용한다. 적용 전 버전 비교는 기존 useReviewActions의 versionId와 useHistory를 유지한 채 DocumentMain 하단의 안정적인 portal host로 이동한다. 상태를 DocumentModel에 복제하는 안보다 변경이 작아 이 안을 선택했다(ADR-TOBE-007). 모드 전환으로 비교창 수명이 바뀌지 않고 저장/복원 검증도 기존 경로를 따른다.

## ADR-TOBE-008 · 최소 창과 확대 확장

800×600에서는 원문510px+요청290px를 그대로 이행한다. 그보다 좁아지는 확대 환경은 두 열을 계속 줄이는 안(동시 노출/읽기 폭 악화)과720 CSS px 미만에서 한 영역으로 왕복하는 안(16px 보존/왕복 필요)을 비교해 후자를 선택한다. 낮은 창의 검토 도구·본문은 글꼴 축소나 overflow 잘림 대신 바깥 스크롤과 자연 높이로 접근한다. 원문/검토/오른쪽 폼은 언마운트하지 않는다. 현재 작업 선택은 오른쪽의 보조 진입에 유지하고 목록 토글은 좁은 창의 문서 헤더로 이동한다. App이 소유한 목록 상태를 콜백으로 전달하며 새 상태 복제는 없다.

TB7 영향도: ConnectionSettings가 sidebar 안에 있어 무테 탐색 버튼 스타일이 성공 CTA까지 상속됨을 독립 Impeccable layout 검토에서 확인했다. dialog를 body portal로 격리하는 안(기존 modal·상태 수명 유지/상속 제거)과 sidebar 선택자를 모두 제한하는 안(범위 작음/향후 누락 위험)을 비교해 portal을 선택했다. 상태 모델은 그대로이며 실제 테스트 성공 때만 성공 면을 제공한다. 목표650px·padding32와 CTA 배경을 네이티브로 검사했다(`tobe-tb7.log`,4개 통과). 좁은 요청은 조건 편집과 초안 보조 행동을 같은 행에 두고 대화/추가 요청을 접어257px 입력 폭을 유지했다. 보조 내용은 언마운트하지 않는다.

ADR-TOBE-009: 원문 목업의 읽기 시작선을 맞추기 위해 접기 gutter는 흐름에서 빼고 hover/키보드 포커스 시 표시한다. 접기 단축키·Markdown 편집·줄 번호·undo는 그대로다. 원문 기본 표시는 목업처럼 중립 문자·활성 배경으로 통일한다. diff 헤더는 실제 파서 제목만 사용하며 원문 저장 좌표와 분리한다. 조작을 삭제하는 안보다 표시 경계를 좁히는 안이 회귀 위험이 작다.

독립 layout A는6개 렌더·계산 치수/소스를 검토했고, 종료 후 독립 mechanical B의 layout/full detect는각 exit0/[]였다. A의 연결 CTA 상속·제목 가림·좁은 요청·원문 시작선·복귀 포커스를 수정 중이다. B는 빈 좁은 시작 화면의 탐색 단절을 추가로 찾아 수정 전 실패 회귀를 준비했다. 탐지0건을 시안 합격으로 해석하지 않는다.

TB8 회귀 중간 기록: 원문/연결/생성/재시작·시안 구조·독립 SC07·충돌/복구·좌우 정렬·이력/재작성/내보내기·성능/기동 실패를 각각 실행했다. 이전 label/위치 참조와 새 helper의 CSS/text 선택자·누락 import는 테스트 문제로 정정했다. 실제 결함은 빈 좁은 창의 탐색 누락, 숨긴 comment 상세가 작업 탭까지 숨기던 selector, 요청 외부로 옮긴 빈 status의 여백이었다. 각각 수정 전 실패 로그를 보존한다. 새 긴 표 검사는4줄 표시·전문 펼침·초안 왕복·복귀 포커스·전체 quote 저장·저장만으로 생성 없음이 통과했다.9개 환경의 도달/히트·초안 검사는 통과했고 busy 코멘트 왕복은 수정 후 재실행 대상이다. 최종 전체 통과 전 완료로 간주하지 않는다.

ADR-TOBE-010: 좁은 기본 요청은 대화/추가 요청만 접으며 저장/범위/조건 오류와 초안 가져오기 확인은 요청 옆에 유지한다. 이전 실패/중단이 있으면 대화를 펼친다. 모두 접는 안은 오류 발견성을 해치고 모두 펼치는 안은 기본 입력 폭을 줄이므로 상태별 노출을 선택했다. task/global 조건은 이전과 같은 독립 flush 경계이며 기존 종료 검사의 task textarea 선택자를 직접 자식2개로 제한했다. 공통 조건까지 ‘task 저장 중 잠금’ 대상으로 새로 묶지 않았다.

ADR-TOBE-011: 독립 typeset 검토가 실제800×200% 캡처의 버전 기록/diff 중첩과 긴 표의 앞부분만 표시하는 미리보기를 발견했다. 버튼 hit/가로 overflow 검사는 이를 놓쳤다. 새 실제 사각형 교차·변경행 가시성 검사가 수정 전 실패했다(`tobe-extreme-before.log`). 낮은 창의 검토를 무한 확장하는 안(전체 본문/과도한 바깥 스크롤)과 높이280px의 내부 비교+자연 높이 도구/기록 흐름(읽기·이동 모두 접근)을 비교해 후자를 선택했다. 문서/검토/기록을 같은 grid의 자연 행으로 배치한다.

긴 인용은 원문/제안 전체 문자열을 자르는 안(앵커 손실)을 제외하고, 첫 변경의 앞 문맥으로 표시 스크롤만 이동하는 안을 선택했다. 명시적으로 선택한 부분 인용은 처음부터 표시한다. ‘전체 인용 중 변경 위치 미리보기’와 전문 펼침을 함께 제공하며 실제 저장 quote는 그대로다. 변경 위치 계산4개 단위 검사를 추가해 총75개 통과했다. 일반6개 목업의 한 줄 인용에는 영향이 없다. 헤더 메뉴는 보조 진입으로서 주 버튼 정렬을 밀지 않게 기존 빈 공간에 배치한다. 시안의 정렬선과 기능 접근을 함께 유지한다.

최소 창 흐름 수정 후9개 실제 콘텐츠 크기/배율과 초안·히트·기록 교차 검사가 통과했다(`tobe-grid.log`,사용성10개). auto grid행의 축소 허용 때문에 본문이 기록 위로 넘쳤으므로 낮은 창의 행을 max-content로 정했다. 모든 행에 고정 높이를 주는 안은 긴 조건/오류를 잘라 제외했다. 확대 비교는 내부280px 스크롤, 도구와 기록은 바깥 자연 흐름을 따른다. 기록 자체의 hit 검사도 최종 회귀에 추가했다.

TB3 본문 마감: 기존 ‘텍스트로 변경 읽기’는 제거하지 않고 오른쪽 작업 옵션으로 옮겨 기본 diff의444px 읽기 높이를 확보했다. 복원/충돌 비교의 텍스트 대안은 기존 위치를 유지한다. 변경 그룹 제목 위12px과 실제 WKWebView 행 높이의 반올림 차이를 보정해 목표의32.8px 행 리듬을 맞춘다. 단순 footer 숨김 안보다 보조 진입 이동 안이 기능 접근과 시안을 함께 보존한다.

## ADR-DOC-001 · 일회성 계획의 문서 통합

- 배경/문제: 완료된 작업 계획이 영속 문서와 중복되고 최신 기준·링크·비교 테스트가 임시 체크리스트에 의존했다.
- 목표: 유효한 화면 계약·설계 결정·인수 조건을 기존 문서에 통합하고 임시 계획을 커밋 이력에서 제외한다.
- 비목표/제약: 앱 동작·과거 캡처·검증 결과를 바꾸지 않고 사용자 평가의 미검증 상태를 유지한다.
- 대안 A: 삭제 커밋만 추가하면 변경은 작지만 과거 커밋에 파일이 남는다. 대안 B: 최초 추가 커밋을 수정하고 후속 커밋을 재적용하면 이력에서 제외되지만 후속 커밋 해시가 바뀐다. 사용자 요청에 따라 B를 선택한다.
- 가정: 완료된 체크리스트 자체는 영속화하지 않는다. 비교 자료의 T/R 번호는 당시 작업 식별자로 남기며 현재 완료 여부는 실행 기록으로 판단한다.
- 영향: 문서 링크·시각 기준·비교 자료 검사만 변경한다. 테스트는 임시 파일의 태스크 존재 검사 대신 이력 식별자의 형식과 로컬 자료 연결을 확인한다.

문서 통합 검증: 임시 체크리스트 제거 뒤 비교 테스트8개 통과, whitespace 검사 통과. 전체 비교12개 중2개는 기존 `tobe-captures/target`의 manifest/PNG 누락으로 실패하며 변경 전 테스트에서도 재현했다. 기존 실행 당시의 통과 기록과 현재 체크아웃의 재실행 결과를 구분한다.
