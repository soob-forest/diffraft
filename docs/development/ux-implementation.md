# UX 개선 구현 기록

2026-11-01~02 · 최초 구현과 첫 보완의 체크포인트다. 아래 검사 수·설치 미수행·미완료 표시는 해당 단계 기준이며, 최신 구현·검증·설치본은 [UX 개선 현재 상태](ux-status.md)를 따른다.

기준: [제안서](../design/ux-improvement-proposal.md)와 당시 로컬 실행 계획의 T00~T16. 아래 표에 구현 범위를 요약하고 당시 변경의 결정과 검증 결과를 보존한다.

## 문제와 변경 경계

배경: 선택한 표현을 다시 요청하고 결과를 검토하는 과정에서 대상·상태·작성 내용이 끊긴다.
목표: 정확한 선택 수정, 실제 저장값에 근거한 상태, 원문 편집 영향, 초안 복원을 구현한다.
비목표: 자동 승인·재실행·의미 병합·승인 단위 분할. 제약: 기존 파일 충돌·단일 생성·버전 검증 유지.
가정: 로컬 단일 작성자이며 과거 요청 JSON의 실행 의미를 유지한다.

## 결정과 영향

- 상태 표시: 컴포넌트마다 분기하면 변경은 작지만 문구가 달라질 위험이 있다. 순수 판정 함수를 공유하면 테스트와 일관성이 좋아져 이 안을 선택한다. 승인·저장 로직은 변경하지 않는다.
- 코멘트: 저장과 재제안을 합치면 단계는 줄지만 저장 실패·중복 처리가 커진다. 우선 미저장·저장 중 다음 행동을 막는 안을 선택한다. 직접 선택 수정은 별도 경로다.
- 나머지 선택 계약·저장 대안은 SPEC의 비교를 따른다. 작업별 추가 가정은 아래 기록에 남긴다.

## 자동 검증

- TypeScript 112개와 프로세스 종료 4개 통과. 타입 검사·린트·차이의 공백 검사도 통과했다.
- Rust 자동 검사 329개(workflow 155개 포함)는 구현 단계에서 통과했다. 잠금 해제 후에는 Rust 제품 코드를 변경하지 않았다.
- 선택 수정 native 14개 통과: 후보 성공/잘못된 응답, 별도 프로세스 초안 복원, 확정 문맥·재작성 후보 선택, 키보드·직접 수정·이력·원문 범위·완료·첫 요청을 포함한다.
- 기존 사용성 native 10개 통과: 조건 저장 실패·문서 이동 차단·초안 보존·100개 변경·작은 창의 본문/기록 분리를 확인했다.
- 긴 인용·지시·모델명에서 1440×900·1280×800·800×600 × 100/150/200% 조합을 통과했다. 본문 16px, 인용 최대 4줄, 가로 넘침 없음, 요청 버튼의 실제 hit target을 검사한다. 실제 오류 안내도 같은 9개 조합을 통과했다. 관측값은 `.artifacts/ux/selected-layout.json`, `error-layout.json`에 남긴다.
- 전체 native 회귀 38개 실행 단계·120개 항목 통과. 이후 스크롤 메뉴·종료 리스너 보호를 반영한 최신 빌드에서 관련 8개 실행 단계·23개 항목도 통과했다.
- 최종 `npm run native:build` 통과. E2E 기능이 없는 일반 debug 빌드로 복원했다.

구현 단계의 `contracts:check`, `native:fmt`, `native:check`, `native:test`, 프런트 `build`는 통과했다. 최종 변경의 프런트 71개 파일을 다시 점검해 파일 300줄·함수 본문 50줄·매개변수 5개·복잡도 10 제한 위반이 없었다.

## 실제 화면

[현재 앱 캡처 1~9](../usage/ux/README.md)에 합성 fixture의 선택 작성·확인·새 후보·잘못된 선택·원문 범위·편집 영향·과거 비교·검토 완료·요청 종류를 연결한다. 각 화면의 원본·재현 테스트·SHA-256을 기록한다. 실제 캡처와 정적 시안의 패널 구성 차이도 명시한다.

## 잠금 해제 후 통합 UX 결정 기록 (ADR)

상태: 채택 · 2026-11-01. 가정: 로컬 단일 작성자이며 문서 전환 때 문서 ID로 workspace를 재생성한다. 실제 저장값과 ID를 검사하며 시간 지연으로 동작을 가정하지 않는다.

화면 잠금 해제 후 검사를 재개했다. visibility 검사나 테스트 조건을 우회하지 않았다.

- 선택 작성 중 떠 있는 도구가 남는 실패를 캡처와 E2E로 재현했다. 클릭 때 선택을 지우면 복귀 대상을 잃는다. 작성 중 도구만 숨기고 비교가 바뀌면 위치를 무효화하는 안을 선택해 선택을 보존했다.
- 키보드 메뉴를 연 직후 높이 보정 스크롤이 메뉴를 지우며 포커스를 잃는 경합을 재현했다. 임의 대기나 모든 스크롤에서 닫는 안 대신 포커스를 준 메뉴만 유지하는 안을 선택했다. 드래그 자동 메뉴는 스크롤 때 닫고, 비교가 변경되면 모두 무효화한다. 실제 스크롤 후 버튼 포커스와 Esc 복귀를 native 검사에 추가했다.
- 문단 확장 뒤 포커스가 버튼에 남아 단축키가 끊겼다. 버튼에 남겨 재선택하게 하는 안보다 명시적 범위 이동 후 diff로 포커스를 돌리는 안을 선택했다. 드래그에는 포커스 이동을 추가하지 않았다.
- 추가 초안 저장이 조건 저장보다 먼저 실패해 접힌 조건 폼에 실패가 표시되지 않았다. 검사 기대를 바꾸면 기존 보장을 잃으므로 원문·조건을 준비한 뒤 초안을 flush하고 확인을 여는 순서를 선택했다. 어느 저장이든 실패하면 실행하지 않는다.
- 작은 높이에서 새 중앙 비교 래퍼의 flex basis가 0으로 계산됐다. 임의 최소 높이는 긴 도구 영역을 가릴 수 있어 기존의 내용 기준 스크롤 정책을 현재/이력 래퍼에도 적용했다. 본문·검토 영역이 diff보다 작지 않은지도 검사한다.
- 첫 작업 직후 공통 조건 로딩과 자동 요청 준비가 경합했다. 시간 지연은 장치 속도에 의존하므로 같은 읽기 Promise의 완료를 기다리는 안을 선택했다. 읽기 실패는 전파하고 재시도할 때 다시 읽는다. 문서마다 workspace가 재생성되는 기존 경계를 따른다.
- 크기가 넘친 비교 파일은 빈 줄을 줄이는 대신 타입과 진입 hook을 분리했다. 실행·승인·저장 계약은 바꾸지 않았다.
- 영속 초안을 보존하는 변경으로 재작성 실행 중에도 모달 확인창이 남는 회귀를 `rewrite-cancel`로 재현했다. 확인창을 유지하면 모델 정보는 남지만 중단 버튼을 가린다. 실행할 요청 객체는 고정한 채 확인 상태만 먼저 비우고, 지시는 별도 실행 스냅샷으로 보존하는 안을 선택했다. 일반 요청에도 같은 정책을 적용하고 진행 중 확인창이 닫히는 회귀 검사를 추가했다. 성공 때는 일치하는 실행 초안만 지우고 실패·중단에는 지시를 남긴다.
- 초안 복원 실패 때 workspace가 마운트되지 않아 기존 시작 오류·정상 종료 처리가 가려졌다. 복원 실패에도 편집 화면을 여는 안은 미복원 초안을 덮을 위험이 있어 채택하지 않았다. 입력 화면이 한 번도 열리지 않은 초기화 단계만 읽기 전용 오류/재시도/정상 종료를 제공한다. 일반 workspace는 원문·조건·초안 flush를 계속 필수로 수행한다. 지원하지 않는 DB의 바이트 불변과 부모가 관측한 code 0/signal null, Exit 시 WebView 생존을 검사했다. 빠른 종료의 드라이버 응답 소실도 종료 증거 없이 통과시키지 않는다. 초기화→workspace 리스너 교체 뒤 늦게 전달된 종료 이벤트는 비활성 리스너에서 차단하며, 이를 단위 검사로 추가 검증했다.
- 기존 완료 문구를 검사하던 E2E는 실제 완료 상태·승인 2개/거절 1개·확정본 보기 계약으로 갱신했다. Codex 복구 검사의 새 문서 생성 경합은 새 ID·빈 원문·이동 완료를 먼저 확인하게 고쳤다. 제품의 원문 불변 검사는 유지했다.
- 기존 TO-BE 검사는 요청 종류 2개를 가정했다. 이제 정확한 3개 라벨(수정 제안/설명만/전체 재작성)을 검사한다. 첫 요청 테스트의 넓은 label 선택도 실제 입력란으로 한정하고 목표가 보존되는지 확인했다.

## 남은 수동 인수

화면 잠금 차단은 해결됐다. 실제 IME·VoiceOver는 [별도 인수 절차](ux-native-validation.md)에 시도 결과와 재현 방법을 기록했다. 네이티브 제어로 한글 문자열과 자모 삭제는 관찰했으나 composition 이벤트는 0이었고, VoiceOver 프로세스도 실행되지 않았다. 수동 선택 검사 2개는 실패 종료했으며 자동 회귀 통과 수에 포함하지 않는다. 자동 문자 입력·AX 트리 조회를 실제 입력기·스크린리더 통과로 대체하지 않는다.

실제 작성자의 준비 시간·전환 수·재입력·범위 이해는 측정하지 않았다. 동일 문서·지시로 기존/새 흐름을 각각 관찰하고 기준값을 측정한 뒤 목표를 정해야 한다. 가짜 E2E 실행 시간은 사용자 과업 시간을 대신하지 않는다.

SPEC의 최종 접근성·사용성 게이트는 미체크로 유지한다. PR/커밋·설치·실계정 호출은 수행하지 않았다. 설치된 앱과 사용자 데이터는 변경하지 않았다.

## 구현 리뷰 후 보완 — 2026-11-02

[보완 기록](ux-followup.md)에 문제 정의·대안·실패 회귀부터 최종 검증까지 기록했다. 같은 후보 재선택의 최신 head 갱신, 실패 요청과 정확한 초안 연결, 직렬화 크기 사전 검사·조건부 비우기·오류 복구 화면을 보완했다.

이번 변경의 검증은 TypeScript 122개·종료 검사 4개, 타입·린트·빌드, 관련 native 8단계·31항목과 복구 오류 화면 9개 창/배율 조합이다. 일반 debug 빌드로 복원했다. 기존 전체 native 120개·Rust 329개는 이전 구현 기록이며 이번에 전체 재실행한 수치로 합산하지 않는다. 실제 IME·VoiceOver·작성자 평가는 계속 별도 미완료다.
