# 완료 문서 복구와 패널 상태 보완

## Problem 1-Pager

- 배경: 문서 목록 제거·즉시 다시 열기와 패널 크기 조절을 구현했다.
- 문제: 문서 이동·재실행 후 제거 안내가 없어지면 앱 내부 문서를 찾기 어렵다. 요청 패널 너비·열림 상태도 문서 전환 시 초기화된다.
- 목표: 항상 접근 가능한 완료 문서 목록에서 원래 문서·이력으로 복구하고, 같은 앱 세션의 문서 전환에서 패널 너비·열림 상태를 유지한다.
- 비목표: 파일·이력 영구 삭제, 저장 스키마·IPC 변경, 패널 설정의 앱 재실행 후 복원, 기존 비교 테스트의 별도 실패 수정.
- 제약: 원문·조건·초안 저장과 목록 설정 저장에 실패하면 복구를 적용하지 않는다. 좁은 화면의 본문·요청 전환과 현재 입력 보존을 유지한다.

## ADR: 보완 방식

- 가정: 이번 패널 상태 유지는 앱을 열어 둔 동안의 문서 전환을 대상으로 한다. 완료 문서 목록은 기존 localStorage의 문서 ID를 사용해 재실행 후에도 제공한다.
- 복구 대안 A — 마지막 제거 안내를 계속 유지: 코드 변경이 작음 / 여러 문서·재실행 복구를 해결하지 못함 / 제외.
- 복구 대안 B — 완료 문서 목록: 모든 제거 문서를 파일 선택 없이 복구 / 원본 snapshot의 전체 문서 목록을 유지해야 함 / 선택.
- 상태 대안 A — 문서별 상태 저장소·Context: 문서별 복원과 깊은 트리 공유에 유리 / 추가 추상화·동기화가 필요 / 제외.
- 상태 대안 B — 상위 App 상태와 명시적인 props: 문서 전환과 독립적이고 I/O가 없음 / 두 계층에 props 전달 필요 / 가장 단순한 방식으로 선택.

## 호출 경로와 영향도

- `useWorkspace → workspaceActions → editorCommand`의 저장·이동 잠금은 그대로 사용한다. 원본 snapshot을 보관하고 활성/완료 목록을 표시 시점에 나눈다. 숨긴 문서의 ID·메타데이터를 버리지 않으므로 재실행 후에도 복구할 수 있다.
- `App → WorkspaceContent → DocumentWorkspace → WorkspaceBody`로 요청 패널의 너비·열림 상태를 전달한다. 문서 ID에 따른 편집기 재마운트는 원문·대상 상태만 초기화하고 패널 상태는 유지한다.
- 완료 문서 복구 성공으로 버튼이 사라지면 표시 중인 원문 편집기로 포커스를 이동한다. 원문이 숨겨진 작은 창에서는 패널 전환 버튼으로 복귀한다. 실패하면 버튼과 현재 입력을 유지한다.

## 검증

- 보완 전 실행에서 요청 패널 `600 → 360px` 초기화와 완료 목록 부재를 먼저 검출했다. 원본 snapshot 보존·완료 목록 복원 단위 테스트도 먼저 실패시켰다.
- `npm run typecheck`, `npm run lint`, `git diff --check`: 통과.
- `npm run test:unit`: Vitest 89개 파일·329개 테스트와 Node 스크립트 9개 테스트 통과. 복구 전 원문 저장 실패·목록 설정 저장 실패에 현재 입력과 완료 상태가 유지되고 재시도되는 경우를 포함한다.
- `npm run test:e2e -- workspace-followup`: 3개·실제 앱 재실행 1개 통과. 600px 너비 유지, 닫힌 패널 유지, 이동 후 내부 문서 복구, 재실행·800px 창에서 파일 선택 없이 ID·내용·버전 기록 복구 및 포커스 복귀를 확인했다.
- `npm run test:e2e -- workspace-panels`: 기존 정리·설정·패널 조작 5개와 재실행 1개 통과.
- `npm run test:e2e -- navigation`: 기존 문서 이동·저장 실패 2개와 재실행 1개 통과.
- `.artifacts/workspace-followup/completed.png`, `restored-narrow.png`로 넓은 창의 완료 목록과 좁은 창의 복구 결과를 확인했다. Impeccable layout 검사에는 결정적 경고가 없다.
- `npm run native:build`: 일반 앱 빌드 통과. E2E 검사 후 debug 실행 파일을 일반 앱으로 복원했다.
- Vite의 기존 메인 JavaScript 500 kB 초과 경고는 남아 있다. 이전 작업에서 변경 전에도 확인한 `layout.e2e.mjs:292`의 별도 승인 기대 실패는 이번 보완 범위에 포함하지 않았다.
