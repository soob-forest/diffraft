# 과거 생성 요청 재호출 호환성 보완

작성일: 2026-10-29

## Problem 1-Pager

- 배경: 모델 선택 전의 생성 요청 JSON에는 `model` 필드가 없다.
- 문제: 동일 ID 재호출에서 JSON 원문을 비교하여 `cli_default`가 추가된 동일 요청을 거부한다.
- 목표: 과거 요청의 기본 모델 해석을 적용해 동일 요청을 재사용하고 실제 내용 변경은 거부한다.
- 비목표: 재시도 정책, CLI 실행, UI, DB 스키마 변경.
- 제약: 저장 기록을 덮어쓰지 않고 손상된 기록은 거부한다. 실제 CLI·계정 없이 검증한다.

## ADR: 비교 방법

| 대안 | 장점 | 단점·위험 | 결정 |
| --- | --- | --- | --- |
| 마이그레이션에서 과거 JSON에 모델 삽입 | 문자열 비교 유지 | 저장 기록 변경과 추가 마이그레이션 필요 | 제외 |
| 저장 JSON을 요청 타입으로 읽고 같은 직렬화 방식으로 비교 | 기존 serde 기본값·검증 재사용, 저장 기록 보존 | 비교 시 역직렬화·직렬화 추가 | 채택 |

가정: 요청의 동일성은 JSON 공백·키 순서가 아닌 요청 필드 값으로 결정한다. 누락된 모델만 기존 계약에 따라 CLI 기본값으로 읽고 알 수 없는 모델·필드는 거부한다.

영향도: `begin_generation → replay`에서 저장 요청만 정규화한다. 새 요청 직렬화, 상태 검사, 문서 잠금, 완료 결과 재사용과 새 ID 재시도는 유지한다. 공통 타입에 비교 trait을 추가하거나 저장 데이터를 변경할 필요가 없다.

## 검증

- [x] 회귀 테스트에서 과거 RUNNING/SUCCEEDED 요청 재호출 실패를 먼저 확인한다.
- [x] 동일 요청 재호출, 완료 결과 재사용, 기록 보존을 검증한다.
- [x] 모델·지시·범위 변경, 손상 기록, FAILED/CANCELLED ID 재사용 거부를 검증한다.
- [x] 관련 Rust 워크플로와 포맷·정적 검사를 실행한다.

2026-10-29 결과: 신규 회귀 테스트 5개를 포함한 `cargo test --locked --features test-support --test workflow` 117개 통과. `npm run native:fmt`, `npm run native:check`(전체 타깃 Clippy, 경고 오류 처리), `git diff --check` 통과.

수정 전 과거 RUNNING/SUCCEEDED 재호출과 종료 상태 판별 테스트의 실패를 확인했다. 최초 손상 데이터 테스트의 비정상 JSON은 DB의 `json_valid` 제약에서 먼저 거부되어, 유효한 JSON이지만 잘못된 요청 타입인 사례로 정정했다. 완료 요청 테스트는 가짜 CLI로 결과를 만든 후 v6 형식으로 되돌려 재개방·마이그레이션하고, 실제 CLI 없이 저장된 결과가 반환되며 대화가 중복되지 않는지 확인한다.

변경은 Rust 저장 계층에 한정되어 UI/E2E·실계정 호출은 재실행하지 않았다. 이번 보완의 검증 결과는 앞선 모델 선택 기능 전체 검사 기록과 구분한다.
