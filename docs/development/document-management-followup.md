# 문서 목록 상태와 탐색 개선

## Problem 1-Pager

- 배경: 문서를 완료 목록으로 이동하고 복구할 수 있으나 완료 목록 자체를 정리할 수 없다.
- 문제: 체크 아이콘만으로는 완료 동작을 찾기 어렵다. 현재 문서의 목차·변경 탐색이 여러 문서를 관리하는 사이드바 아래에 있다.
- 목표: 일반 → 완료 → 목록에서 완전히 제거 상태를 제공하고 우클릭·더보기·키보드로 같은 동작에 접근한다. 탐색을 현재 문서의 보기 선택 옆으로 이동한다.
- 비목표: 원본 파일·작업 이력 삭제, AI 요청/승인 동작을 문서 메뉴에 추가, 전체 레이아웃 재설계.
- 제약: 기존 완료 설정과 문서 ID를 보존한다. 저장 실패 시 입력과 목록 상태를 유지한다. 메뉴는 화면 경계·키보드·800×600 창을 지원한다.

## ADR

- ‘완전 제거’는 문서 목록 양쪽에서 제거한다는 의미로 해석한다. 파일·작업 이력은 남기며 확인 창에 명시한다. 외부 파일을 다시 열면 기존 ID와 이력을 사용한다. 내부 문서는 파일 경로를 따로 열지 않으면 목록에서 복구할 수 없으므로 확인이 필요하다.
- 완료 ID와 제거 ID는 서로 겹치지 않는다. v2가 없을 때만 v1 완료 배열을 읽고 첫 변경에서 v2를 저장한다. 저장 성공 후에만 메모리 상태를 바꾼다.
- 모든 상태 변경은 기존 입력 저장과 navigation lock을 공유한다. 완료 문서만 완전 제거할 수 있다. 우클릭은 대상 문서를 열거나 선택하지 않는다.
- 메뉴 제공 동작: 일반 문서 열기·완료로 이동, 완료 문서 다시 열기·목록에서 완전히 제거. 파일 삭제·이름 변경 등은 이번 변경 범위에 포함하지 않는다.

## 영향도

`DocumentList` → `workspaceActions` → `useWorkspace` → 사이드바 행과 완료 목록을 변경한다. 원시 workspace snapshot과 저장소는 유지하고 목록 투영만 변경한다. `NavigationHosts`는 사이드바에서 문서 modebar로 이동하며 원문/검토 포털 호출은 유지한다.

## 화면 확인

- 읽기 순서: 넓은 창의 중앙 원문을 주 영역으로 유지했다. 왼쪽 문서명과 더보기는 같은 행이고, 현재 문서의 탐색은 보기 탭과 같은 묶음이다.
- 그룹·리듬: 문서 열기/생성과 목록 사이를 구분하고 완료 목록은 별도로 펼친다. 메뉴는 대상 제목 → 열기 → 상태 변경 순이며, 제거 확인은 제목 → 영향 → 취소/실행 순이다.
- 구조·밀도: 파일 목록에는 문서 관리만 두고 문서 내부 목차/변경 탐색은 중앙에서 필요할 때 펼친다. 항목이 길거나 많으면 자체 스크롤한다.
- 반응형·극단 상태: 1440×900의 메뉴·확인 창과 800×600의 목차·변경 목록을 실제 WKWebView 캡처로 확인했다. 처음 검출한 팝업의 왼쪽 넘침은 viewport 기준 위치 제한으로 수정했다. 기존 패널 검사는 680px 한 영역 전환도 포함한다.
- 키보드: Shift+F10 진입, 방향키, Escape 복귀, Tab으로 다음 컨트롤 이동을 검증했다. 확인 창은 취소에 초기 포커스를 두고 실패 시 오류·재시도를 유지한다. 단위 검토 진입 시 탐색이 자동으로 펼쳐져 본문을 가리지 않도록 했다.
- 결정적 레이아웃 검사: 수정한 화면 파일의 Impeccable `detect --json --scope layout` 결과 `[]`.
- 캡처: `apps/desktop/.artifacts/document-management/{right-click-wide,remove-write-failure,outline-compact,review-navigation-compact,reopened}.png` (합성 문서·격리 데이터).

## 검증

- 단위 회귀를 먼저 실패시킨 뒤 구현했다. 완료 → 제거 → 명시적 재개, v1 읽기 호환, 제거 상태의 우선순위, 잘못된 설정, 저장 실패 시 메모리 상태 유지, flush 실패·잠금과 메뉴 위치/키보드 경계를 포함한다.
- `npm run typecheck`, `npm run lint`, `git diff --check`: 통과.
- `npm run test:unit`: Vitest 90개 파일·337개 테스트, Node 스크립트 9개 테스트 통과.
- `npm run native:build:e2e`: 통과. 소스 식별자 `079d6c4408244a2d-e2e`. Rust·SQLite·IPC 계약 변경은 없다.
- `document-management`: 4개 + 재실행 1개 통과. 비활성 문서의 우클릭 대상 유지, 더보기·Shift+F10·방향키·Escape·Tab, 완료/다시 열기, 확인 취소, localStorage 쓰기 실패·재시도, 양쪽 목록 제거 유지, 같은 파일의 ID·내용·버전 복구, 800×600에서 목차/변경 선택을 확인했다.
- 기존 `workspace-panels` 6개, `workspace-followup` 4개, `navigation` 3개 통과. 실제 SQLite 잠금에 원문 저장이 실패하는 경우와 내부 문서 복구·너비·열림 상태 유지도 포함한다.
- 기존 `rewrite-review` 10개 + 재실행 2개 통과. 빈 필터·필터 밖 선택·코멘트 초안·부분 결정·비교 로딩 실패·늦은 응답·긴 제목·관련 범위·확대/작은 높이·재실행 복원을 확인했다. 더보기 버튼을 다른 문서로 잘못 고르던 검사 선택자를 문서명 버튼으로 한정했다.
- 자동화의 우클릭은 기존 선택 편집 검사처럼 `contextmenu` 이벤트와 기본 메뉴 차단을 검증한다. 임베디드 드라이버의 클릭은 OS 기본 우클릭 이벤트를 생성하지 않는다. 실제 한글 IME·VoiceOver 수동 인수는 이번 검증에 포함하지 않았다.
- Vite의 기존 메인 JavaScript 500 kB 초과 경고는 남아 있다. 의존성이나 코드 분할은 변경하지 않았다. 이전 작업에서 확인한 별도 `layout.e2e.mjs:292` 승인 기대 실패는 이번 범위 밖이다.
- 기존 `review` 6개와 `patch-groups` 6개 + 재실행 1개 통과. 변경 탐색·부분 결정·후보 수정·외부 충돌·그룹 전환·승인 경계를 포함한다. 이번에 실행한 관련 네이티브 E2E는 총 43개다. 의존 변경의 부분 승인 거부 오류는 실패 경로의 기대 결과이며, 드라이버의 stale/스크롤 재시도 안내 후 검사도 통과했다.
- `npm run native:build`: 통과. E2E 종료 후 debug 실행 파일을 일반 앱으로 복원했다. 이번 변경은 소스·일반 빌드까지 반영했으며 설치 앱 교체·커밋·push는 수행하지 않았다.
