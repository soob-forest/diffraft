영향도: R0는 Codex 전송 계층의 종료 상태와 테스트에 한정한다. 후속 변경은 공급자별 설정·요청·DB·세션·명령 분기와 UI를 연결한다. 기존 문서 승인·저장 경계를 공유하되 생성 결과 검증 이전의 데이터 변경은 허용하지 않는다.

## 3. 대안과 결정

### ADR-CODEX-004: 정리 실패 보존

| 대안 | 장점 | 단점·위험 | 결정 |
| --- | --- | --- | --- |
| 공통 `ProcessLease::release`를 빌림 방식으로 바꾸고 매번 재시도 | lease를 보유해 재시도 가능 | Claude 호출자까지 영향이 늘고, 프로세스 종료 확인과 lease 재시도 상태는 별도로 필요 | 이번 수정에서 보류 |
| `Peer`에 종료 확인 여부와 정리 결과를 보존 | Codex에 수정 범위를 한정하고 반복 호출 결과를 명확히 함 | 오류 상태와 Drop 정리 정책을 테스트해야 함 | 채택 |

종료 확인에 성공한 뒤 lease 해제가 실패한 경우 오류를 보관하고 후속 `close()`도 같은 오류를 반환한다. 같은 자식에 종료 신호를 반복하지 않는다. 종료 확인 자체가 실패한 경우 lease와 복구 정보를 유지하고, 소유권 확인·제한된 정리 시도 정책을 별도로 적용한다. 실패를 무조건 `closed=true`로 치환하지 않는다.

### ADR-CODEX-005: 사용자 목적까지 연결하는 방법

| 대안 | 장점 | 단점·위험 | 결정 |
| --- | --- | --- | --- |
| Claude 실행기를 범용 공급자 프레임워크로 전면 교체 | 공통 추상화를 일괄 정리 | 변경이 커지고 기존 저장·세션·취소 회귀 위험이 높음 | 제외 |
| 저장 요청을 기준으로 최소 공통 분기를 추가하고 Codex를 단계별 연결 | 기존 Claude 계약을 보존하며 작은 단위로 검증 | 이행 중 구·신 계약의 읽기 호환을 유지해야 함 | 채택 |

R0와 각 C 단계는 개별 리뷰 가능한 변경으로 나눈다. 각 변경 전에 관련 파일 전체와 정의·참조·호출자·테스트를 읽고, 영향도와 가정을 기록한다. 파일 300줄·함수 50줄·매개변수 5개·복잡도 10 이하를 유지한다.

## 4. 수행 순서와 변경 범위

순서: `R0 → C0 잔여 → C1 → C2 → C3 → C4 → C5`. C4는 누적 통합 검증 단계이며 각 단계의 테스트와 fixture는 구현과 함께 작성한다. 기존 TODO의 C 태스크를 재사용하고 추가 결함만 R0로 추적한다.

### R0. 프로세스 정리 결함 — 가장 먼저 수행

- 대상: `codex_adapter/transport.rs`, `tests/codex_transport.rs`와 필요한 종료 상태 테스트 모듈.
- fixture 준비 알림을 받은 뒤 임시 lease의 토큰만 다른 유효 값으로 바꾼다. 첫 close는 오류, 두 번째도 오류라는 테스트를 먼저 실패시킨다. 사용자 데이터·실제 인증은 사용하지 않는다.
- 종료 확인과 lease 해제 결과를 나눠 기록한다. 정상 정리만 반복 호출에서 성공을 반환하며, 실패 후 연결 I/O와 성공 상태 전환은 차단한다.
- 타 소유자의 기록을 삭제하거나 오류를 숨기지 않는다. 종료 확인 후에는 명시적 close·Drop에서 같은 프로세스에 신호를 반복하지 않는다.
- 정상 close 반복, 실패 반복, Drop, 취소·타임아웃, 자식 종료, lease 잔존 시 새 시작 차단, 재시작 복구를 검증한다. 종료 확인 실패 주입이 필요하면 테스트 경계에서 결정적으로 제어한다.
- 공통 lease API 변경이 필요해지면 `claude_adapter/guarded_process.rs`와 기존 프로세스·복구 테스트를 먼저 재검토하고 ADR의 범위를 갱신한다.

완료: 영구 회귀 테스트의 실패→수정→통과, Codex 및 기존 Claude 프로세스 회귀, 정적 검사를 기록한다. R0 완료만으로 Codex 사용 가능을 표시하지 않는다.

### C0 잔여. 실행·제한 계약 확정

- 설치 버전의 스키마와 공식 문서로 초기화·계정·페이지·thread·turn·구조화 출력·중단의 필수 기능을 정한다. 검증한 버전과 최소 지원 버전을 구분하고 필수 기능 누락은 구체적 오류로 처리한다.
- 기존 ChatGPT 인증을 재사용하는 환경·인자 생성 경계를 제품 코드로 정한다. 사용자 설정 변경·토큰 복사 없이 공급자·엔드포인트·계정 범위를 확인한다.
- 시작·설정 탐색 단계부터 훅·MCP 등 외부 실행 위험을 검토하고 제한 적용 전 의도하지 않은 실행이 없는지 확인한다. 제한을 입증할 수 없으면 근거와 대안을 기록한다.
- 제한 설정 검증, 실제 도구 제공 여부, 외부 부수효과 관측을 구분한 검증표를 만든다. 읽기 전용 설정이나 모델의 거절 문장만으로 범위 밖 읽기 차단을 통과 처리하지 않는다.

완료: C0-02~06 계약과 fixture 기준 확정. 실제 생성·도구 유도 입력의 최종 입증은 C5에서 별도로 수행한다.

### C1. 설정·요청·DB·세션 연결

- 대상: `domain/{model,connection,generation,regeneration,rewrite,conversation}.rs`, 설정 IPC, `storage/{job_model,generation_*}.rs`, 새 마이그레이션과 관련 테스트.
- 공급자·공급자별 마지막 모델·실행 경로를 저장한다. 신규 데이터는 Codex, 기존 데이터는 Claude를 유지한다. 손상·권한·동시 저장·재시작을 검증한다.
- 일반 생성·재제안·재작성에 공급자와 모델·effort를 고정한다. Codex 기본값은 확인 전에 목록에서 구체적 ID로 확정하고, 준비된 요청을 실행 시 전역 설정으로 덮어쓰지 않는다.
- schema 7 다음 마이그레이션에서 Claude 전용 CHECK와 세션 키를 확장한다. 과거 요청의 공급자 누락은 Claude, 모델 누락은 cli_default로 해석하며 실제 실행 모델 미상은 유지한다. 과거 저장 JSON 원문은 보존한다.
- 작업·공급자·계정/워크스페이스별 세션을 분리한다. 기존 Claude 세션을 임의의 Codex 계정에 연결하지 않는다. 계정 변경 시 기존 thread 재개를 차단한다.
- 동일 ID의 의미 비교·완료 결과 재사용·재시도 고정을 검증하고 Rust에서 TypeScript 계약을 재생성한다.

완료: C1-02~07. 설정 변경·재시작·설치/인증 실패에도 저장 요청이 보존되고 기존 DB 마이그레이션·실패 롤백과 읽기 호환 테스트가 통과한다.

### C2. Codex 실행과 모든 생성 경로 연결

- 대상: 새 Codex 진단·실행·이벤트 모듈, `commands/{connection,generation,regeneration,rewrite}.rs`, 최소 공통 실행 경계와 기존 결과 저장 경로.
- 계정·모델·실행 제한을 확인하고 저장된 공급자로 분기한다. Codex 선택 시 Claude 진단·프로세스가 호출되지 않는지 fixture가 검사한다.
- thread 시작/명시적 저장 ID 재개, turn 시작·완료·중단과 ID 상관관계를 처리한다. 알림을 버리는 진단용 `Peer::call`은 생성 이벤트 루프로 사용하지 않는다.
- 예상 밖 승인·도구 요청은 실행하지 않고 명확히 실패시킨다. 다른 thread/turn 이벤트·중복 완료·부분 JSON을 성공으로 처리하지 않는다.
- EXPLAIN·PATCH·재제안·REWRITE·다른 방향을 모두 연결한다. 완료 상태·출력 크기·스키마·문서 버전·범위 검증 뒤 원자적으로 결과를 저장한다.
- 연결 테스트와 실제 요청은 공급자·모델·경로·계정 범위를 고정한다. 취소/완료 경합, 종료·재시작 복구를 검증하고 자동 재시도·공급자 대체를 하지 않는다.

완료: C2-01~08. 가짜 App Server가 제품의 실제 실행 설정·요청값을 검사하고 모든 생성 모드의 성공·실패·중단을 검증한다.

### C3. Impeccable 기반 설정·요청 UI

- 설치된 Impeccable의 Operate·craft-floor와 기존 TO-BE를 기준으로 공급자 선택, 공급자별 모델·경로·인증과 다음 행동을 연결한다.
- 설정 선택·저장은 오프라인 동작으로 유지하고 모델 목록 조회·로그인·실제 테스트의 상태와 사용량 안내를 구분한다.
- 확인·진행·복구 화면에 고정된 요청 공급자/모델을 표시한다. 설정·계정 변경과 늦은 응답이 이전 테스트 성공을 재사용하지 못하게 한다.
- Claude 미설치·Codex 로그인됨·미로그인·모델 목록 실패·저장 실패·한도/정책 오류를 확인한다. 실제 캡처·키보드·포커스·두 창 크기와 세 배율로 리뷰한다.

완료: C3-01~06. 사용자가 Claude 없이 Codex를 설정하고 모든 요청 확인·실패 복구 경로를 조작할 수 있다.

### C4~C5. 통합·실사용·완료 판정

- C4: 별도 DB·가짜 App Server로 모든 생성 모드와 최소 한 개씩의 성공/실패 E2E를 제품 IPC 경로로 수행한다. 마이그레이션·재시도·공급자/계정 전환·중복·중단 경합·재시작도 포함한다.
- C5: 현재 ChatGPT 인증과 합성 문서로 앱에서 실제 연결·설명·수정·재제안·재작성·다른 방향·승인/저장을 수행한다. 생성만으로 원문이 바뀌지 않는지 확인한다.
- 도구 차단은 임시 표식 파일, 더미 실행 카운터, 로컬 수신기 등 통제된 자산과 프로토콜/도구 제공 상태로 관측한다. 개인 문서나 외부 서비스에 접근하도록 유도하지 않는다. 관측되지 않은 능력은 미검증으로 남긴다.
- 사용량을 소비하는 실제 호출은 C5 검증으로 기록하고 자동 CI에서 분리한다. 오류·시간·중단 결과는 본문·이메일·토큰·원문 오류 없이 기록한다.
- 자동 검사 → E2E용 빌드 → 관련 E2E 순차 실행 → 실제 계정 검증 → 일반 앱 빌드·테스트 코드 제외 확인 순으로 수행한다. Cargo/앱 빌드와 E2E는 동시에 실행하지 않는다.

완료: C4-01~07 및 C5-01~06의 증거가 있고 SPEC 11.5 인수 기준을 충족한다. 실제 계정 한도·정책으로 미실행한 항목이 있으면 지원 완료로 표시하지 않는다.

## 5. 필수 검증표

| 경계 | 통과 기준 |

R0는 `codex_transport`, 기존 Codex 계약 테스트와 `process`·`guarded_process`, `native:fmt`·`native:check`를 실행한다. 전체 연결 후에는 [TODO 기본 검사 명령](../../TODO.md)과 관련 E2E를 실행한다. 신규 Codex E2E 선택 이름은 실행기에 등록하고 테스트 안내에 기록한다.

각 변경 기록에는 태스크 ID, 변경 영향도, 실행 명령·결과, 재현/캡처 위치와 남은 미검증 항목을 남긴다. 이 문서 작성은 수정이나 검증 통과를 의미하지 않는다. 완료 체크의 원본은 TODO다. 실행 결과와 수정 중 발견·보완한 결함은 [구현 기록](codex-integration.md), 실제 화면·키보드는 [UI 리뷰](codex-ui-review.md)에 남겼다.
