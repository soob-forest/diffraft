# 문서 탐색 후속 수정

## Problem 1-Pager

- 배경: 문서 탐색을 중앙 보기 탭 옆으로 이동했다.
- 문제: 미리보기의 목차는 숨긴 원문 편집기만 이동시킨다. 작은 창에서 바깥 스크롤 후 fixed 탐색 팝업이 진입점과 떨어진다.
- 목표: 표시 중인 미리보기 제목으로 정확히 이동하고, 바깥 스크롤에는 팝업을 닫되 내부 목록 스크롤은 유지한다.
- 비목표: 원문/검토 이동 방식·문서 상태·파일·AI 요청 변경, 레이아웃 재설계.
- 제약: 기존 URL/HTML/이미지 안전 처리와 내보내기 미리보기를 유지한다. 중복 제목·BOM·CRLF·한글/emoji·잘못된 위치를 검증한다. 원문 선택을 미리보기 이동으로 바꾸지 않는다.

## 대안과 ADR

- 미리보기 대안 A — 원문으로 전환 후 이동: 기존 이동 재사용 / 읽던 보기가 바뀜 / 원치 않은 편집 진입 위험.
- 미리보기 대안 B — 렌더된 제목에 원문 UTF-16 위치 연결 (선택): 현재 보기·중복 제목 구분 유지 / 렌더 위치 연결 필요 / 대상 위치가 없으면 안내.
- 팝업 대안 A — 바깥 스크롤마다 위치 재계산: 팝업 유지 / 연속 배치 계산·조상 처리 필요 / 스크롤 중 본문을 가리는 위험.
- 팝업 대안 B — 바깥 스크롤 시 닫기 (선택): 기존 선택/문서 메뉴와 일관·작은 수정 / 다시 펼쳐야 함 / 내부 스크롤을 잘못 닫지 않도록 경계 검사 필요.
- 가정: 미리보기 목차 선택은 현재 미리보기를 유지하며 같은 제목을 반복 선택해도 다시 이동해야 한다. 제목 텍스트나 순번 대신 parser의 원문 위치를 사용한다. 원문과 미리보기 이동 요청은 분리하고 처리한 미리보기 요청은 소비한다.

## 호출 경로와 영향도

`Outline → EditingArea → Preview`에 미리보기 전용 이동을 연결한다. `SourceEditor`의 선택/이동은 그대로 두며 미리보기 이동을 전달하지 않는다. `Preview`는 내보내기에서도 사용되므로 이동 props는 선택 사항이다. `DocumentNavigation`의 캡처 단계 scroll 구독은 팝업 외부에서 발생한 경우에만 닫는다.

렌더 연결 대안은 제목별 React 컴포넌트를 만드는 방식과 HAST에 위치 메타데이터만 추가하는 방식을 비교했다. 전자는 제목 렌더링을 직접 제어하지만 컴포넌트 수명·포커스 재마운트 위험이 있다. 후자는 기본 제목 태그·서식을 유지하며 파서 위치만 연결하므로 선택했다. 위치 메타데이터에 선두 BOM 한 글자를 더해 Rust 원문 좌표와 맞춘다.

## 검증

- 수정 전에 새 SSR 위치 검사 1개와 네이티브 회귀 3개가 실패하는 것을 확인했다. 기존 리뷰 재현에서는 미리보기 scrollTop이 0, 화면 밖 제목 y가 3223px에 머물렀으며, 바깥 스크롤 80px 뒤 팝업 y는 그대로였다.
- `npm run typecheck`, `npm run lint`, `git diff --check`: 통과.
- `npm run test:unit`: 91개 파일·345개 테스트와 Node 스크립트 9개 테스트 통과. 기존 HTML/이미지/URL 보호, BOM 유무·CRLF·emoji·서식/중복/setext 제목의 원문 위치, 존재하지 않는 위치와 비정수/음수/무한대 입력을 포함한다.
- `npm run test:e2e -- document-navigation`: 새 회귀 3개 통과. 1440×900·800×600에서 동일 제목을 반복 선택해 실제 화면에 드러내며, 이후 원문에 입력해 커서·나머지 원문·BOM/CRLF가 보존되는지 검증한다. 렌더 대상 부재에는 안내하고, 내부 스크롤 유지·바깥 스크롤 닫힘·Escape를 확인한다.
- 기존 네이티브 `document-management` 5개, `export` 6개, `review`(PATCH 그룹 포함) 13개, `rewrite-review` 12개 통과. 새 검사를 포함한 관련 E2E는 39개다. 저장 실패·재실행·승인 경계·필터/초안·늦은 응답·작은 높이/확대 검사를 포함한다.
- 렌더 확인: `.artifacts/document-navigation/{preview-wide,preview-compact,missing-heading,outer-scroll-compact}.png`. 현재 보기와 기존 화면 구성을 유지하고, 선택한 제목에 기존 색의 가시적 포커스를 제공한다. 팝업이 사라진 후 본문 조작을 가리지 않는다. 오류 안내는 미리보기 안에서 읽을 수 있게 유지한다.
- Impeccable layout 검사 결과 `[]`. 기존 Vite 메인 청크 500 kB 초과 경고는 남아 있다. 부분 승인 거부는 E2E 실패 경로의 기대 결과이며 드라이버의 stale/스크롤 재시도 후 검사도 통과했다. 실제 한글 IME·VoiceOver 수동 인수는 수행하지 않았다.

오류 화면의 마지막 캡처에서 안내가 열린 팝업에 가려짐을 확인했다. 실패 시 안내에 포커스를 옮겨 기존 바깥 포커스 닫힘을 사용한다. 반복 실패에도 같은 동작을 보장하되 일반 문서 상태 갱신만으로 포커스를 다시 빼앗지 않도록 실패한 이동 요청을 상태로 보관한다. 이 경로도 팝업 닫힘·안내 포커스의 회귀가 먼저 실패하는 것을 확인했다.

오류 포커스 보완 후 단위 345개·스크립트 9개, 탐색 3개·내보내기 6개를 다시 통과했다. `npm run native:build`도 통과해 E2E 실행 파일을 일반 앱으로 복원했다. 소스와 빌드에 반영했으며 설치 앱 교체·커밋·push는 수행하지 않았다.
