# 사용성 개선 실행 기록

2026-10-28 이전 구현 이력. 당시 기준: [디자인 개선안](../design/design-guide.md#9-화면별-상세-개선안). VoiceOver 제외.

현재 작업은 [시안 이행 재구현 기록](design-reimplementation.md)을 따른다. 아래 요청 순서·하단 상세·640px 정책과 검사 개수는 이전 구현의 기록이며 새 구현의 완료 근거가 아니다.

## Problem 1-Pager

- 배경: 원문·조건은 저장되지만 요청과 코멘트는 화면 수명에 묶여 있다.
- 문제: 화면 왕복 입력 손실, 분산된 요청 범위와 승인 행동, 작은 창 탐색 부담.
- 목표: 세션 초안 보호와 기존 S00~S10 디자인의 사용성 개선을 실제 제품에 구현한다.
- 비목표: DB 변경, 재시작 초안 복원, 자동 AI 실행·승인, 새 디자인 체계.
- 제약: 기존 최신 버전 검증·단일 생성·명시적 승인·확정본 내보내기 유지.

## ADR-IMPL-001 · 세션 초안

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 모듈 전역 Map | 구현이 작음 | 앱 인스턴스·테스트 사이 상태 혼입 |
| App 소유 저장소와 Context | 문서 언마운트와 독립, 세션 격리 | 구독·비동기 응답 경계 필요 |

App 소유 저장소를 선택한다. 요청은 문서/작업 키, 코멘트는 문서/작업/묶음/제안/쪽 키에 작성 당시 revision·인용·범위를 함께 저장한다. revision을 바깥 키로만 쓰면 이전 초안을 발견할 수 없으므로 레코드 안의 검증 키로 보존한다. revision 또는 원문 인용 불일치는 명시적 재확인 전 저장하지 않는다. 늦은 저장 성공은 제출 당시 레코드와 일치할 때만 지운다.

가정: 앱을 닫기 전의 이동만 보호한다. 저장소는 파일·로그·localStorage로 내보내지 않는다.

영향: App → DocumentWorkspace → GenerationPanel/ReviewPanel의 입력 상태만 변경한다. 요청·코멘트 저장은 기존 IPC 경계와 검증을 통과하며 초안 변경은 부수효과를 만들지 않는다.

## 검증 기록

- 변경 전 typecheck/lint/build 통과, 단위 테스트 17파일 57개 통과.
- E2E 실행기는 시나리오별 임시 DB·가짜 CLI를 사용하며 재시작 단계만 같은 DB를 공유한다. 신규 usability 시나리오를 등록한다.

## ADR-IMPL-002 · 요청·조건·검토 배치

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 요청·검토 전용 단계 화면 | 진행 순서가 명확 | 반복 검토의 화면 왕복과 상태 전달 증가 |
| 기존 화면에 요청 우선·조건 접기·선택 도구 배치 | 기존 사용 방식과 저장 계약 유지 | 좁은 폭과 접힌 상태의 오류 표시 검증 필요 |

두 번째를 선택한다. 요청 → 조건 요약/편집 → 대화 순서로 배치한다. 조건을 대화 아래에 두면 이전 지시를 찾다가 현재 적용 조건을 놓칠 수 있어 순서를 보완했다. 조건 상태와 flush 소유권은 TaskPanel에 유지하고 표시 위치만 GenerationPanel의 children으로 전달한다.

영향: DocumentWorkspace → TaskPanel/GenerationPanel → 기존 조건 flush/요청 확인 경로. 저장 실패는 요약에 남고 이동·요청은 중단된다. 원문 선택 상태는 기존 useRequestScope 하나를 유지한다.

## ADR-IMPL-003 · 좁은 폭과 검토 탐색

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 모든 패널을 축소해 동시에 표시 | 화면 전환 없음 | 800px·확대 환경에서 본문과 입력 폭 부족 |
| 보조 패널 접기와 좁은 폭의 본문/작업 전환 | 핵심 내용에 폭 확보 | 이동 뒤 보이는 패널·포커스 동기화 필요 |

두 번째를 선택한다. CSS viewport 1000px 이하 진입 시 문서 목록을 접고, 950px 이하에서는 본문/작업을 교대로 표시한다. DOM을 유지해 입력·편집기 상태를 보존한다. 재작성 진입·제안 도착 시 좁은 폭에서는 본문을 표시한다. 두 열 합계가 640px 미만이면 인라인 전환을 제안한다(열당 약 320px, 기존 플랫폼 글꼴 기준). 자동 보기 전환으로 독자의 선택을 바꾸지 않는다.

변경 5개까지 번호 버튼을 유지하고 6개 이상은 선택 목록과 이전/다음을 제공한다. 전체 승인은 그룹 수·제안 수·줄 수를 따로 표시한다. 조정 가능한 범용 레이아웃 엔진 대신 해당 화면의 명시적 규칙을 사용한다.

영향: App/DocumentWorkspace CSS 표시, GroupBar 선택·포커스, DiffViewer 폭 안내만 변경한다. 승인·원문·코멘트 앵커 계산은 기존 계약을 사용한다. 9개 창/실제 배율에서 초안 보존·가로 넘침·주요 버튼 hit target을 검증했다. 읽기 편안함에 대한 사용자 관찰은 별도다.

## ADR-IMPL-004 · 상태 안내와 검증 경계

연결 오류로 모든 차단 사유를 요약하면 안내는 짧지만 프로세스 종료 확인 실패까지 오진한다. 기존 GenerationSnapshot.blocked 메시지를 그대로 텍스트로 표시하는 방식을 선택한다. 코멘트 초안 편집은 허용하되 검토 상태 잠금 중 제출은 버튼과 핸들러 양쪽에서 차단한다.

화면 검사는 CSS zoom만 바꾸는 방식과 실제 WebView 배율 변경을 비교했다. 후자를 선택하여 테스트 빌드에만 창 크기·확대·표시 권한을 부여했다. 제품 권한·Rust 로직·DB·IPC 계약은 변경하지 않았다. hidden 창의 검사를 강행하면 잘못된 배치 통과를 만들 수 있으므로 visible 선행 조건을 유지한다.

## 캡처·측정과 미검증 한계

[실제 전후 비교](../design/usability-actual.html)는 같은 합성 문서 v12/작업/1440×900/100%의 요청·검토·코멘트를 비교한다. AS-IS는 구현 전 손실 재현 때 확보했고 TO-BE는 21:17 KST의 최신 캡처다. 경로·포커스·스크롤 위치 차이는 공개한다. 원본 11개 디자인·6개 정적 제안은 보존한다.

실패·생성 중·대상 재확인·적용 전 비교·100개 변경과 3개 창 × 3개 실제 배율의 요청/검토 이미지를 연결했다. [실측 JSON](../design/usability-captures/measurements.json)의 가로 넘침 검사와 별도로 버튼 중앙의 실제 클릭 대상도 통과했다. 좁은 창의 구현 전 실제 이미지는 확보하지 않았으므로 재구성 출처를 유지한다.

최신 이미지들을 직접 확인했다. 비교 HTML의 로컬 자산 검사는 통과했지만 CUA 브라우저 목록이 비어 있어 이번 HTML 수정 후 브라우저 렌더링 재검사는 미실행이다. 이전 정적 제안의 6개 화면·확대·Esc 검증과 구분한다. 임시 HTTP 서버는 종료했다.

초기 손실 회귀 2개는 수정 전 실패·수정 후 통과를 확인했다. 이번 자동 표본에서 초안 손실·혼입·의도하지 않은 반영은 발견하지 않았지만 제품 전체 발생률이나 사용자 작업시간 개선율은 미측정이다. 실제 두벌식 IME·OS 파일 선택/저장/취소·5명 관찰·최소 사양 장치는 미검증이다. 자동 입력과 전문가 평가를 실제 사람 관찰로 계산하지 않는다.

## 2026-10-28 재개 · ADR-IMPL-005

창 표시가 정상화되어 usability 10개 중 7개가 통과했다. 코멘트 다음 단계는 details가 열린 상태이고 textarea도 활성인데 포커스가 버튼에 남는 것을 확인했다. 즉시 focus와 다음 렌더 프레임 focus를 비교했다. 전자는 WebKit의 펼침 레이아웃 전에 실행되어 실패하므로 후자를 선택한다. 프레임 시점에 연결·열림·활성을 다시 확인해 늦은 포커스가 사라진 폼에 적용되지 않게 한다. 영향은 CommentForm의 명시적 다음 행동만이며 AI 실행은 없다.

나머지 2건은 검사 준비 문제였다. WebDriver selectByAttribute 후 값이 whole로 남아 빈 선택 경로에 진입하지 않았고, 100개 fixture의 before에 줄바꿈을 포함하여 기존 의존 그룹 규칙상 하나로 결합됐다. 기존 테스트와 같은 change 이벤트로 범위를 선택하고, 독립 문장 fixture에서는 끝 줄바꿈을 제외한다. 제품 범위·그룹 안전성 규칙은 바꾸지 않는다.


## ADR-IMPL-006 · 비교 증거와 검사 기준

- 전후 화면을 새로 그리면 상태를 맞추기 쉽지만 실제 구현과 다른 이미지를 만들 위험이 있다. 기존 AS-IS 3장을 유지하고 최신 네이티브 캡처를 연결하는 방식을 선택했다. 코멘트는 입력이 보이는 위치로 스크롤하며 경로·포커스·스크롤 차이를 공개한다. 최초에 확보하지 않은 좁은 창 AS-IS를 실제 캡처인 것처럼 만들지 않는다.
- 구현 전 상태 목업을 별도로 유지하면 픽셀 시안 이력이 생기지만 구현과 중복된다. 구현 지시 이후에는 실제 실패·로딩·비활성·재확인·조건 저장 화면을 상태 명세와 연결한다. 기존 S 시안과 6개 제안은 그대로 보존한다.
- review 배치 검사는 보기 전환 버튼 클릭이 만든 스크롤 위치 때문에 sticky 승인 도구와 diff 상단 좌표를 비교해 실패했다. sticky를 제거하는 대안은 읽는 동안 승인 행동을 유지하는 목적을 잃는다. 초기 배치 검사는 scrollTop 0에서 수행하고, 스크롤 중 핵심 버튼은 별도 실제 hit target 검사로 확인한다. 제품 CSS·승인 계약은 변경하지 않았다.
- layout 스크롤 검사의 실패는 교체 행의 삭제 키 `delete:10:null`과 삽입 키 `insert:null:10`이 같아야 한다는 잘못된 조건이었다. 진단에서 양쪽 scrollTop 703·행 높이104·후속 문맥 좌표가 일치했다. 키를 강제로 같게 만드는 대신 동일 원문 문맥의 키와 세로 좌표를 대조한다. 보기 전환 후 원래 source key 보존 검사는 그대로 유지한다.
- 영향: 테스트의 캡처 시점·측정 기준과 비교 문서만 변경한다. 이미지 원본을 합성·보정하지 않는다. 캡처는 동작 검사를 보완하며 입력 보존·원문 불변의 증명을 대신하지 않는다.

## 남은 실제 입력·과업 검사 절차

자동화와 실제 사람 관찰은 구분한다. 아래 결과는 아직 미기록이며 통과로 계산하지 않는다.

| 대상 | 실행 절차 | 기록할 결과 |
| --- | --- | --- |
| 실제 한국어 IME | 일반 앱의 원문·요청·코멘트에서 두벌식 `한` 입력 직후 Backspace, 이어 쓰기·조합 중 삭제·저장·문서 왕복 | `하` 유지 여부, 글자 중복/손실, 조합 중 요청 차단 |
| 키보드·OS 창 | Tab으로 요청·패널·승인 이동, F7/Shift+F7 변경 왕복, Esc로 확인 취소, 실제 열기·저장·덮어쓰기 취소 | 포커스 위치·가시성, 취소 후 원문과 초안 불변 |
| 첫 사용 과업 | 초보/반복 사용자 합계 5명에게 합성 여행 문서와 “수치를 유지하며 문장을 다듬기” 목표 제공, UI 사용법은 설명하지 않음 | 첫 요청 성공, 범위 설명 정확도, 저장 범위 오해 |
| 검토·회복 과업 | 제안의 10분→5분 변경 거절, 코멘트 재제안, 문서 왕복 후 재개, 적용 전 비교와 복원 취소, 확정본 내보내기 | 의도하지 않은 반영·초안 손실·혼입 건수, 탐색 왕복, 재입력 문자 수 |
| 전후 비교 | 같은 합성 문서·과업을 동일 장치에서 순서를 교차해 수행 | UI 조작 시간과 AI 대기 시간 분리, 도움 요청 횟수, 실패 이유 |

참여자별 익명 ID·앱 버전·창 크기·배율·과업·성공/실패·UI 시간·AI 대기·재입력·왕복·메모만 기록한다. 실제 문서·요청·인증 원문을 수집하지 않는다. 참여자·최소 장치가 제공되지 않은 상태에서 개선율을 산출하지 않는다. VoiceOver는 제외한다.
