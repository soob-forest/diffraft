# UX 개선 현재 상태

2026-11-02 · DocReview 0.1.0 · 선택 팝오버·초안·전환 경계의 구현과 자동 회귀 검증 완료.

현재 동작은 [화면 계약](../design/ux-runtime-contract.md), 조작 방법은 [앱 사용법](../../README.md#앱-사용법), 실제 화면은 [합성 앱 캡처 19장](../usage/ux/README.md)을 따른다. [개선 제안서](../design/ux-improvement-proposal.md)와 정적 화면안은 설계 이력이다.

## 구현된 동작

- 원문과 diff에서 드래그를 마치면 선택 옆에 `이 부분 수정`이 표시된다. diff는 `코멘트`도 제공한다. 지시는 오른쪽에서 작성하고 인용·전달 문맥·모델을 확인한 뒤 명시적으로 실행한다.
- 후보 내부 선택은 새 미승인 revision, 원문 선택은 기존 제안을 보존하는 새 부분 묶음, 재작성 후보 선택은 새 전체 후보를 만든다. 승인 단위는 기존 규칙을 유지한다.
- 요청·선택 수정·코멘트·후보 수정 초안은 SQLite에 보관한다. 저장 실패·크기 초과·손상 기록의 복구를 구분하고, 원문과 diff의 마지막 작성 대상을 각각 복원한다. 현재 DB 스키마는 10이다.
- 저장 후 정확한 결과의 그룹·revision으로 복귀한다. 원문 요청 중 보기 왕복에도 실행 잠금·성공·실패 처리를 유지한다. 작업을 바꾸면 임시 작성창을 닫고, 이전 작업의 늦은 완료가 현재 화면을 바꾸지 않는다.
- 원문 편집 영향은 문서 전체 작업에서 집계한다. 과거 제안은 당시 기준의 읽기 전용 diff로 열며, 대화 결과는 원래 요청의 정확한 결과와 현재 상태를 연결한다.

## 남은 확인

- 실제 한국어 IME 조합·자모 삭제·조합 중 Esc와 VoiceOver 읽기·이동은 [수동 인수 절차](ux-native-validation.md)에 남아 있다. 자동 문자 입력·DOM/AX 검사를 완료 근거로 쓰지 않는다.
- 실제 작성자의 준비 시간·화면 전환·재입력·범위 이해는 아직 측정하지 않았다. 자동 E2E 소요 시간을 사용자 과업 시간으로 해석하지 않는다.
- 내부 서명을 확인했으며 공개 배포용 Apple 공증, 최소 사양 장치·새 macOS 사용자 환경 검증은 별도다. [설치 안내](../installation.md#지원-환경과-제한)를 따른다.

## 문서 정리 결정

배경: 여러 단계의 기록이 현재 상태 안내로 연결돼 설치본·검사 수를 혼동할 수 있었다. 목표는 현재 상태와 검증 한계를 한 진입점에서 확인하는 것이다. 기능 변경·과거 증거 삭제는 범위에 포함하지 않는다. 가정은 단계별 기록을 후속 회귀의 근거로 계속 사용한다는 것이다.

| 대안 | 장점 | 단점·위험 |
| --- | --- | --- |
| 기록을 한 문서로 합치고 이전 파일 제거 | 문서 수 감소 | 단계별 실패·검증 시점과 기존 링크를 잃음 |
| 현재 상태 안내와 단계별 기록 분리 | 현재 진입점 명확, 이전 증거 보존 | 후속 기능 변경 때 안내 갱신 필요 |

두 번째 안을 선택했다. README·목차·제품 명세·검사 안내는 이 문서로 연결하며, 단계 기록에는 체크포인트임을 표시한다. 선택 팝오버 계획은 저장소의 독립 문서로 읽을 수 있게 해 로컬 SPEC 개정 절에 의존하지 않는다.

커밋 검사에서 Codex 테스트 fixture가 302줄인 것을 확인했다. 목표는 300줄 제한을 지키면서 응답 계약을 보존하는 것이며 제품 동작 변경은 범위에 포함하지 않는다. 서버 상태와 순수 응답 생성을 분리할 수 있다고 가정한다. 빈 줄 축소는 변경이 작지만 책임 분리를 하지 못한다. 응답 생성 분리는 파일 하나가 늘지만 독립적인 계약 검사가 가능해 이 안을 선택했다. 영향은 가짜 CLI의 응답 생성과 테스트에 한정하며 제품 소스·설치 빌드 식별자는 바꾸지 않는다.
