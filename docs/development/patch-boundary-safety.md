# PATCH 부분 승인·미완성 fence 보완

작성: 2026-11-09 Asia/Seoul · 상태: 구현·전체 검사·네이티브 검증·일반 빌드 복원 완료

## Problem 1-Pager

| 항목 | 내용 |
| --- | --- |
| 배경 | PATCH 정책 v2는 독립 변경을 나누고 기존 미완성 코드블록의 일반 문구 교정을 허용한다. |
| 문제 | 여러 변경이 합쳐져야 생기는 구조를 놓쳐 부분 승인으로 새 미완성 fence가 저장된다. 기존 미완성 fence의 컨테이너 제거도 보존으로 오인한다. |
| 목표 | 복합 구조 변경을 함께 검토하고 실제 승인 결과의 새 미완성 fence를 저장 전에 거부한다. 기존 블록의 컨테이너·범위를 보존한다. |
| 비목표 | Markdown 전체 문법 검증, 의미 추론, REWRITE 변경, 이미 확정된 본문 자동 교정, 설치 앱·사용자 DB 교체. |
| 제약 | 원문 바이트·좌표·기존 결정·코멘트·저널 재생을 보존한다. 기존 문서 락·트랜잭션을 사용한다. |

## ADR-005: 복합 구조와 실제 승인 결과

| 대안 | 장점 | 단점 | 위험 |
| --- | --- | --- | --- |
| 원문에 변경 하나만 적용해 비교 | 기존 비용이 작다. | 조합으로 생기는 구조를 놓친다. | 그룹 일부 승인으로 구조가 깨진다. |
| 원문 단독 적용과 전체 후보에서 한 변경을 제외한 결과를 함께 비교 | 양쪽 문맥의 구조 기여를 식별한다. | 파싱 비용이 증가한다. | 중복 구분자처럼 단일 제외만으로 보이지 않는 조합은 남을 수 있다. |

두 번째 안을 선택한다. 모든 부분집합을 열거하는 지수 비용은 도입하지 않는다. 방어 경계로 신규 승인에서 실제 선택 결과를 같은 fence 규칙으로 검사한다. 이전 승인에 따른 좌표 이동을 반영하고 현재 head와 비교해 과거 확정본의 오류 때문에 무관한 새 교정을 거부하지 않는다. 검사는 임시 파일·저널 생성 전에 수행하며 재생·복구에는 추가하지 않는다.

가정: fence가 새로 미완성 상태가 되는 부분 승인은 허용하지 않는다. 부분 처리된 구형 묶음도 신규 승인에는 이 검사를 적용하되 과거 저널의 확정된 저장 의도는 재해석하지 않는다.

## ADR-006: 기존 미완성 fence 보존

| 대안 | 장점 | 단점 | 위험 |
| --- | --- | --- | --- |
| 여는 구분자 위치만 대응 | 일반 본문 교정을 쉽게 허용한다. | 컨테이너·끝 경계 확장을 구분하지 못한다. | 뒤의 본문이 코드로 편입된다. |
| 여는 경계·파서 조상 컨테이너·변경 후 끝 경계를 함께 대응 | 일반 교정과 구조 확장을 구분한다. | 경계 좌표 대응이 필요하다. | 경계와 겹친 큰 교체는 보수적으로 거부할 수 있다. |

두 번째 안을 선택한다. 본문이나 무관한 위치의 교정은 허용한다. 컨테이너를 바꾸거나 블록이 차지하는 범위를 확장한 미완성 fence는 새 구조 오류로 취급한다. BOM/CRLF·중첩 목록·인용·EOF 본문 교정을 회귀로 고정한다.

## ADR-007: 정책 v3

정책 번호 유지와 번호 증가를 비교했다. 유지는 저장 변경이 작지만 기존 v2의 잘못된 그룹이 그대로 남는다. v3 증가는 기존 준비 경계에서 전환할 수 있으나 오래된 결정·전환 롤백 검증이 필요하다. v3을 선택한다.

전부 미처리인 메타데이터 없음/v1/v2만 기존 명시적 준비에서 v3으로 전환한다. 일부 처리·과거 기록·미래 정책은 자동 변경하지 않는다. 새 스키마·IPC 필드는 추가하지 않는다.

## 호출 경로·영향

- 등록·부분 요청·후보 수정·재제안·준비 → `regroup_patch → plan → patch_structure / patch_fences`: 그룹 구성과 허용 범위만 변경한다.
- 신규 승인 → `accept_proposals → validate_patch_acceptance → reconstruct → write_record`: 실제 선택 결과 검증을 저널 앞에 추가한다.
- 복구 → `journal / review_effects`: 기존 재생 규칙을 유지한다.

영향: 정책 v3에서 복합 구조 변경만 결합되고 무관한 변경은 분리된다. v2 준비는 revision을 증가시켜 오래된 확인을 거부한다. 문서 락 안의 순수 검사라 추가 락·재시도·외부 I/O는 없다.

## ADR-008: E2E 창의 표시 좌표

전체 재작성 회귀에서 WebDriver가 `(24, 48)`로 이동시킨 창이 실제 macOS 관측에서는 `X=-1495`에 놓여 WebView가 숨겨졌다. 재실행도 시작 전 표시 검사에서 실패했다. 재시도만 반복하는 안은 코드 변경이 없지만 같은 화면 밖 좌표 문제가 남는다. Tauri의 주 모니터 원점과 명시적 물리 좌표를 사용하는 안은 테스트 도구 변경이 필요하지만 실제 대상 창을 화면 안에 배치할 수 있다. 두 번째 안을 선택한다.

소유한 E2E 창만 Tauri API로 배치한다. PID·실행 파일 확인·전면 활성화·문서 visibility·실제 프레임·hit 검사를 유지하며 가짜 visibility나 검사 생략은 사용하지 않는다. 제품 창 배치나 OS 디스플레이 설정은 변경하지 않는다. 테스트 도구 변경 후 관련 화면 회귀를 새 실행으로 다시 확인한다.

Tauri의 위치 이동은 기본 권한 밖이므로 E2E 설정의 `main` 창에만 `core:window:allow-set-position`을 추가한다. 일반 앱의 권한은 그대로다. 권한 추가 전의 명시적 거부 실행도 `boundary-e2e-review-position-permission.log`로 보존한다.
