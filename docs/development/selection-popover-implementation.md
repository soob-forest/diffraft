## 구현

- diff 선택 옆에 강조된 ‘이 부분 수정’과 보조 ‘코멘트’를 둔다. 문장·문단 확장은 더보기로 옮기고 상단 중복을 제거했다. 코멘트는 한 제안에 정확히 포함된 인용만 연결한다.
- 원문에도 같은 선택 팝오버를 제공한다. 선택만으로 일반 요청 범위·작성 대상·포커스를 바꾸지 않는다. 원문 선택 요청은 기존 제안을 보존하는 confirmed 경로로 새 미승인 묶음을 만든다.
- 작성 대상은 묶음 ID 없이 식별한다. 구형 confirmed 초안은 원본 키로 호환 조회하며 여러 지시는 사용자가 고른다. 후보·재작성 키와 CAS·손상 격리 정책은 유지한다.
- 작업이 없으면 같은 인용으로 목표·첫 지시를 작성하고 작업 하나를 명시 생성한다. 소유 작업이 없는 입력은 임시 상태임을 안내한다. 생성 취소·재진입·중복 클릭과 원문 변경을 처리한다.
- 겹치는 제안은 다른 작업까지 조회해 해당 작업의 현재 검토로 명시 이동한다. 이동 전 초안 저장을 완료하며 실패하면 작성 화면을 유지한다. 과거 대화의 결과 링크는 계속 읽기 전용 이력을 연다.
- 확인 단계에서는 입력 폼을 접고 실제 인용·대상 버전/revision·지시·준비된 모델·전달 문맥·기존 제안 영향과 최종 요청을 표시한다. 취소하면 지시로 돌아간다.
- 새 후보의 revision·미승인 상태와 이전 후보 비교·재요청·별도 승인 경로를 표시한다. 임의 드래그의 문자 수는 grapheme 기준이며 문장 수로 추정하지 않는다.
- 팝오버는 실제 크기를 측정해 편집기/창 경계 안에 배치하고 아래 공간이 부족하면 선택 행 위로 옮긴다. 입력·조합 시작·선택 해제·Esc·보기 전환·바깥 스크롤에 닫는다. 키보드 포커스는 자동 스크롤을 막고 이동한다.
- 낮은 높이의 원문 화면은 최소 편집 공간과 세로 스크롤을 사용한다. 큰 헤더 때문에 본문 높이가 0이 되는 상태를 방지했다.
- 앱 이름에서 빌드 ID·빌드 종류·시간대를 포함한 시각을 확인한다. 제품 소스 내용 해시와 실행 파일 해시는 별도 manifest에 기록한다.

## 검증

| 검사 | 결과 |
| --- | --- |
| TypeScript·실행기 단위 | 158개(TypeScript 149, Node 9) 통과 |
| Rust | 333개 통과, 실계정 등 명시 실행 30개 ignored |
| Rust fmt·clippy·생성 계약 | 통과 |
| 신규 native | 성공/실패·다른 작업 겹침·첫 작업·오래된 원문·프로세스 재시작과 팝오버 배율 검사 통과 |
| 관련 native | 19단계·64건 통과: 팝오버 9, UX 17, 복구 6, 사용성 10, 종료 4, 모델 5, Codex 13 |
| 최종 표시 보완 뒤 native | UX 5단계·17건 + 팝오버 3단계·9건 통과. 같은 최종 소스에서 로컬 키보드/화면 7건 추가 반복 통과 |
| 팝오버 화면 | 원문 9개·diff 9개 조합에서 경계·버튼 hit target·선택 강조의 가시성 검사 |
| 실제 IME·VoiceOver·작성자 평가 | 미완료. 자동 문자 삽입·AX/DOM 검사로 대신 집계하지 않음 |

자동 검사는 실제 계정 대신 가짜 Claude/Codex와 소유한 임시 DB를 사용한다. 최종 확인 전 AI 호출, 승인 전 확정 파일 변경, 선택 밖/다른 제안 손실을 별도로 검사한다. `selection_migration.rs`는 스키마 8/9→10, 기존 작업·원문·초안 보존, 마이그레이션 실패 롤백과 백업 재개방을 검사한다.

## 발견하고 수정한 경계

1. CodeMirror 갱신 중 좌표를 측정하면 플러그인이 중단됐다. 측정을 갱신 뒤로 미뤘다.
2. 작성 패널이 성공 후 사라지면 상위 busy가 남을 수 있었다. 상위 상태는 항상 해제하고 컴포넌트 내부 갱신만 mount 상태를 검사한다.
3. 작업을 바꿔 겹치는 검토를 열 때 초안의 지연 저장이 아직 남았다. 이동 전 flush와 실패 시 현재 작성 유지로 보완했다.
4. 고정 버튼 제거 후 일반 ‘범위 확인’이 인용을 영속 고정하지 못했다. 검증된 원문 선택 스냅샷을 저장하도록 연결했다.
5. 팝오버 경계만 통과해도 확대 시 본문이 보이지 않는 경우가 있었다. 최소 읽기 공간과 선택 중앙 hit target 검사를 추가했다.
6. 팝오버의 키보드 포커스와 자동 스크롤이 닫기 동작과 경합했다. `preventScroll` 적용 후 키보드·직접 수정·9개 배율의 로컬 native 7건을 3회 연속 통과했다.
7. 최종 화면 대조에서 완료 뒤 이전 선택 안내가 남았다. 상단의 임시 선택 안내를 남은 그룹이 있을 때만 표시한다. 새 회귀 assertion의 실패를 먼저 확인하고 UX 17건·팝오버 9건·로컬 7건 재검증과 완료 PNG 대조를 통과했다.

초기 테스트가 다른 행을 선택하거나 내장 드라이버가 HTML 버튼의 Enter 기본 동작을 실행하지 않는 경우는 제품 결함과 분리했다. 인용을 정확히 비교하고 일반 release의 OS 입력을 별도로 확인한다. 작은 범위의 수정·리뷰·리팩터링 뒤 관련 검사를 재실행했다.

완료 안내의 실패 재현 실행에서는 첫 키보드 포커스 대기도 한 차례 시간 초과했다. 이 실행을 통과로 집계하지 않았다. 최종 소스의 전체 UX와 별도 로컬 반복은 모두 통과했으며, 일반 release의 OS 키 입력도 확인했다. 해당 시간 초과의 단독 원인은 확정하지 않았으므로 실제 입력 수동 인수에서 빠른 선택·단축키를 다시 확인한다.

64건의 관련 회귀는 `2a031217c61cb306-e2e`에서 수행했다. 이후 AppHeader 책임 분리와 완료 안내 표시 조건을 변경했고, 최종 `c6c5fd71c91c0f6f-e2e`에서 위 26건과 반복 7건을 통과했다. 이 차이를 숨기고 64건 모두를 최종 바이너리 검사로 표기하지 않는다. [화면 출처 manifest](../usage/ux/manifest.json)는 최종 소스의 합성 캡처만 포함한다.

## 일반 앱 반영 경계

일반 release는 `--verification-workspace`로 명시한 사용자 소유 0700 임시 폴더에서 먼저 확인한다. 절대 경로·실제 임시 폴더 하위·고정 마커·소유권·심볼릭 링크를 검사하고 잘못된 인자에는 사용자 DB로 폴백하지 않는다. 일반 앱에는 가짜 공급자·E2E IPC를 포함하지 않는다.

기존 실행 앱은 저장 상태를 확인해 정상 종료했다. 스키마 8의 사용자 DB는 별도 0600 백업으로 보관하고 integrity check를 통과했다. 이전 앱 번들도 되돌릴 수 있도록 별도 보관했다. 새 DB를 오래된 앱으로 여는 다운그레이드는 하지 않았다.

실제 사용자 문서로 생성·승인 검사는 하지 않았다. 앱은 갱신된 설치 경로에서 저장된 원문 화면으로 열어 두었다. 빌드 경고 중 Apple 공증은 자격 환경이 없어 생략됐으며, 내부용 ad-hoc 서명 검증만 통과했다. 공개 배포용 공증 완료를 의미하지 않는다.

## 남은 수동 인수

[실제 IME·VoiceOver 절차](ux-native-validation.md)와 실제 작성자의 준비 시간·전환·재입력·범위 이해 평가는 계속 미완료다. 추가 HTML 화면 페이지의 브라우저 직접 미리보기는 로컬 파일 URL 정책으로 차단됐다. 삽입한 실제 앱 합성 PNG는 별도로 열어 기존 시안과 대조했으며 픽셀 완전 일치를 주장하지 않는다. T22와 기존 T16의 수동 인수를 남겨 두고 구현·자동 회귀·설치 반영과 구분했다.
