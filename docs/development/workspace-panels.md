# 작업 공간 패널과 완료 문서 정리

## Problem 1-Pager

- 배경: 왼쪽 문서 탐색, 중앙 편집, 오른쪽 AI 요청·상세를 함께 사용한다.
- 문제: 완료 문서를 목록에서 제거할 수 없고, AI 연결 설정이 문서 탐색에 섞여 있으며 보조 영역의 크기가 고정되어 있다.
- 목표: 완료 문서의 목록 제거·복구, 상단 설정 진입, 패널 닫기·다시 열기 및 크기 조절을 제공한다.
- 비목표: 원본 파일·검토 기록 삭제, 분리된 OS 창, 편집·AI 요청 계약 변경.
- 제약: 원문·조건·초안 저장에 실패하면 문서 제거를 중단한다. 기존 좁은 화면의 단일 본문 전환과 접근성·포커스 복귀를 유지한다.

## ADR: 제거 의미와 레이아웃

- 가정: ‘작업 완료한 부분 제거’는 왼쪽 문서 목록 정리이며, 문서 파일과 작업 이력의 영구 삭제를 뜻하지 않는다. 각 창은 현재 화면의 문서·요청·버전 기록 패널을 뜻한다.
- 대안 A — 문서·이력 영구 삭제: 저장 공간까지 정리 가능 / 복구 불가와 미승인 작업 손실 위험 / 요구 범위를 넘어 제외.
- 대안 B — 목록에서 제거하고 다시 열기: 파일·작업·초안 보존 / 별도 목록 상태 필요 / 가장 작은 안전한 동작으로 선택.
- 대안 A — 범용 도킹 라이브러리: 자유로운 배치 / 의존성·포커스·스크롤 복잡도 증가 / 제외.
- 대안 B — 기존 그리드와 크기 조절 경계: 기존 편집·검토 흐름 유지 / 독립 OS 창 이동 불가 / 선택.
- 목록 저장 대안 A — SQLite 테이블: 앱 데이터 백업에 포함 / 스키마·IPC·과거 마이그레이션 검증 변경 필요 / 제외. 대안 B — localStorage의 문서 ID 목록: 문서 저장 계약 유지 / 웹뷰 설정 초기화 시 목록 정리 초기화 / UI 선호 설정으로 선택.
- 너비는 현재 작업 공간에서 유지한다. 화면이 좁아지면 표시 너비만 제한하고 사용자의 넓은 화면 설정은 유지한다. 버전 기록은 기존 펼치기·접기를 유지하며 펼친 높이를 조절한다.

## 호출 경로와 영향도

- 문서 목록: `App → useWorkspace → editorCommand → commands::editor → Store`를 따른다. 제거 전에 현재 원문·조건·모든 초안을 저장하고 동일한 이동 잠금으로 중복 실행을 막는다.
- 제거된 문서 ID만 버전이 있는 localStorage 설정으로 저장하고, workspace snapshot을 화면에 반영하기 전에 필터링한다. UI 선호 설정이므로 SQLite 마이그레이션·IPC 변경 없이 구현한다. 원본·버전·작업·선택·초안은 보존하고 파일을 다시 열거나 제거 직후 복구하면 같은 문서 ID로 돌아온다. OS의 웹뷰 데이터 초기화·다른 Mac으로 이동 시 목록 정리는 초기화될 수 있다.
- 레이아웃: `App → DocumentWorkspace → WorkspacePanels`의 기존 마운트를 유지해 패널 닫기와 크기 조절이 입력을 지우지 않도록 한다. 중앙 본문 너비는 양옆 패널 변경에 따라 조절된다.
- AI 설정은 기존 모달과 요청 내부의 `AI 변경`을 재사용하며 공급자·인증·생성 동작은 바꾸지 않는다.

## 검증

- `npm run typecheck`, `npm run lint`: 통과.
- `npm run test:unit`: Vitest 89개 파일·327개 테스트와 Node 스크립트 9개 테스트 통과. 목록 저장 실패·잘못된 형식·재시작 필터·복구, 제거 전 flush 실패, 중복 실행 잠금, 마지막/비활성 문서 제거 및 키보드 경계를 포함한다.
- `npm run native:build:e2e`: 통과. Rust·IPC·SQLite 스키마는 변경하지 않았다.
- `npm run test:e2e -- workspace-panels`: 실제 WKWebView·Rust IPC에서 5개 성공, 실제 앱 종료·재실행 후 1개 성공. 설정 포커스 복귀, 드래그·키보드 너비 변경, 닫기·열기 시 너비 유지, 1440/800/680 CSS px, SQLite 잠금으로 인한 원문 저장 실패·재시도, 즉시 복구·원본 보존·동일 문서 재개를 확인했다. 높이 조절 후 버전 기록 접기에 남는 inline 높이를 회귀 테스트로 먼저 검출했고, 접을 때 높이를 해제해 수정했다.
- 렌더 확인: `.artifacts/workspace-panels/{wide,compact,single-pane,reopened}.png`. 큰 창은 편집을 중심으로 양옆 보조 영역을 유지하고, 좁은 창은 문서 목록 오버레이와 본문·요청 전환을 사용한다. 설정은 항상 상단 오른쪽에 있고 좁은 창에서는 톱니바퀴로 표시한다.
- Impeccable layout 검사: 변경 화면의 결정적 경고 없음. Vite 빌드는 통과하지만 메인 JavaScript 청크의 500 kB 초과 경고가 남아 있다. 의존성·코드 분할 변경은 이번 작업에 포함하지 않았다.
- 기존 문서 이동 검사 `npm run test:e2e -- navigation`: 이동 2개·재실행 1개 통과. 처음 실행에서 손잡이의 바깥 4px로 인한 가로 넘침을 검출했고 안쪽 배치로 수정했다.
- 기존 비교 검사 `npm run test:e2e -- layout`: 줄 정렬·스크롤·150% 확대 3개 통과, 마지막 ‘결합된 변경’ 승인 기대 1개 실패. 변경 전 커밋 `7c6f7a2`의 제품 소스를 별도 임시 폴더에서 빌드해도 같은 `layout.e2e.mjs:292`에서 3개 통과·1개 실패했다. 현재 결과는 두 변경 중 코드 변경만 승인되지만 테스트는 두 변경 모두 적용을 기대한다. 이번 패널 변경과 분리된 기존 실패로 남겼다. 근거: `.artifacts/workspace-panels/baseline-layout.log`.
