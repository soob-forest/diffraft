# 선택 팝오버와 제안 화면 정합화 작업 계획

2026-11-02 · 상태: T17~T21·T23~T24 구현·검증·설치 반영 · T22 실제 입력 수동 인수 대기

선택 팝오버 보완의 독립 실행 계획이다. [개선 제안서](../design/ux-improvement-proposal.md)와 [화면 1~9](../design/ux-proposal/index.html)의 행동 위치·정보 위계·문구를 기준으로 한다. 전체 수행 현황은 [UX 개선 현재 상태](ux-status.md), 이 계획의 구현 결과는 [실행 기록](selection-popover-implementation.md), 차이와 예외는 [시안 대조](selection-popover-audit.md), 실제 화면은 [합성 캡처](../usage/ux/README.md)를 따른다.

## 1. Problem 1-Pager

| 항목 | 정의 |
| --- | --- |
| 배경 | 사용자는 원문과 diff를 읽는 위치에서 일부 문장·문단에 수정 요청을 시작하려 한다. |
| 문제 | 개발 빌드의 팝오버는 시안과 행동 구성·강조가 다르고 상단에 버튼이 중복된다. 원문은 고정 버튼에서 일반 생성으로 연결된다. 사용 중인 release 앱과 검증한 개발 빌드도 다르다. |
| 목표 | diff는 선택 옆의 ‘이 부분 수정 / 코멘트’, 원문은 선택 옆의 ‘이 부분 수정’으로 시작한다. 오른쪽에서 인용·지시·문맥을 확인하고 기존 제안을 보존하는 새 부분 제안을 만든다. 시안 대조와 실제 실행본 확인을 완료 조건에 포함한다. |
| 비목표 | 팝오버 안의 장문 입력, 자동 AI 실행·승인·범위 확대, 원문 코멘트 신설, 문장별 승인 단위 신설, 전체 테마 개편. |
| 제약 | 확정본 불변, 정확한 좌표·인용·head 검증, 단일 생성, 초안 CAS·손상 기록 격리, 기존 일반 생성·재작성의 명시적 보관 정책을 유지한다. |

가정: ‘이 부분 수정’은 선택 범위 밖과 기존 미승인 제안을 유지하려는 의도다. 기존 제안을 기록으로 옮기는 일반 생성은 별도 요청 폼에서 명시적으로 선택한다. 기능 통과·시안 일치·사용 앱 갱신을 각각 판정한다.

영향: 선택 이벤트·팝오버 표시·작성 패널 진입, 확정본 선택 대상과 초안 식별·복구, 원문 요청 라우팅을 변경한다. 일반 요청의 기본 의미와 승인 시 다른 묶음이 STALE이 되는 기존 규칙은 유지한다. 본문·지시·인용은 진단 로그에 남기지 않는다.

## 2. 확인한 차이와 대안

2026-11-02 확인 시 실행 앱은 11월 1일 release 번들이었고 최근 보완은 debug 빌드에 있었다. 개발 빌드에도 선택 옆 팝오버는 있지만 ‘이 문장 선택 / 이 문단 선택 / 이 부분 수정’이 같은 위계로 표시되고 상단 도구에 중복된다. 시안은 ‘이 부분 수정’을 강조하고 ‘코멘트’를 보조 행동으로 둔다.

| 결정 | 대안 A: 장점 / 단점·위험 | 대안 B: 장점 / 단점·위험 | 선택 |
| --- | --- | --- | --- |
| 지시 입력 | 작은 행동 팝오버 → 오른쪽 작성: 기존 패널 재사용 / 시선 이동 필요 | 팝오버 안 입력: 대상과 가까움 / 장문·IME·가림·확대 처리 복잡 | A |
| 발견 방식 | 드래그 완료 후 표시: 발견 쉬움 / 복사용 선택에도 노출 | 우클릭만 표시: 방해 적음 / 발견 어려움 | A를 기본으로 하고 우클릭·키보드도 제공 |
| 원문 실행 | 일반 생성 재사용: 연결 작음 / 다른 제안이 보관될 수 있음 | 확정본 선택 요청: 기존 제안 보존 / 대상·초안 연결 추가 필요 | B |
| 문장·문단 확장 | 주 행동과 나란히: 노출 쉬움 / 핵심 행동 분산 | 보조 메뉴: 선택 요청에 집중 / 추가 조작 필요 | B. 범위는 실행 전에 표시 |
| 시안 차이 처리 | 문서를 구현에 맞춤: 작업 작음 / 설계 목적을 놓칠 수 있음 | 시안별 차이표로 구현 조정: 검토 가능 / 상태별 대조 필요 | B. 의도적 예외는 이유와 인수 기준 기록 |

## 3. 화면·상호작용 계약

| 위치 | 팝오버 | 클릭 뒤 |
| --- | --- | --- |
| diff의 유효한 제안 선택 | 강조된 ‘이 부분 수정’ + 보조 ‘코멘트’ | 각각 선택 수정 작성 / 선택 인용의 코멘트 작성 |
| 원문 편집기의 연속 선택 | 강조된 ‘이 부분 수정’ | 원문 선택을 고정하고 오른쪽 작성 열기 |
| 범위 확장 | 보조 메뉴의 ‘이 문장 선택 / 이 문단 선택’ | 확대된 실제 범위를 먼저 선택하며 AI는 실행하지 않음 |

원문 흐름: **드래그 → 선택 옆 ‘이 부분 수정’ → 오른쪽 인용·지시 → 요청 내용 확인 → 확인 후 요청 → 새 미승인 제안 검토**.

- 팝오버는 전체 화면 모달이 아니다. 마우스 드래그 완료 후 비어 있지 않은 연속 선택에만 표시한다. 키보드 선택은 진입 단축키로 열 수 있다. 선택만으로 요청 범위·작성 대상·포커스를 바꾸지 않는다.
- 본문·선택을 가리지 않는 가까운 위치에 표시하고 패널 경계·창 가장자리에서 위치를 보정한다. 상단에 같은 행동을 반복 표시하지 않는다. 문장·문단 확장과 보조 진입은 키보드로 접근 가능하게 유지한다.
- 입력·IME 조합 시작·선택 해제·Esc·화면 전환·스크롤에는 떠 있는 팝오버를 닫는다. 닫힌 뒤에도 유효한 선택은 우클릭·단축키로 다시 열 수 있다. 원문 기본 복사·잘라내기·붙여넣기와 OS 단축키를 보존한다.
- ‘이 부분 수정’을 누르면 인용·문서·작업·기준을 고정하고 작성 패널에 포커스를 옮긴다. 원문의 선택 강조는 패널 이동 후에도 유지한다. 변경된 편집 버퍼나 다른 문서에 예전 위치를 강조하지 않는다.
- 작성 패널 공통 제목은 ‘선택한 부분 수정’으로 하고 대상에 ‘원문 · vN’ 또는 ‘제안 내용 · rN’을 표시한다. 정확한 인용·범위·적용 단위를 지시보다 먼저 보여준다.
- ‘선택한 N문장’은 경계를 확실히 판정할 때만 쓴다. 임의 드래그는 선택 문자 수와 인용을 표시하며 문장·문단 개수를 추정하지 않는다.
- ‘요청 내용 확인’에는 수정 허용 범위와 실제 전달 문맥·선택한 코멘트·모델·사용량·기존 제안에 미치는 영향을 구분한다. 확정본 유지와 별도 승인 원칙을 표시한다.
- 다른 선택을 복사하는 동안 작성 대상을 바꾸지 않는다. 새 팝오버의 수정 행동을 눌렀을 때 기존 대상 초안 보관·대상 변경을 선택하게 한다. 취소하면 기존 지시·대상을 유지한다.
- 작업이 없으면 선택을 유지한 채 작업 생성과 첫 지시로 이어간다. 유효한 작업 ID가 생기기 전에는 잘못된 소유 키로 영속 저장하지 않는다. 저장 전 상태를 구분하고 작업 생성 취소·실패·중복 클릭을 처리한다.
- 원문 저장·head·인용 검증 실패에는 AI를 실행하지 않고 지시를 보존한다. 원문 내용이 바뀌면 새 대상을 확인하며 문자열 검색으로 임의 재연결하지 않는다.
- 미승인 제안과 겹치면 해당 검토를 여는 명시적 행동을 제공한다. before 선택을 after 좌표로 임의 변환하지 않는다. 여러 대상이 겹치면 사용자가 선택하도록 안내한다.
- 새 원문 부분 제안 생성은 기존 제안·결정·코멘트를 보존한다. 이후 승인으로 다른 묶음의 기준이 바뀌는 영향은 확인 영역에 표시한다. 생성 시 보존과 승인 후 유효성을 구분한다.
- 성공 후 해당 결과를 열고 새 미승인 상태·이전 후보 비교·다시 다듬기·승인 경로를 제공한다. Esc·돌아가기는 원래 편집기의 선택·스크롤·포커스를 복원한다.

프런트는 `apps/desktop/src/`, Rust는 `apps/desktop/src-tauri/src/` 기준이다. 공통화는 diff·원문의 표시/닫기/위치 보정처럼 의미가 같은 부분만 한다. 편집 가능 원문과 읽기 전용 diff의 이벤트·좌표 처리를 억지로 하나로 묶지 않는다.

착수 시 backend는 기존 제안을 보존하는 확정본 선택 경로를 갖지만 프런트 confirmed 대상은 `batchId`를 요구했다. 구현 후에는 묶음 없는 canonical 대상과 구형 키 호환 조회를 사용한다. **가짜 묶음 ID를 만들거나 임의의 활성 묶음을 연결하지 않는다.**

원문·diff에서 같은 확정본 선택을 가리킬 때는 문서·작업·head·범위·인용으로 같은 대상을 식별한다. UI 진입 위치는 복귀 정보로 분리한다. 기존 confirmed 초안의 묶음 포함 키와 새 식별 방식의 중복·충돌을 먼저 설계한다. 충돌 시 한 지시를 임의로 지우지 않으며, 변경된 키·active 인덱스·decode·실패 복구를 함께 호환시킨다. DB 스키마 변경은 필요성을 입증한 경우에만 별도 작업으로 한다.

## 5. 실행 단계와 완료 조건

### T17. 시안 차이표와 기준 문구 고정 — P1

- [x] 9개 시안과 실제 개발 빌드를 같은 상태·창 크기로 대조한다. 문구·버튼 위계·표시 위치·진입/닫기·완료 행동을 별도 열로 기록한다. 버전·문서·건수 등 합성 데이터 차이는 분리한다.
- [x] 화면 1~4의 팝오버·범위/문맥·새 후보/실패, 화면 5의 원문 부분 수정, 화면 6~9의 영향·이력·완료·요청 종류까지 추적한다. 새 원문 흐름의 화면안을 추가하고 원래 시안을 단순히 현재 구현으로 덮지 않는다.
- [x] 기준 문구표를 고정한다. 공통 ‘이 부분 수정’, diff ‘코멘트’, ‘요청 내용 확인 / 확인 후 요청’, ‘선택한 부분 수정’과 대상 배지를 사용한다. 화면 9의 ‘부분 수정 / 설명 / 전체 재작성’을 적용하되 일반 요청의 보관 영향은 숨기지 않는다.
- 완료: 모든 차이가 수정 작업 또는 구체적 이유가 있는 예외에 연결된다. 단위 통과를 시안 일치로 표기하지 않는다.

### T18. diff 팝오버 정합화 — P1 · 선행 T17

- [x] 선택 옆 주 행동 ‘이 부분 수정’과 보조 ‘코멘트’를 시안 위계로 배치한다. 코멘트는 선택 쪽·인용을 현재 코멘트 작성 경로로 전달한다.
- [x] 문장·문단 확장을 보조 메뉴로 옮기고 상단의 중복 행동을 제거한다. 잘못된 혼합 선택·과거 기록·변경 전 인용은 이유와 유효한 다음 행동을 제공한다.
- [x] 드래그 중 조기 표시, 클릭 직전 소실, 버튼 아래 선택 붕괴, 스크롤·팝오버 내부 스크롤 경합을 회귀 검사한다. 선택 완료까지 입력 포커스를 유지한다.
- 완료: 인라인·나란히에서 두 행동이 같은 인용으로 연결되며 팝오버 버튼은 한 번 클릭으로 동작한다.

### T19. 원문 선택 옆 팝오버 — P1 · 선행 T17, T18의 표시 계약

- [x] 편집기의 raw 좌표와 선택 화면 위치·pointerup·composition 상태를 전달한다. BOM·CRLF·한글·이모지·반복 문장을 고려한다.
- [x] 비어 있지 않은 연속 선택에 ‘이 부분 수정’을 표시한다. 복사용 선택·키보드 입력·드래그·IME를 방해하지 않고 창/스크롤 경계에서 위치를 보정한다.

### T20. 묶음 없는 원문 대상과 초안 호환 — P1 · 선행 T17

- [x] 실패한 원문 요청의 ‘초안 열기’가 제안 묶음 없이도 원래 원문 탭·인용·지시를 복원하도록 한다. 성공 시 일치하는 제출 초안만 비운다.
- 완료: 기존 초안을 잃지 않고 저장·앱 재시작·탭 왕복·실패 복구·동시 입력 검사를 통과한다.

## 7. 실행·보고 규칙

작업 순서는 **T17 → T18·T20 → T19 → T21 → T22 → T23 → T24**이며 표의 선행 조건을 따른다. 의미가 겹치지 않는 작은 변경으로 나누고 변경 전 관련 정의·참조·테스트·설정을 전체 읽는다. 파일 300줄·함수 본문 50줄·매개변수 5개·순환 복잡도 10을 넘기면 책임별로 분리한다.

정적/단위: `typecheck`, `lint`, `test:unit`, `build`. Rust 변경 시 `native:fmt`, `native:check`, `native:test`, `contracts:check`와 필요한 계약 재생성을 수행한다. 선택·마이그레이션·저장 경계의 기존 Rust 검사는 UI만 바꿨다는 이유로 대체하지 않는다.

native: `native:build:e2e` 완료 확인 → 신규 원문/diff 시나리오 → 관련 기존 회귀 → 정상 종료/재시작 → `native:build` → 일반 release 검증 순서다. 실패·실행 중 셀을 확인하지 않은 채 다음 빌드/앱 실행을 시작하지 않는다.

기존 142개 단위·37개 native 통과는 이전 보완의 기준선이며 이번 계획의 완료 증거가 아니다. 실제 IME·VoiceOver·작성자 평가는 기존 T16에서도 미완료로 유지한다. 구현 후 계획·차이표·검사 결과·검증 앱 식별자를 함께 갱신한다.
