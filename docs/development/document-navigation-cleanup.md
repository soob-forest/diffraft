# 문서 관리·탐색 구현 후 정리

## Problem 1-Pager

- 배경: 작업 목록과 AI 설정·문서 탐색을 각 영역으로 옮기고 실패 복구를 보완했다.
- 문제: 쓰지 않는 작업용 포털, 단일 슬롯의 이름 분기, 읽히지 않는 이동 번호, 이전 사이드바 CSS와 중복 workspace 조회가 남았다.
- 목표: 호출자가 없거나 결과가 사용되지 않는 부분을 제거하면서 탐색·오류 복구 동작을 보존한다.
- 비목표: 새 기능·새 추상화·저장소 변경, 유효성 검사나 실패 보상 제거, 설치·커밋·push.
- 제약: 문서/검토 포털과 반복 목차 이동, 작은 창 표시, 선택 복구·원문 저장을 기존 회귀로 검증한다.

## 대안과 ADR

| 대안 | 장점 / 단점 / 위험 |
| --- | --- |
| 미래 확장을 위해 미사용 슬롯·필드를 유지 | 수정 없음 / 계약과 상태 증가 / 실제 사용 경로 파악이 어려움 |
| 사용 중인 단일 계약으로 축소 (선택) | 불필요한 상태·분기·DOM 제거 / 추후 확장 때 추가 필요 / 전체 호출자 확인 필요 |
| 반복 처리까지 하나의 범용 함수로 통합 | 줄 수 감소 / 오류 복구 순서가 숨겨짐 / 기존 보완 동작의 회귀 위험 |

- 가정: 탐색 포털과 PreviewJump는 private 데스크톱 앱 내부 계약이며 외부 소비자는 없다. 전체 소스 참조를 확인하고 타입 검사로 검증한다.
- 모든 NavigationSlot 호출자는 현재 `outline`이다. `tasks/setTasks`, 빈 호스트와 단일 이름 인자를 제거한다. 현재 문서 목차만 펼칠 때 마운트하고 검토 탐색은 유지한다.
- 목차 요청의 serial은 생성과 타입 외에는 읽지 않는다. 각 클릭이 새 요청 객체를 만들고 effect가 그 객체를 구독하므로 반복 이동은 유지된다. 검토 diff의 실제 사용 중인 serial은 별도 계약이므로 유지한다.
- 모든 PreviewJump 생성자는 원문 스냅샷을 제공한다. source를 필수로 하고 없는 스냅샷을 허용하던 분기만 제거한다. DOM 위치·각주·BOM 검증은 유지한다.
- currentId가 있으면 선택 복구에 사용할 ID가 이미 있다. 이때 사전 workspace 조회를 생략하고, 없을 때만 기존 선택을 조회한다. 선택 후 실패 보상은 유지한다.
- 이전 사이드바용 CSS는 현재 DOM에 일치하지 않는다. 예전 고정 목차 폭/경계/숨김 규칙을 지우고 현재 팝업에서 쓰는 overflow는 해당 규칙에 둔다.

## 영향도

`NavigationProvider → NavigationHost ← EditingArea/ReviewComparison/UnitReview`의 미사용 채널과 이름 인자를 제거한다. `DocumentOutline → Preview/SourceEditor`의 미사용 이동 번호와 source 생략 허용을 정리한다. `workspaceActions.navigate`의 사전 조회만 조건부로 만들며, 저장·목록 상태·오류 메시지·복구 순서는 유지한다.

## 검증

- 전역 검색으로 tasks 포털 호출자가 없고, 목차 이동 serial은 생성·타입 외에는 읽지 않는 것을 확인했다. 실제 소비자가 있는 검토 diff serial과 저장/위치 검증은 유지했다. 정리 후 제품 코드에 구 호스트·슬롯 이름·삭제한 사이드바 선택자가 남지 않는다.
- 기존 선택 후 조회 실패 fixture를 중복 조회가 없는 순서에 맞춰 먼저 실패시킨 뒤 수정했다. 현재 편집기가 없을 때 저장된 선택으로 복구하는 사례도 추가했다.
- `npm run test:unit`: 92개 파일·366개와 Node 스크립트 9개 통과. `npm run typecheck`, `npm run lint`, `git diff --check` 통과.
- 800×600 목차와 1440×900 미리보기 캡처를 확인했다. `.artifacts/document-management/outline-compact.png`, `.artifacts/document-navigation/preview-wide.png`에 현재 배치·스크롤 동작을 보관했다. 화면 검사 hook에 새 결정적 문제는 없다.
- 관련 네이티브 E2E 47개 통과: 문서 탐색 6, 문서 관리·재실행 7, 문서/작업 선택 복원 3, 검토/그룹 13, 재작성 검토 12, 내보내기 6. 같은 제목 반복 선택·원문 커서 보존·각주·설정 오류·부분 결정·초안·작은 창·재실행을 포함한다.
- 기존 Vite 메인 청크 500 kB 초과 경고는 유지된다. 네이티브 드라이버의 stale/scroll 재시도 안내 이후 검사도 통과했다. 실제 한글 IME·VoiceOver 수동 인수는 수행하지 않았다.
- `npm run native:build` 통과. E2E 실행 파일은 현재 소스와 일치하는 일반 debug 빌드로 복원했다. 설치 앱·실제 사용자 문서·기존 SPEC/TODO 수정 사항은 변경하지 않았다.
