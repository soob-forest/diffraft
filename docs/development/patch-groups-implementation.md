# PATCH 개별 변경 검토 구현·검증 기록

기준: [SPEC](../../SPEC.md), [작업 목록](../../TODO.md) · 2026-11-06 Asia/Seoul

## 문제와 구현

같은 요청의 독립 삭제 네 개가 줄바꿈·목록 때문에 한 그룹으로 저장됐다. 요청 전체 결합과 무조건 분리를 비교하고, 검증된 연산을 기본으로 실제 연결된 변경만 결합하는 정책을 채택했다. 가정·대안·호환성 결정은 SPEC의 ADR-001/002에 기록했다.

- `document/patch_groups.rs`: 참조 정의·사용처와 유일하게 확인한 이동을 연결하고 기준본 위치 순으로 그룹을 구성한다. 저장 연산을 다시 분할하거나 정규화하지 않는다.
- `document/patch_structure.rs`: 일반 문구와 구조 변경을 구분하고 연결된 코드·목록·표·제목 범위만 결합한다. 안전한 구조 범위를 특정할 수 없으면 재요청 오류를 반환한다.
- `storage/patch_group_records.rs`: 신규 등록·직접 수정·선택 수정·재제안에 같은 정책을 적용한다. 처리된 기록·SUPERSEDED revision을 덮어쓰지 않고, 구성 변화가 없는 그룹 ID를 유지한다.
- 스키마 13의 `patch_reviews`: 정책 버전·그룹 구성 revision·결합 이유를 저장한다. 구형 DB는 기존 백업·트랜잭션 이관 절차를 따른다.
- `storage/patch_review_prepare.rs`: 명시적 검토 준비 명령에서 전부 미처리·유효한 현재 활성 PATCH만 한 번 재분류한다. 락 아래 원문·head·파일·생성 상태를 검사하고 전환 기록과 그룹을 함께 저장한다. 조회 명령은 재분류하지 않는다.
- 결정 요청은 예상 그룹 revision도 검사한다. 구형 저널의 누락 필드는 기본값으로 읽고 기존 복구 흐름을 유지한다.
- 검토 화면에서 그룹 수·결합 이유·전체 승인 대상을 표시한다. 재분류 후 proposal 기준 선택을 복원하고, 같은 행의 두 번째 변경으로도 이동한다. 그룹 revision이 달라지면 확인창을 무효화한다.
- E2E 실행기의 fixture 준비를 `e2e-workspace.mjs`로 분리해 파일 크기 제한을 지켰다. 가짜 공급자와 소유한 임시 DB만 사용한다.

## 회귀 재현과 실행 증거

첫 저장 회귀에서 독립 삭제 네 개의 그룹 수가 실제 1, 기대 4로 실패했다. 수정 후 같은 사례가 4그룹으로 통과했다. 프런트엔드에서는 동일 행의 두 번째 그룹 이동과 그룹 revision 변경 시 확인 무효화 두 실패를 먼저 확인한 뒤 수정했다.

| 검사 | 현재 확인 결과 |
| --- | --- |
| Rust `patch_group_plan` 최종 회귀 | 9개 통과: 독립 문구·참조·이동·반복 문구·fence/표/중첩 목록/제목·Unicode/100그룹 |
| Rust `review` 최종 회귀 | 33개 통과, 부모가 실행하는 복구 worker 1개는 의도적 ignored. 참조·이동 그룹의 부분 승인/거절도 저장 경계에서 거부한다. |
| 프런트엔드 단위 검사 | 86파일 313개 통과 |
| 실행 도구 단위 검사 | 9개 통과 |
| Rust 전체 검사 | 53개 결과 묶음, 397개 통과·0실패·30개 의도적 ignored. 이후 추가한 4개 사례와 fence 보완은 위 두 최종 회귀 42개로 다시 실행해 통과했다. |
| 타입·린트·Rust fmt/clippy·생성 계약 | 통과, clippy 경고 없음 |
| 웹 빌드 | 통과. 기본 청크 534.31kB의 500kB 초과 경고를 확인했다. 청크 분할은 이번 그룹 정책 변경 범위 밖의 성능 후속 항목으로 기록한다. |
| 네이티브 E2E | 아래 흐름별 결과 참조. Cargo·빌드·앱은 순차 실행했다. |

초기 검사 중 테스트 필터의 정확한 이름이 맞지 않아 0개 실행된 시도가 있었다. 정확한 이름으로 다시 실행해 실패를 확인했다. 첫 Rust 검사에서는 slice 타입 불일치와 불필요한 lifetime을 수정했고, Biome은 앱 디렉터리에서 실행해 중첩 설정 충돌을 해결했다. 전체 Rust 회귀의 기존 승인 테스트 한 곳은 후보 수정 뒤의 새 그룹 revision을 전달하도록 갱신한 뒤 전체를 다시 실행했다. 검증 실패와 도구 실행 오류를 통과 기록으로 포함하지 않는다.

추가 저장 fixture는 기존 블록 계약에 맞게 참조 정의를 문맥 교체 안에 추가하고, 문단 삭제 anchor에서 블록 밖 빈 줄을 제외했다. 첫 fixture 탐색 실패 뒤 수정된 사례로 33개를 다시 실행했다. 실행 명령의 없는 `npm test` 별칭도 `npm run test:unit`으로 바로잡아 313개와 도구 9개의 실행을 확인했다.

최종 소스 검토에서 `~~~invalid`처럼 구분자 뒤 문자가 있는 줄을 닫는 fence로 오인하는 사례를 발견했다. 새 순수 회귀가 먼저 실패함을 확인한 뒤, 닫는 구분자 뒤에는 공백만 허용하도록 검사했다. 영향은 구조 변경의 안전 범위 검증이며 정상 fence·일반 문구·저장 연산은 보존한다.

로그는 `apps/desktop/.artifacts/patch-*.log`에 보관한다. 실제 사용자 문서·AI 응답·인증값은 기록하지 않았다. 아래 최종 결과는 실행한 검사에 한해 갱신한다.

초기 검토 검사는 가려진 창과 gutter 측정 시점 때문에 실패했다. 검증한 테스트 창을 전면 복원하고 렌더를 기다린 뒤 동일한 정렬 조건으로 통과했다. 사용성 검사는 구형 버튼 문구·폼 선택자·모드 복귀를 현재 UI에 맞췄다. 좁은 화면은 상세 패널을 닫고 본문으로 복귀한 뒤 실제 hit target을 기다린다. 클릭 가능성·본문 공간·넘침 조건을 완화하지 않았다.

WebDriver의 스크롤 Actions 재시도 경고는 Web API 스크롤 후 실제 hit target을 검사해 확인했다. 오류를 숨기거나 테스트를 건너뛰지 않았다. 화면은 `.artifacts/patch-groups-800-{1,1.5,2}.png`와 `.artifacts/usability/`에 보관한다. 선택 번호와 결정 버튼의 캡처를 육안으로 확인했다. 작은 화면의 본문 읽기는 별도 스크롤 후 검사하므로 모든 내용을 한 화면에 동시에 표시한다는 의미는 아니다.

사용성 측정의 실제 창은 800×600·1280×800·1440×900이다. 100/150/200%에서 창 테두리와 확대를 제외한 CSS viewport도 `measurements.json`에 함께 기록했다. 합성 문서의 일부 승인·거절과 구형 전환은 네이티브 E2E로 확인했으며, 실계정 응답을 사용한 수동 인수와 구분한다.

2026-11-06 UTC+09:00 실행에서 지정 E2E는 총 48개가 통과했다. 검토 9개·사용성 10개는 최종 `585312d849edada4-e2e`에서 실행했다. 나머지는 `3c36486d016eb4eb-e2e`에서 통과했으며 이후 변경은 선택 제목 포커스 훅 분리와 잘못된 닫는 fence 검증이다. 최종 빌드의 소스 SHA-256은 `585312d849edada440871a376bde36676d5060d08d23fe9d23ba844539e7f446`, 바이너리는 `5535c0513d4c9430690ca21ee32ba4147fb9c6109d347082fd896a60f51a74cc`다. 흐름별 로그·시각·빌드는 `.artifacts/patch-e2e-status.json`, 빌드 증거는 `.artifacts/build-e2e.json`에 기록했다.

마지막으로 `npm run native:build`와 같은 실행기를 통해 일반 개발 빌드를 복원했다(exit 0). `2026-11-06T02:11:09.990Z`의 `585312d849edada4-debug`는 같은 최종 소스이며 바이너리 SHA-256은 `e7acd7eaf47aa1bea3bf64bdd2cc56c904db1e61d8bf630a854642bc8a491183`다. 일반 빌드의 기본 청크 경고는 534.33kB로 위 성능 후속 범위에 포함한다. `.artifacts/build-debug.json`에 출처를 남겼다. PG-01~20의 구현·검증을 완료했고 설치된 사용자 앱과 사용자 DB는 교체·전환하지 않았다.

## 적용 범위와 제한

- 새로운 생성과 revision은 새 정책을 사용한다. 구형 묶음의 자동 전환은 모든 최신 제안이 미처리·유효한 현재 활성 PATCH로 제한한다.
- 일부 처리된 구형 묶음·과거 기록·REWRITE의 검토 계획을 자동 변경하지 않는다.
- AI가 반환한 하나의 큰 교체를 문장별로 재분해하지 않는다. 추가 AI 호출·의미상의 의존성 추론·새 anchor 삽입 계약을 도입하지 않는다.
- 일반 빌드 복원과 실제 사용자 설치 앱 교체는 별개다. 설치 앱·사용자 DB에 대한 배포나 전환은 이 검증에 포함하지 않는다.
- 실제 계정의 AI 응답 품질과 VoiceOver·한글 IME의 기존 미확인 범위를 합성 fixture나 키 이벤트 검사로 대체하지 않는다.
