# 제품 인수 기준

문서 식별자 SPEC-AT  |  버전 0.2  |  작성 기준일 2026년 10월 26일

[기능 명세](specification.md)의 14절과 16절에 있던 인수 조건을 모았다. AT01~AT24의 요구사항과 번호는 원문을 유지한다.

## 14 핵심 인수 시나리오

아래 검증은 출시 전에 통과해야 할 조건이다. 현재 실행 또는 통과한 테스트 결과가 아니다. 각각 고정된 입력 문서와 기대 결과를 사용한다.

| ID | 연관 요구 | 시나리오와 기대 결과 |
| --- | --- | --- |
| AT01 | FR06, FR07 | 변경 A와 B 중 A만 승인. 확정본에는 A만 존재하고 B는 PENDING |
| AT02 | FR08 | A 거절 후 남은 변경 승인. A 원문 유지, 나머지만 한 버전으로 적용 |
| AT03 | FR08, FR17 | 일괄 승인 직전 외부 파일 수정. 승인 전체 실패, 부분 반영 0건 |
| AT04 | FR09 | 코멘트 후 재제안 성공. 기존 revision은 교체되고 새 제안은 미승인 |
| AT05 | FR09 | 제안 문구 직접 수정 후 앱 종료. 재개 시 수정된 제안이 남고 확정본은 그대로 |
| AT06 | FR10 | 전체 재작성안을 취소. 확정본 해시가 요청 전과 동일 |
| AT07 | FR12 | v14에서 v12 복원. v15 내용은 v12와 같고 v14는 계속 접근 가능 |
| AT08 | FR11 | 승인 후 편집 취소. 이전 승인 경계를 넘어 내용을 덮지 않음 |
| AT09 | FR05, FR14 | 앱 재시작 후 같은 작업 열기. 대화, 조건, 코멘트와 제안 상태 복원 |
| AT10 | FR14 | CLI 세션 파일이 없는 상황. 새 세션임을 표시하고 로컬 맥락 재구성 |
| AT11 | FR15 | 생성 중 본문 수정. 이전 기준 응답은 STALE, 승인 차단 |
| AT12 | FR15 | 중단 후 늦은 응답과 재시도 응답 도착. 활성 attempt 결과만 한 번 등록 |
| AT13 | FR13 | 미승인 제안과 코멘트가 있는 상태로 복사. 저장된 확정본만 클립보드에 포함 |
| AT14 | FR16, FR18 | 파일 교체 전후 각 지점에서 강제 종료. 재시작 시 일관된 저장 전후 상태로 복구 |

추가 필수 경계 사례는 한국어 조합 중 입력, 이모지, 반복 문단, CRLF와 BOM, 표 내부 파이프, 코드 블록 안의 제목 기호, 삭제된 코멘트 위치, 한 문서의 두 작업, 중복 승인 클릭, 디스크 부족이다. 각 경우 승인하지 않은 원문 바이트가 유지되는지 확인한다.

| AT21 | 긴 줄 자동 줄바꿈·배율 150%·표/코드 블록에서 논리 행 수와 승인 범위 불변 |
| AT22 | 재작성안 W02는 실제 +4/-4 표시. 개별 구간 승인 불가, 전체 적용/취소만 가능 |
| AT23 | 전체 승인 확인창을 연 후 본문 변경 시 확인창이 무효화되고 적용 0건 |
| AT24 | 복원 비교 방향은 현재→복원할 내용. v15에서 v14 내용 복원 시 새 v16 생성 |

AT01~AT14와 AT15~AT24는 제품 개발의 인수 기준이다. 이 문서 제공 시 실제 앱에서 실행한 테스트 결과가 아니다.

이 조건은 목표이며 체크 결과는 [TO-BE 실행 기록](../development/tobe-implementation.md)의 TB-G1~G4와 별도 사용자 평가 상태를 따른다. 이미지 존재나 자동 탐지 0건만으로 디자인 완료 처리하지 않는다.

비교는 같은 합성 문서·작업·버전·선택·콘텐츠 크기·배율·접힘·스크롤을 맞추고 차이와 근거를 공개한다. 재개 안내는 실제 발생 분기별로 확인한다. 기능 회귀·시각 대조·Impeccable 검토·일반 앱/DMG 및 설치본 검증은 각각 기록한다. 빌드/E2E는 직렬 실행하고 마지막 debug 실행 파일은 일반 빌드로 복원한다. 5명 사용자 과업 평가·효과 측정은 별도 미검증이며 자동 검사로 대체하지 않는다.
