# 현재 UX 화면 계약

2026-11-02 · [구현·검증 현재 상태](../development/ux-status.md) · [팝오버 작업 계획](../development/selection-popover-plan.md) · [제안 화면 1~9](ux-proposal/index.html) · [원문 팝오버 추가안](ux-proposal/source-selection-popover.html) · [보완 대조표](../development/selection-popover-audit.md).
이 문서는 새 기능의 동작 계약이다. 정적 시안의 픽셀 일치와 실제 사용성 검증 완료를 뜻하지 않는다. 기존 글꼴·색·패널 크기는 디자인 명세 13절을 따른다.

## 선택과 수정 — 화면 1~4

- 선택 옆 팝오버에 강조된 `이 부분 수정`과 보조 `코멘트`를 제공하며 상단에 중복하지 않는다. 유효한 한 제안의 정확한 선택에만 코멘트를 연결한다. 문장·문단 확장은 `더보기`에 둔다. 드래그는 인용만 선택하며 포커스를 옮기거나 AI를 실행하지 않는다. 우클릭/Shift+F10은 선택 행동, Cmd+Shift+Enter는 작성 패널만 연다.
- 작성 패널 순서는 대상·인용 → 승인 단위 → 지시 → 지시 예시 → 포함할 저장 코멘트 → 실제 초안 상태 → 모델 → 요청 내용 확인이다. 코멘트 등록을 필수 단계로 두지 않는다.
- 확인 단계는 수정 인용과 참고 문맥을 구분한다. 확정 모델·지시·조건·대화·최근 결정·포함 코멘트가 준비한 스냅샷과 같아야 한다. 최종 `확인 후 요청`만 AI를 실행한다.
- 후보 선택은 새 revision, 확정 문맥 선택은 현재 head의 새 묶음, 재작성 후보 선택은 새 전체 후보로 저장한다. 일부를 다듬는 행동과 승인 단위는 다르다.
- 새 대상으로 이동할 때 작성 중인 이전 대상 초안을 보관한다. 이전 대상의 지시를 새 대상으로 자동 이식하지 않는다. 실패·중단에는 인용·지시·이전 후보를 유지한다.
- 원문과 diff는 마지막으로 연 대상을 각각 유지한다. 같은 confirmed 범위의 실제 초안은 공유하지만 다른 탭에서 후보를 열었다고 원문 작성 대상을 바꾸지 않는다. 작성 중 다른 변경을 읽어도 저장 후에는 실제 결과의 그룹·revision·본문 위치로 복귀한다.
- 같은 후보 revision·범위를 명시적으로 재선택하면 최신 확정본 기준으로 대상을 갱신한다. 지시·직접 수정 입력은 보존하고 이전 확인 정보는 해제한다. 실패 요청의 초안 열기는 해당 요청과 일치하는 유일한 대상만 열며, 부재·모호함에는 현재 초안을 유지하고 재선택을 안내한다.
- 문장/문단 행동은 실제 범위를 먼저 선택한다. 표·목록·코드·모호한 경계에는 드래그를 안내한다. 직접 부분 수정은 단일 유효 미승인 후보에서 AI 없이 새 revision으로 저장한다.
- Esc는 확인에서 지시로, 작성에서 diff로 복귀한다. 실행 중에는 확인·대상 변경을 잠그고 앱 상단의 중단을 사용한다. 새 결과는 정확한 batch/revision으로 연결하고 이전 revision 비교를 제공한다.

## 원문 선택과 편집 영향 — 화면 5~6

원문은 드래그 완료 후 선택 옆 `이 부분 수정` → 오른쪽 `선택한 부분 수정` → `요청 내용 확인` → `확인 후 요청`으로 이어진다. 선택만으로 일반 요청의 범위·초안·포커스를 바꾸지 않는다. 원문·조건 저장 후 head·범위·정확한 인용을 다시 검증하고 기존 미승인 제안을 보존하는 confirmed 선택 요청으로 새 묶음을 만든다. 일반 생성의 이전 제안 보관 동작으로 대체하지 않는다.

대상은 묶음 ID 없이 문서·작업·head·범위·인용으로 식별한다. 구형 confirmed 키는 호환 조회하고 충돌하는 지시는 명시적으로 선택하며 임의 삭제하지 않는다. `원문 · vN` 또는 `제안 내용 · rN`과 실제 인용·문자 수를 표시한다. 미승인 제안과 겹치면 해당 작업의 현재 검토를 명시적으로 열며 변경 전 선택을 후보 좌표로 자동 변환하지 않는다.

작업이 없으면 같은 선택을 유지한 채 목표·첫 지시를 작성한다. 명시적으로 작업을 하나 만든 뒤 초안을 저장하며 AI는 자동 실행하지 않는다. 소유 작업이 없는 입력은 임시 상태임을 안내한다. 실패·중단에는 지시를 유지하고, 원문 변경에는 재선택을 요구한다. 새 결과는 현재 미승인 검토로 열고 대화의 과거 결과와 구분한다. 돌아가기는 원문의 선택·스크롤·포커스를 복원한다.

원문 편집 영향은 현재 문서의 모든 작업에서 합산한 미승인 제안·승인 그룹·전체 후보 수다. 영향을 받는 작업의 검토로 이동할 수 있다. 입력을 막는 모달은 사용하지 않는다. 저장 후 기준이 바뀐 제안은 STALE이며 최신 원문에서 요청을 준비한다.

원문 요청의 실행 상태는 작성 패널의 표시 수명과 분리한다. 보기 왕복에도 확인·취소 행동의 실행 잠금을 유지하며 성공은 정확한 새 검토, 실패는 같은 인용·지시·오류로 이어진다. 작업을 바꾸면 임시 작성창과 대상 변경 선택지는 닫고 저장 초안은 작업별로 유지한다. 다른 작업으로 이동한 뒤 이전 요청이 끝나도 현재 화면을 되돌리지 않는다. 첫 작업 생성은 같은 인용·지시로 명시 인계한다.

## 상태·이력·대화 — 화면 7~8

상태는 저장된 결정·유효성·묶음 상태에서 판정한다. 검토 중·완료·변경 없음·과거 기록·취소·기준 변경·범위 충돌·전체 후보·전체 적용을 구분한다. AI의 과거 요약은 현재 배지를 결정하지 않는다.

오른쪽 처리 목록은 제목·상태·revision·이유와 `당시 변경 비교`를 제공한다. 중앙에서는 당시 base와 후보 또는 이전 revision과 새 revision을 읽기 전용으로 비교한다. 현재 검토 viewer를 유지해 복귀 시 읽던 위치와 초안을 보존한다. 승인·거절은 현재 유효 후보에서만 가능하다.

대화의 `이 요청의 변경 보기`는 원래 job이 만든 정확한 결과를 연다. 복원할 수 없는 참조와 설명 응답에는 존재하지 않는 결과 링크를 만들지 않는다. 이미 연 이전 대화 페이지도 현재 결과 상태를 갱신한다.

## 요청·초안·모델 — 화면 9

- 요청 종류는 부분 수정/설명/전체 재작성이다. 모드별 지시를 보관한다. 첫 작업에서 첫 지시를 함께 작성해도 작업 저장 후 확인 단계까지만 진행한다. 일반 요청 폼의 범위 변경은 별도 명시 행동으로 유지한다.
- 원문 저장과 초안 저장은 별도다. 요청·코멘트·선택·직접 수정·재제안·재작성 초안은 대상별로 SQLite에 저장하고 실제 저장 중/완료/실패와 수동 재시도를 표시한다. 저장 순번과 조건부 갱신으로 늦은 응답이 새 입력을 덮지 않는다.
- 저장된 준비 모델·범위도 복원한다. 재실행만으로 AI를 보내지 않으며 오래된 head/revision/인용은 다시 확인한다. 자동 기간 삭제는 없고 문서/작업 삭제에 종속 초안을 정리한다.
- 초안의 직렬화 UTF-8 저장 한도는 3 MiB다. 원문 범위 고정은 한도를 검사한 뒤 기존 초안을 변경한다. 크기 초과로 저장이 막히면 해당 초안 종류와 명시적 비우기 행동을 제공한다. 더 새로운 입력과 다른 초안은 보존하며, 일반 저장 오류에는 재시도를 제공한다. 복구 안내·버튼은 작은 창과 확대 화면에서 줄바꿈·스크롤로 접근한다.
- 요청 폼에 현재 공급자·모델과 변경 경로를 둔다. Codex 기본값은 미확정 상태를 구별하고 확인 전에 모델 ID·추론 설정을 고정한다. 설정 저장·상태 조회·로그인·유료 테스트를 구분한다.

## 키보드·작은 화면

변경 상세/작업·대화 탭은 탭/패널 ID를 연결하고 방향키·Home/End와 가시적 포커스를 제공한다. 선택 행동은 일반 버튼 묶음으로 Tab 이동한다. 숨은 패널은 탐색에서 제외한다. 긴 인용·지시·오류는 줄바꿈과 스크롤로 읽으며 본문 글꼴을 줄여 숨기지 않는다.

팝오버는 드래그 중에는 표시하지 않고 선택 완료 뒤에도 편집기 포커스를 유지한다. 편집·IME 조합·선택 해제·Esc·보기 전환·바깥 스크롤에 닫는다. 팝오버 내부 스크롤은 유지한다. Esc는 현재 선택을 바꾸지 않고 편집기에 포커스만 복귀한다. 임의 드래그를 문장 개수로 추정하지 않으며 문자 수는 grapheme 기준이다.

원문의 유효한 선택에서 우클릭하면 수정 팝오버만 표시하고 기본 컨텍스트 메뉴를 중복 표시하지 않는다. 빈 선택의 기본 메뉴와 편집기의 복사 단축키는 유지한다. 보기 전환은 예약된 표시 작업도 취소하며 돌아왔다는 이유만으로 이전 위치의 팝오버를 다시 띄우지 않는다.

실제 3개 창 크기·3개 확대율·한국어 IME·VoiceOver 검사 결과는 실행 기록에서 별도로 확인한다. DOM과 가짜 문자 입력은 실제 입력기·스크린리더 검증의 대체물이 아니다.
