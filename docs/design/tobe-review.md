# TO-BE 이행 · Impeccable 검토

2026-10-29 · Operate · 대상: 고정 `.refined`6개와 새 WKWebView 렌더. [직접 비교](tobe-implementation.html) · [실행/ADR](../development/tobe-implementation.md). 최종 통합87개·단위75개·비교12개와 일반 설치본 검증까지 완료했으며 실행 기록에서 근거를 별도 확인할 수 있다. VoiceOver 제외. 과거29/40과 사용자 연구 결과를 새 점수로 재사용하지 않는다.

## 방법

Impeccable layout/typeset/quieter/polish/clarify/harden 플레이북으로 소스·렌더·치수·상호작용을 확인했다. layout A(`/root/tobe_layout_review`) 완료 후 mechanical B(`/root/tobe_mechanical_scan`)가 독립 탐지를 실행했다. typeset A(`/root/tobe_typography_review`)도 이전 점수/탐지 결과를 보지 않고6개·긴 표·확대 상태를 검토했다. 이후 B의 type/full 탐지는각 exit0/[]였다. WKWebView의 실측·가짜 CLI·별도 임시 DB를 사용했고 실제 계정에 요청하지 않았다. 사람 참여형 평가와 구분한다.

## 판단

- **layout:** 요청·검토 결정·코멘트 작성의 읽기 순서가 목표와 일치한다.196/360/290px 영역,50/32px 프레임, 하단 기록을 유지한다. 보조 기능은 문서 메뉴/문서 탐색/작업 옵션에 남긴다.
- **typeset:** 제목22px, 영역16px/600, 조작14px/500, 보조13px. 입력16px/26.4px, diff16px/1.8, 인용16px/1.7이다. 외부 폰트 없이 기존 시스템 글꼴·모노스페이스 역할을 유지한다. 플랫폼의 행 박스 반올림은 CSS에서 보정한다.
- **quieter:** 중립 범위·인용·초안과 무테 탐색으로 반복 경계/청색 경쟁을 줄였다. 요청 확인·선택 승인·코멘트 저장을 각 맥락의 주 행동으로 둔다. 후보/재제안 폼을 기본 상세에 동시에 적재하지 않는다.
- **clarify:** 요청 범위와 기준 버전, 저장과 AI 실행의 차이, 초안 수명, 실패 후 수정/재시도, 복원의 영향을 행동 옆에 제공한다. 성공 상태에서는 닫기를 강조하고 진단은 접는다.
- **harden:** 조건 flush 실패·저장 실패·빈 선택·revision 교체·늦은 응답·생성 중단·재시작·긴 제목/표·100개 변경을 실제 IPC로 검사한다. 원문/후보/앵커와 세션 초안 경계를 유지한다.
- **polish:** 원문 시작선260/60px, diff 제목/번호/기호 컬럼, 요청·코멘트 입력, 대화창 비례를 직접 대조한다. 확대에서도 글자를 축소하지 않으며 도구/기록/주 행동은 스크롤로 접근한다. 포커스·대비·오류 상태를 함께 본다.

대비 계산: 본문15.46:1, 보조/패널5.96:1, 삭제8.56:1, 추가8.50:1, 주요 버튼6.38:1. 자동 탐지0건은 이 대비나 시안 일치의 근거가 아니다. 실제 렌더 대조 및 상호작용 증거를 함께 사용한다.

사용자5명 과업 평가·효과 측정, 장시간 읽기 피로와 실제 AI 응답 품질은 별도 미검증이다. UI 작업이 해당 결과를 증명하지 않는다.

최종 재확인: 수정 후 독립 typeset 평가에서 추가 P1/P2 없음. 마지막 전체 탐지도 exit0/[]였다. 연결 성공 캡처는 전역 생성 상태까지 유휴가 된 뒤 촬영했다. 이는 사용자 연구 결과나 새 휴리스틱 점수가 아니다.
