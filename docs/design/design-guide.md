# 화면 및 디자인 시스템 명세

버전 0.2 · 2026-10-26 · 원본 자산: [assets](assets)

## 1 디자인 방향

문서를 작성하는 동안은 편집기, AI 변경을 검토하는 동안은 diff 도구처럼 동작한다. 확정본·미승인 제안·작업 대화의 경계를 화면에서 드러낸다. 승인 행동은 그 행동이 적용할 변경 가까이에 두고 전체 승인은 상단의 현재 제안 묶음 도구 영역에 둔다.

| 참고 제품 | 확인한 동작 | 이번 설계에 채택 | 채택하지 않는 범위 |
| --- | --- | --- | --- |
| VS Code | 인라인/나란히 diff, 변경 간 이동, 변경 구간 조작 | 소스 diff, 좌우 비교, 문맥 접기, 구간별 행동 | Git staging·commit 작업 흐름 |
| GitHub 리뷰 | diff 보기 전환, 줄/범위 코멘트, 제안 검토 | before/after 구간 코멘트, 검토 진척 | PR·다중 검토자·병합 승인 |
| Google Docs | 원문을 유지하는 제안, 개별/전체 승인, 제안 코멘트 | 미승인 제안 분리, 남은 변경 전체 승인 | 공동 편집·알림·계정 권한 모델 |
| Obsidian | Markdown 원문 편집과 읽기 화면 | 편집/미리보기 구분, 문서 중심 탐색 | 플러그인 생태계·지식 그래프 |

제품 사실은 [공식 참고 자료](../references.md)에 근거한다. 채택 여부와 화면 수치는 이 앱에 대한 설계 판단이다. 공식 화면의 픽셀·아이콘·브랜딩을 복제하지 않았으며 모든 전달 화면은 이 제품을 위해 새로 작성했다.

## 2 기본 화면 구조

시안 캔버스는 1600×1000이다. PNG는 3200×2000이며 SVG는 같은 논리 좌표를 사용한다.

| 영역 | 크기 기준 | 역할 |
| --- | --- | --- |
| 앱 상단 | 높이 50 | 제품명, 작업 공간 |
| 왼쪽 탐색 | 폭 220 | 문서, 문서별 작업, 목차 또는 변경 목록, 연결 설정 |
| 문서 헤더 | 높이 74 | 문서명, 확정본 버전, 실제 저장 상태, 버전 기록, 내보내기 |
| 모드 탭 | 높이 52 | 편집 / 변경 검토 / 미리보기 |
| 검토 도구 | 높이 약 52 | 비교 기준, 보기 모드, 문맥 접기, 이동, 전체 승인 |
| 중앙 본문 | 유동 폭 | 소스 편집기 또는 실제 diff |
| 오른쪽 작업 패널 | 기본 폭 360, 접기 가능 | 작업 대화, 고정 조건, 코멘트, 맥락 |
| 하단 상태 | 높이 32 | 로컬 작업, 인코딩, 승인 상태 원칙 |

실제 창 크기와 OS 배율은 구현에서 검증한다. 최소 창 목표는 1280×800이며, 폭이 부족하면 왼쪽 탐색과 오른쪽 대화를 접을 수 있다. 나란히 보기의 각 열 폭이 540 미만이면 인라인 전환을 권장한다. 사용자가 고른 보기 설정을 임의로 바꾸기보다 전환 행동과 이유를 보여준다. 창 축소로 인라인이 필요한 경우 선택 변경과 코멘트 앵커를 보존한다.

## 3 Diff 컴포넌트

### 3.1 표현 규칙

- 인라인: `이전 행 번호 / 이후 행 번호 / − 또는 + / 원문` 순서다. 삭제 줄은 이전 번호만, 추가 줄은 이후 번호만 가진다.
- 나란히: 왼쪽 확정본, 오른쪽 제안 반영 예상본. 각 열의 행 번호는 그 문서를 기준으로 한다.
- 줄 배경은 변경의 종류를, 진한 부분 배경은 바뀐 표현을 나타낸다. 색만으로 상태를 전달하지 않는다.
- 변하지 않은 문맥은 중립색으로 표시한다. 줄 번호 차이가 큰 구간은 문맥 더 보기로 펼칠 수 있다.
- 추가/삭제 통계는 실제 줄 차이이고 승인 개수는 독립 승인 그룹 수다.
- 긴 줄은 기본 자동 줄바꿈한다. 코드·표를 읽기 위해 가로 스크롤을 선택할 수 있으나 원문을 잘라 저장하지 않는다.
- diff 화면에서 직접 확정본을 편집하지 않는다. 후보를 수정하려면 `제안 직접 수정`, 원문을 수정하려면 `편집` 탭을 선택한다.

### 3.2 행동과 상태

| 컴포넌트 | 기본 행동 | 실행 이후 |
| --- | --- | --- |
| 변경 헤더의 승인 | 해당 그룹의 현재 revision만 적용 | 승인됨, 새 확정본 버전 표시 |
| 변경 헤더의 거절 | 해당 그룹을 반영하지 않음 | 처리됨 목록으로 이동, 원문 유지 |
| 코멘트 | 현재 변경 또는 선택한 before/after 구간에 연결 | 오른쪽 코멘트 패널 표시 |
| 제안 직접 수정 | 별도 후보 편집 상태 열기 | 저장한 새 revision은 다시 미승인 |
| 남은 변경 N개 승인 | 현재 문서·현재 묶음의 대상 확인창 | 최종 승인 시 유효성 전체 검사 후 저장 |
| 변경 부분만 | 변하지 않은 구간 접기 | 내용·결정 상태 불변 |
| 이전/다음 변경 | 다음 독립 승인 그룹으로 이동 | 선택·포커스·대상 코멘트 함께 갱신 |
| 전체 재작성 적용 | 후보 전체를 적용 | 적용 전 버전 보관, 새 확정본 생성 |

### 3.3 특수 상태

승인·거절·교체·취소는 처리된 기록이고, 기준 불일치·충돌은 현재 제안의 유효성 문제다. 둘을 같은 상태 색 하나로 합치지 않는다. 승인이 불가능하면 이유를 버튼 가까이에 표시하고 최신 문서에서 재제안하는 행동을 제공한다.

재작성 모드는 실제 diff를 보여주되 구간별 승인 버튼을 없앤다. 전체 승인과 전체 재작성 적용의 레이블을 구분한다. 버전 복원은 현재→선택 버전의 방향으로 diff를 보여주며 기존 버전을 덮는 대신 새 버전을 만든다고 명시한다.

## 4 글꼴·색·간격

정확한 값은 [design-tokens.json](assets/design-tokens.json)에 있다. PNG는 NanumGothic으로 렌더링했다. SVG는 글자와 도형을 편집할 수 있으며 글꼴 미설치 환경에서는 대체 글꼴에 따라 줄 폭이 달라질 수 있다. 전달된 PNG를 외형 기준으로 삼는다.

| 역할 | 값 | 사용처 |
| --- | --- | --- |
| 기본 본문 | #182537 | 제목과 본문 |
| 보조 문구 | #607083 | 설명, 상태, 행 번호 |
| 주요 행동 | #2957C8 | 승인·전송·선택 탭 |
| 추가 줄/표현 | #E8F5EC / #B6E1C2 | + 추가 |
| 삭제 줄/표현 | #FDEDEC / #F6C1BB | − 삭제 |
| 추가/삭제 글자 | #14633B / #A0332D | 색과 기호를 병행 |
| 경고 | #FFF3D9 / #815A13 | 충돌, 재연결 |
| 기본 간격 | 4, 8, 12, 16, 24, 32 | 컴포넌트 내부·영역 간격 |
| 둥근 모서리 | 6, 8, 12 | 버튼, 패널, 확인창 |

본문 16~18px, 제목 22~30px, 보조 문구 12~14px를 기준으로 한다. 실제 제품은 글꼴 크기 조절과 OS 배율을 따른다. 색 대비는 기본 본문과 주요 행동에서 WCAG AA 수준을 목표로 검증하며 이 시안 자체가 인증을 의미하지 않는다.

## 5 키보드와 접근성

- 모든 승인·거절·코멘트 행동을 Tab으로 접근할 수 있게 한다. 아이콘만 있는 이동 버튼에 접근성 이름을 제공한다.
- F7/Shift+F7을 다음/이전 변경의 후보 단축키로 제안한다. 실제 충돌 여부를 OS에서 검증한다.
- Ctrl/Cmd+Z는 직접 편집 구간만 되돌린다. 승인과 버전 복원을 같은 단축키로 숨기지 않는다.
- 전체 승인 단축키는 MVP에서 두지 않는다. 승인 단축키 오입력으로 큰 범위가 반영되는 일을 줄인다.
- 확인창은 제목·대상·버튼을 스크린리더가 읽고, Esc로 닫으면 원래 버튼으로 포커스를 돌린다. Enter는 현재 포커스가 놓인 버튼만 실행한다.
- diff의 읽기 순서는 변경 제목 → 삭제 → 추가 → 문맥 → 행동이다. `추가`, `삭제`, `미승인`, `충돌`을 음성으로도 구분한다.
- 재생성 후 새 제안 도착, 승인 완료와 오류는 과도한 포커스 이동 없이 상태 영역으로 알린다.

## 6 화면 자산 목록과 사용법

| 파일 이름 | 화면 |
| --- | --- |
| S00_connection | 공식 CLI 연결 |
| S01_editor | 원문 편집·범위 선택 |
| S02_inline_diff | 인라인 diff |
| S03_split_diff | 나란히 diff |
| S04_comment_revision | 코멘트·재제안 |
| S05_bulk_approve | 전체 승인 확인 |
| S06_full_rewrite | 전체 재작성 비교 |
| S07_restore | 버전 복원 diff |
| S08_resume | 작업 재개·맥락 |
| S09_conflict | 외부 파일 비교 |
| S10_export | 확정본 내보내기 |

각 이름에 `.svg`와 `.png`가 있으며 `assets/screens/`에 별도로 보관한다. [화면 갤러리](gallery.html)는 PNG를 내장하므로 HTML 하나로도 열 수 있다. 갤러리의 시나리오 선택과 확대만 작동하며 화면 안 제품 버튼은 정적 디자인이다. 실제 앱 코드를 전달한 것이 아니다.

예외 상태는 [기능 명세](../product/specification.md)와 [시나리오](scenarios.md)의 배너·행동 표로 정의한다. 정적 화면 11개는 모든 반응형·오류 상태의 픽셀 시안을 포함하지 않는다.
